# MedTrust 租户模型规范

## 可信空间角色定义

### 1. 数据提供方 (Data Provider)

**角色描述**: 拥有医疗数据并愿意在可信空间内共享的机构或个人

**典型用户**:
- 医院信息科
- 医学检验机构
- 医药企业
- 患者个人

**核心功能**:
- 数据资产上传与管理
- 数据质量评估
- 使用策略配置（谁能用、怎么用、多少钱）
- 收益查看与提现
- 数据使用监控

**数据类型**:
| 数据类别 | 示例 |
|---------|------|
| 电子病历 | 诊断记录、医嘱、护理记录 |
| 影像数据 | CT、MRI、X光、超声 |
| 检验数据 | 血常规、生化指标、基因数据 |
| 处方数据 | 用药记录、药品信息 |
| 随访数据 | 随访记录、预后信息 |

**收益模式**:
- 按次计费：每次数据被查询/使用
- 包月订阅：固定周期内的数据访问权
- 结果分成：基于数据产生的研究成果分成

---

### 2. 数据使用方 (Data Consumer)

**角色描述**: 需要使用医疗数据进行研究、分析或应用开发的机构

**典型用户**:
- 医学科研人员
- AI 算法公司
- 药企研发部门
- 保险公司
- 公共卫生机构

**核心功能**:
- 数据发现与搜索
- 数据使用申请
- 沙箱计算环境
- 隐私计算任务执行
- 结果获取与导出

**使用场景**:
| 场景 | 描述 |
|------|------|
| 临床科研 | 专病数据库构建、回顾性研究 |
| AI 训练 | 医学影像识别模型训练 |
| 药物研发 | 真实世界研究、疗效评估 |
| 保险精算 | 疾病风险评估、定价模型 |
| 公卫监测 | 流行病监测、健康趋势分析 |

**计费模式**:
- 计算资源费：CPU/GPU 使用时长
- 数据使用费：按数据提供方定价
- 平台服务费：平台技术支撑费用

---

### 3. 平台运营方 (Platform Admin)

**角色描述**: 可信空间平台的运营管理者

**核心功能**:
- 租户准入审核
- 数据合规审查
- 交易纠纷仲裁
- 平台规则制定
- 运营数据分析

**监管能力**:
- 全链路审计日志
- 敏感操作监控
- 异常行为告警
- 合规报告生成

---

### 4. 技术提供方 (Tech Provider)

**角色描述**: 提供隐私计算算法、AI 模型或技术服务的第三方

**核心功能**:
- 算法入驻与管理
- 计算服务提供
- 技术支持服务
- 算法效果评估

**服务类型**:
| 服务 | 描述 |
|------|------|
| 联邦学习框架 | Flower 部署、模型训练服务 |
| 隐私计算算法 | MPC、同态加密算法 |
| AI 模型服务 | 医学影像分析、NLP 处理 |
| 数据清洗服务 | 数据脱敏、标准化处理 |

## 多租户数据隔离

### 数据隔离策略

```
┌─────────────────────────────────────────────────────────┐
│                    Platform Layer                        │
│              (Shared: Users, Billing, Logs)              │
├─────────────────────────────────────────────────────────┤
│  Tenant A  │  Tenant B  │  Tenant C  │  Tenant D       │
│  (Provider)│ (Consumer) │  (Admin)   │  (Tech)         │
├─────────────────────────────────────────────────────────┤
│  Data Assets│  Projects  │  Audits    │  Algorithms     │
│  Policies   │  Tasks     │  Reports   │  Services       │
│  Earnings   │  Results   │  Settings  │  Stats          │
└─────────────────────────────────────────────────────────┘
```

### Schema 设计

#### 租户表 (tenants)
```typescript
{
  id: string;           // 租户ID
  name: string;         // 租户名称
  type: 'provider' | 'consumer' | 'admin' | 'tech';
  status: 'active' | 'pending' | 'suspended';
  createdAt: Date;
  settings: {
    dataRetention: number;    // 数据保留天数
    computeQuota: number;     // 计算资源配额
    storageQuota: number;     // 存储配额
  };
}
```

#### 租户成员表 (tenant_members)
```typescript
{
  id: string;
  tenantId: string;     // 关联租户
  userId: string;       // 关联用户
  role: 'owner' | 'admin' | 'member';
  permissions: string[];
  joinedAt: Date;
}
```

## 可信空间核心流程

### 流程1: 数据提供方入驻

```
1. 注册账号 → 2. 资质认证 → 3. 租户创建 → 4. 数据上传 → 5. 策略配置 → 6. 上架发布
```

### 流程2: 数据使用方申请

```
1. 浏览数据 → 2. 提交申请 → 3. 策略确认 → 4. 支付费用 → 5. 沙箱计算 → 6. 获取结果
```

### 流程3: 隐私计算任务

```
1. 选择算法 → 2. 配置数据 → 3. 启动计算 → 4. 进度监控 → 5. 结果验证 → 6. 结果交付
```

## 安全与合规

### 数据分级

| 级别 | 描述 | 处理要求 |
|------|------|---------|
| L1 公开 | 已脱敏的统计数据 | 标准沙箱 |
| L2 内部 | 去标识化数据 | 增强沙箱 |
| L3 敏感 | 标识化数据 | MPC/联邦学习 |
| L4 机密 | 原始个人数据 | TEE 环境 |

### 合规要求

- **数据安全法**: 数据分类分级保护
- **个人信息保护法**:  consent 管理、最小必要原则
- **人类遗传资源管理条例**: 遗传数据出境审批
- **等保2.0**: 三级等保要求
