# 给医院领导的一页说明：数据怎么参与研究、安全怎么保障

> 配套技术文档见 `docs/rws-trusted-space-solution.md`；本页为非技术口径，可打印分发。

**一句话**：医院的数据不出明文——出去的只是一张「加密的最小摘抄」，钥匙不随数据走、不在任何一方手里单独保管；算完只回来汇总数字，单条记录当场销毁，全程留痕可审计。

## 一、什么是「加密的最小摘抄」

| | 内容 |
|---|---|
| **摘抄里有什么** | 编号（假名，非姓名）、年龄段、性别、接种/就诊/检测日期、疾病或疫苗编码 |
| **摘抄里没有什么** | 姓名、身份证号、电话、地址、住院号、检查报告原文、检验数值、影像、病历文书 |
| **怎么出去** | 在**医院内网**加密（国密 SM4）成乱码后才出网；白名单之外的字段根本生成不进摘抄 |

研究要算的只是「编号 A 某日接种、编号 A 某日就诊」这类**计数关系**——不需要身份，自然不带走身份。

打个比方：不是把病历复印寄出去，而是**抄一张没有名字的便签 → 锁进保险箱 → 送去一间验证过封条的密封统计室**。开箱钥匙不随车走，由第三方保管人核实统计室封条无误后才当面开锁；统计室只报总数，便签当场销毁，每环节有回执。

## 二、四道安全保障

1. **只摘抄、不拷库**：字段最小化 + 假名化——泄露面从「全院病历」缩到「无身份的计数素材」；
2. **乱码出门、钥匙分持**：解密钥匙由医院托付给独立保管方；平台、云厂商、技术供应商**都不持有钥匙**；
3. **钥匙只进「验明正身」的房间**：基于英特尔芯片的加密计算环境（TDX），开工前须出示硬件证明（代码未篡改、版本合规），证明不过关钥匙不放行——**由机器强制，不靠任何人自觉**；
4. **只回汇总、单条即毁**：只输出过审汇总数（样本太小的分组自动隐去）；计算一结束，环境内单条语料立即销毁，**销毁动作本身有回执、上链可查**——能证明的销毁才是销毁。留下的只有汇总结果与审计凭证（这是可审计、可归因的来源）。

## 三、领导最可能问的七个问题

**Q1 数据到底出没出医院？**
出的不是病历，是一张「无身份的加密便签」；没有钥匙它就是一串乱码。

**Q2 钥匙在谁手里？**
独立保管方，且必须凭硬件证明才交给计算环境。医院、云厂商、平台、技术供应商——**任何一方都单独开不了锁**。

**Q3 云厂商或技术方能看见吗？**
不能。英特尔 TDX 是芯片级加密内存，云的管理程序也读不到；技术方只能看到最终汇总数。

**Q4 被黑客截获怎么办？**
截到的是乱码，且密文与钥匙不同路；即使把整台服务器搬走也解不开。

**Q5 合规吗？**
符合《数据安全法》《个人信息保护法》「最小必要」与去标识化要求；全链使用国密算法（SM2/SM3/SM4）；全程留痕可审计。**如实说明**：真实数据接入前仍需完成院内伦理与数据合规审批，我们不会跳过这一步。

**Q6 出了问题怎么追责？**
数字合约把「谁、用哪些字段、算什么、阈值多少」写死并多方签署；每一步有回执上链，可归因到院、到作业、到时刻。

**Q7 对院内信息系统有影响吗？**
连接器部署在院内，只主动出站、不开入站端口；经视图层只读接入，不改业务库。

**Q8 销毁了什么？留下了什么？**
销毁的是计算环境内解密后的单条语料，销毁动作有回执、上链留痕；留下的是汇总结果和审计凭证（回执链、模块摘要、销毁记录）。医院的原始数据从未出院，归医院自己的保留策略管理，与节点销毁无关。

## 四、对外表述口径（红线）

- ✅ 可以说：「明文不出院、最小必要、密文计算、只出汇总、全程留痕可审计」
- ❌ 不要说：「数据完全不出医院」（密文物理出域，被追问即穿帮）、「绝对安全」（安全是分层收敛，不是绝对）、「平台担保」（平台无密钥，不是信任锚）
