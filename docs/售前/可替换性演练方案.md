# 可替换性演练方案（Replaceability Drill）

> **要解决的问题**：数据集团最怕的不是"你不够强"，是"被你锁死"。
> 论证材料里写"我们可替换"是承诺；**演练是证据**。
>
> **一句话主张**：七条替换轴，任换一层，**调用点零改动、输出逐字节不变、闸门不松**。
>
> **本方案的核心不是"换"，是"怎么证明换了还没坏"**——判据必须机器可判、且**预注册后不可改**。

---

## 0. 为什么这次不用承诺

本仓已经发生过一次真实的层替换：存证链从 FISCO BCOS 换成 ChainMaker（[DECISIONS.md](../../DECISIONS.md) D-RWS-3）。
这次替换留下了三样东西——决策登记、调用点抽象（`ChainAnchorSink` 接口）、以及"换完之后所有守护仍绿"的基线。

**演练就是把这个已经发生过一次的事实，变成可复现、可当着客户面重演的流程。**

---

## 1. 七条替换轴

| # | 轴 | 现有实现 | 替换目标 | **不许改的东西** | 接口/锚点 |
|---|---|---|---|---|---|
| 1 | 数据源 | JSON 记录文件 → 内存筛 → 投影 | OMOP CDM 直连（SQL 投影下推） | 投影构造器、沙箱、OutputGate、存证链路 | `apps/connector/src/domain/data-source/cdm-projection.ts`（注释明写"两条路径在投影载荷处汇合"） |
| 2 | 执行环境 | `SoftwareTee` | 硬件飞地 | `executionIsolation` 与 `attestationLevel` 的**正交**关系 | D-CN-2 |
| 3 | 证明提供者 | `SoftwareAttestationProvider` | 厂商 quote（`mapVendorQuote` + `createHardwareAttestationVerifier`） | `AttestationProvider` 接口、`verifyAttestationForC2` 调用点 | `packages/mdop/src/attestation/provider.ts` |
| 4 | 密钥管理 | `LocalDevKms` / `DevKms` | `HttpKmsClient` → 生产 KMS（Vault） | `KmsClient` 接口、`evaluateKeyRelease` 判定 | `packages/mdop/src/attestation/kms.ts`、`apps/connector/src/tee-node/remote-kms.ts` |
| 5 | 存证链 | ChainMaker | 另一条链（联盟链/公证链） | `ChainAnchorSink.anchor()` 签名 | `packages/mdop/src/anchor/anchor.ts` |
| 6 | 编排通道 | legacy 通道 | MDOP 通道 | 分析语义与产物 schema | `apps/api/src/runtime/orchestration/orchestration.migration.json`（`legacyBudget` 单调下降） |
| 7 | 算法实现 | TS 内联算子 | 签名 Wasm 模块 | 输入/输出载荷、误差口径 | `packages/wasm-algorithms/`（源码重建逐字节一致） |

> **第一轮只做 3、4、5**——理由是这三条正对"供应商锁定"焦虑的核心（证明、密钥、存证）。
> 数据源与算法实现放第二轮，因为它们更多是工程收益，不是信任问题。

## 2. 演练协议（七步，顺序不可换）

### 第 0 步 · 预注册判据（**最关键**）

在动手之前，把判据写进 `docs/售前/drill/<axis>/pre-registration.md` 并 **commit**。判据包含：

- 允许改动的路径集（白名单，精确到目录）
- 输出比对方式（逐字节相等，或已声明的字段级白名单）
- 必须保持全绿的守护清单
- 判定"通过/不通过"的阈值

**commit 之后判据不可修改。** 改了即视为演练作废、重新开始。这条是防"结果导向调判据"，也是整份方案能不能被审计采信的分水岭。

### 第 1 步 · 基线双跑（确认确定性）

同一输入、同一配置跑两遍，输出 JSON 的 SHA-256 必须相等。

不相等就先修确定性——**不然后面所有"同输入同输出"的判据都是假的**。

### 第 2 步 · 单点替换

只改该层。允许动：接口实现、装配（wiring）、配置。

### 第 3 步 · 零改动证明（机器判据）

```bash
git diff --name-only <baseline-sha> | sort > drill/<axis>/touched.txt
# 逐行比对 pre-registration 里的白名单；任何一行越界 = 不通过
```

**人眼看过不算，必须用集合包含关系判定。** 这一条是整场演练的技术核心：它把"调用点零改动"从一个形容词变成一个可以 `diff` 出来的集合。

### 第 4 步 · 同输入同输出

替换前后的产物（聚合投影 / 回执 / 链 payload）做 SHA-256 比对：

- 完全相等 → 最强结论；
- 不相等 → 只允许预注册里声明的字段差异，且必须逐字段列出并解释（例如 `tx_id`、时间戳、`attestationLevel`）。

### 第 5 步 · 闸门不松

```bash
pnpm test     # 12 个守护 + 15 个负例自检 + 工厂 schema 对拍 + 工厂负向验证
```

**同时检查测试文件本身没被改松**：`*.spec.ts` / `*.test.ts` 与 `scripts/check-*.mjs` 必须落在"不许改"路径集里。若确需改动，在演练记录里写理由并由第二人复核——否则演练作废。

### 第 6 步 · 留痕与归档

产出回执与 `tx_id`，把演练记录落 [`.agent-runs/`](../../.agent-runs/)（它本身就是一次 coding agent 会话，必须落血缘，见 [AGENT-OPS.md](../../AGENT-OPS.md) §4）。

归档物（每轴一个目录）：

```
docs/售前/drill/<axis>/
  pre-registration.md   # 预注册判据（commit 时间戳即证据）
  baseline.json         # 基线双跑的两个 hash
  touched.txt           # 实际改动路径清单（与白名单比对结果）
  output-before.json / output-after.json
  gates.txt             # pnpm test 全量输出
  record.json           # 结论、复核人、失败原因（若失败也照实写）
```

## 3. 反作弊清单

演练最容易变成"表演"，所以把**可能作弊的地方**先堵掉：

| 作弊手法 | 堵法 |
|---|---|
| 事后放宽判据 | 预注册 commit 后不可改；改了演练作废 |
| 悄悄改断言/删测试 | 测试与守护路径纳入"不许改"集合，并检查 diff |
| 用 `skip` / `only` / 环境变量关掉失败用例 | 扫描 diff 中 `describe.skip` / `it.only` / `--forceExit` 等标记 |
| 只跑通过的那部分测试 | 必须以 `pnpm test` 全量输出为证据，不接受子集 |
| 挑一个容易的输入 | 输入集预注册（含边界：空集、单行、超阈值触发抑制、缺失率高） |
| 隐藏失败 | **失败也必须记录**（AG-2：失败与中止的会话同样落血缘） |
| 单人自证 | 一人操作、一人复核 diff 范围与判据 |

> 最后一条尤其重要：**给客户看的不是"我们全绿"，是"我们的判据不可被我们单方面解释"。**

## 5. 给客户看的一页（演练汇总矩阵）

| 轴 | 改动文件数 | 是否越界白名单 | 输出是否逐字节一致 | 守护是否全绿 | `tx_id` | 结论 |
|---|---|---|---|---|---|---|
| 3 证明提供者 | 3（实现 + 装配 + 配置） | 否 | 一致 | 是 | `…` | 通过 |
| 4 密钥管理 | 2 | 否 | 一致（仅 `release` 字段按预注册差异） | 是 | `…` | 通过 |
| 5 存证链 | 1（sink 实现） | 否 | 一致（`tx_id` 差异已声明） | 是 | `…` | 通过 |

**这张表的说服力来自第三列与第六列**：改动范围是**几行文件**，且链上留了 `tx_id`。
客户能自己拿着第三列去核对 `git diff`——这比任何"我们架构解耦"的说法都硬。

## 6. 和"敢用"的关系

回到最初的问题：怎么让数据集团**敢于**使用。

演练给的是这样一句可以写进会议纪要的话：

> "该平台的可替换性已由第三方见证的演练验证：任意替换证明提供者、密钥管理或存证链，
> 改动范围限于该层实现与装配，**调用点零改动、产物逐字节一致、全部合规守护保持绿**，
> 演练判据在动手前预注册并可复核。"

这句话里有三样东西是采购最需要的：**范围有界**（改动几行）、**结果可验**（逐字节 + 判据预注册）、**责任可查**（`tx_id` + 血缘记录）。

## 7. 现在就能做的一步

不需要等两周。**先做轴 5（存证链）的"替身 sink"演练**：

`ChainAnchorSink` 只有一个方法（`anchor(input) → {tx_id}`），用内存替身实现即可跑通全链，半天能出第一份 `touched.txt`。
拿到这份文件，你第一次见数据集团时就不是带 PPT 去，而是带一张"我们换过一层链，改动只有 1 个文件"的 diff。
