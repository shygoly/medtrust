# 决策依据包 —— MedTrust 技术路线合规论证

> **用途**：给数据集团（平台运营方）、医院信息科/法务、以及上级评审看的一份材料。
> 目标不是"证明我们先进"，是让签字的人**有据可依、有退可守**。
>
> **使用方式**：这份是**目录与写作规格**。每一章都标了 `【素材】`（本仓哪个文件）、
> `【外部锚点】`（哪份标准/文件）、`【给谁看】`。定稿时按此逐章展开，附录 A 必须逐行可执行。
>
> **一条纪律**：本材料**不许出现无法当场验证的论断**。每条技术断言后面必须跟一条命令或一个文件行号；
> 做不到的，写进第 8 章"已知短板"，不写进正文。

## 0. 一页纸结论（写给不读长文的人）

四个"是/否"，每个后面跟一句证据：

1. **数据会不会出域？** 不会。原始行不进任何跨域边，出网只走 OutputGate（小样本抑制 + 行级拦截）与 HE/安全聚合。
2. **密码合不合规？** 国密 SM2/SM3/SM4 全链路，直引文件在白名单内且有机器守护（现状：直引 9 = 白名单 6 + 在册偏离 3，偏离已登记待偿还）。
3. **出了事能不能查？** 能。合约 → 见证 → 回执 → 链锚定四段留痕，且**血缘（哪个 agent 改了什么）有机器校验**。
4. **被锁死怎么办？** 七条替换轴每一层都可换，其中**存证链已经真实更换过一次**（FISCO BCOS → ChainMaker）。

> 这一页的作用：让评审在 3 分钟内决定"可以往下看"，而不是先怀疑。

## 1. 项目定位与角色分工

`【素材】` [ARCHITECTURE.md](../../ARCHITECTURE.md) §1/§2、[DOMAIN.md](../../DOMAIN.md) 角色表、[docs/丝路数港-接口对拍表.md](../丝路数港-接口对拍表.md)
`【外部锚点】` 国家数据局首批 63 个可信数据空间试点（13 城市 + 22 行业 + 28 企业）；上海市《可信数据空间建设运营指南》DB31DSJ/Z 006—2026
`【给谁看】` 数据集团决策层

要写清楚的只有一件事：**谁站哪个位**。

| 角色 | 谁 | 边界 |
|---|---|---|
| 平台运营方（operator） | 数据集团 | 持有场景、合约、结算与对外资质；**不接触原始数据** |
| 技术提供方（technology provider） | 我们 | 提供底座与连接器；**不持有数据、拿不到院内侧密钥** |
| 数据提供方（provider） | 医院 | 原始数据永不出院；只出聚合与回执 |
| 数据消费方（consumer） | 药企/申办方/研究机构 | 只拿契约允许的产物 |

**这一段是整份材料的政治基础**：把数据集团放在"运营方"而不是"采购方"，它才愿意署名、才愿意去申报试点。

## 3. "数据不出域"的可复核证明

`【素材】` `apps/connector/src/domain/output-gate.ts`、`policy-enforcement.ts`、`local-store.ts`、`he-aggregator.ts`；[FLOWS.md](../../FLOWS.md) 的 `crosses × payload` 红线
`【给谁看】` 医院信息科、伦理、数据集团安全负责人

写作要点：**不要写"我们保证"，写成"三层结构性阻断"**，每层给一个可当场演的动作：

1. **语法层**：跨域边声明 `crosses × payload`，`raw-local` 不得出现在任何跨域边 —— `node scripts/check-meta-docs.mjs` 可验。
2. **执行层**：连接器内只有算子，没有"取数 API"；输出必经 OutputGate（小样本抑制 + 行级拦截），阈值来自 `DEFAULT_MIN_CELL` / `DEFAULT_MIN_AT_RISK`，禁止裸写。
3. **网络层**：出站只有一条长轮询通道，无入站；院内网络分区见 [docs/医院连接器独立部署准备.md](../医院连接器独立部署准备.md) §2.4。

**现场可演**：拿一条超阈值的聚合结果，当场触发抑制，展示被拦的回执。这比架构图有用十倍。

## 4. 安全与密码合规

`【素材】` [TRUST.md](../../TRUST.md) 红线清单（4 组）、`apps/api/src/security/`、`packages/mdop/src/crypto/`
`【外部锚点】` 商用密码应用安全性评估（密评）、等保 2.0 三级

要写：国密算法覆盖哪些环节（传输/存储/签名/摘要）、密钥怎么管（Vault + 5 分钟缓存 + 院内侧密钥不出域）、以及**四条红线各自的机器守护**：

- 红线 1 `sm-crypto` 白名单 → `check-crypto-imports.mjs`（6 条负例自检；在册偏离还清后仍留名单也判红）
- 红线 2 闸门阈值禁裸写 → 小单元格阈值只能引常量
- 红线 2b 未过闸聚合禁出网（merge-then-gate）
- 红线 3 控制面禁行级医疗字段
- 红线 4 TEE 表述红线 → `check-tee-claims.mjs`（当前 `attestationLevel` 恒 `software`，**对外不许声称硬件级**）

> 第 4 组红线是这份材料可信度最高的地方：**我们给自己写了"不许吹牛"的机器约束**。
> 评审看到一条"厂商自愿限制自己宣传口径"的规则，比看到十页性能数据更能建立信任。

## 5. 智能体治理（差异化章节）

`【素材】` [AGENT.md](../../AGENT.md)（R1–R5）、[AGENT-OPS.md](../../AGENT-OPS.md)（L0–L3 动作分级 + F-1…F-5 禁令 + X-1…X-7 豁免）、`scripts/check-agent-lineage.mjs`
`【给谁看】` 数据集团技术负责人、审计

大多数可信空间方案在这一章是空白。要写三件事：

1. **平面登记**：每个 agent 必须登记 `plane`；`plane: connector-local` 是**非法值，校验直接红**——因为连接器是唯一能触达原始数据的部件，在它上面跑不可预测的 agent，等于给"数据不出域"开口子。
2. **动作分级**：agent 的动作按影响面分 L0–L3，L3（改已应用迁移、削弱出域闸、写密钥入库）**不设人工放行档**。
3. **血缘可追溯**：每个改动仓库的会话必须落一份血缘记录，由 `check-agent-lineage.mjs` 强校验（存在性 / 12 字段 schema / cost 与实测对拍 / 放行口径 / append-only），存量欠账走棘轮基线。

> 这一段回答的是评审心里那句没问出来的话：**"你们自己用 AI 改代码，怎么保证它不会把闸门改松？"**

`【给谁看】` 审计、评审专家 —— 这一章决定他们敢不敢签字

逐条列，每条给"影响 / 处置 / 时间表"：

| 短板 | 影响 | 处置 |
|---|---|---|
| **信创未适配**（Node 20 + Postgres + better-sqlite3） | 部分 SOE 采购的硬门槛 | 立项评估达梦/人大金仓 + 麒麟 + 鲲鹏适配；不隐瞒，投标前明示 |

| **团队规模 / 注册资本** | 可能无投标资格 | 与大厂或本地集成商组联合体，双章投标；源码 escrow |
| **X-1**：L2 人工放行无平台时间戳 | 放行不可独立归属 | 交互式确认留痕；接入 MR review 后失效 |
| **X-6**：token / 时长预算无运行时强制点 | 预算靠人事后审计 | 已在 `check-agent-lineage` 事后计量，运行时钩子待补 |
| **待接入 15 个 CTL** | 有条款未落地 | 独立台账跟踪，不混入正册 |
| **部分外部事实为媒体摘要级** | 引用可能失真 | 沿用 `research/competitions/competition-radar.md` 的"待核"标注法，标注核实层级 |

> 这一章的写法本身就是论点：**一家愿意把自己的短板列成表格并且给处置方案的供应商，比一家什么都能做的供应商更可审计。**

## 写作与交付规格

- **篇幅**：正文 40 页左右；附录 A 一页；第 8 章不超过 3 页。
- **排版**：每章首页放"本章一句话结论"，正文用表格与代码块，**不用形容词堆砌**。
- **版本纪律**：材料里每条断言绑定一个 commit 或一个命令；仓变了材料要跟着变，否则视为失效。
- **交付形态**：PDF + 一份可执行的 `make verify`（或 `pnpm test`）说明，让评审能自己验。
