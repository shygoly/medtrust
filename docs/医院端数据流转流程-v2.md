# MedTrust 医院端数据流转全流程 v2

> 本方案取代《MedTrust_医院端数据流转流程》PDF（Coze 生成版）。
> 与 [ARCHITECTURE.md](../ARCHITECTURE.md) 硬决策（D1–D12）对齐；面向医院信息科 / 安全审计的口径组织。
> **诚实表述原则（D9 硬约束）**：当前计算隔离为软件级（`attestationLevel: software`），硬件机密计算（海光 CSV）为明确升级路径。本方案所有安全承诺均按当前真实能力表述，不虚标硬件信任根。

## 一、核心原则（对医院的五条承诺）

1. **原始数据不出域**：患者行级数据全程留在院内，跨域只流动聚合结果（计数 / 效应量 / 加密梯度）。
2. **合约即授权，可强制、可撤销**：每次数据使用对应一份数字合约（范围、算法、隐私预算、留存期限），由院内连接器的策略执行点（PEP）强制执行；合约撤销立即中止任务（fail-closed）。
3. **出域必过闸门**：任何结果出域前必须同步通过输出闸门（白名单塑形 + n<5 小单元格抑制 + 差分隐私预算记账），任一环节失败则结果不出域。
4. **全程国密**：身份（SM2 证书）、通道（SM2 密钥协商 + SM4 加密）、完整性（SM3）全链国密，不用非国密替代做信任链。
5. **全程可审计、可验证**：每次采集与出域均有签名日志；任务证据（输入条件哈希、算法指纹、结果哈希、隐私预算消耗）上长安链存证，医院可独立核验。

**网络原则（替代原方案的"硬件网闸 + 单向摆渡"）**

| 原则 | 内容 | 审计口径 |
|------|------|----------|
| 无入站 | 连接器节点不监听任何来自互联网的连接，只主动外连控制面（gRPC/WS over SM2 安全通道） | 边界防护：入站攻击面为零 |
| 出站白名单 | 防火墙仅放行连接器→控制面单一域名/IP:端口；其余出站全部拒绝 | 出站可控、可审计 |
| 逐区外拨 | 采集区只主动外连隔离区，隔离区只主动外连控制面；任何区不接受来自低信任区的入站连接 | 分区隔离，连接方向单一 |
| 网闸可选 | 若医院强制要求网闸，部署在采集区↔隔离区之间，**作为协议摆渡（双主机摆渡）而非严格单向光闸**——因为任务规格需要进、脱敏数据需要出，严格单向在协议上不成立 | 如实表述，不虚标"物理单向" |

> 原 PDF 方案中"内网与 TEE 域无直接 TCP 连接、单向摆渡"与"RA-TLS 握手"存在物理矛盾（TLS 握手需要双向报文）。v2 用"仅出站 + 白名单 + 分区逐区外拨"达成同等的边界收敛效果，且协议上自洽。

**进程特权分离（修正原方案沙箱 A 的缺陷）**

原方案中网络沙箱 A 同时持有明文患者数据与网络能力，"特权分离"只保护了计算沙箱。v2 划线：

- **明文只存在于无网络权限的进程**：采集脱敏模块（内网采集区）与计算工作进程（隔离区，OS 级隔离、无 socket 权限）。
- **有网络能力的通信进程只经手两类内容**：入向的任务规格 + 出向的已过闸门聚合结果。它永远接触不到行级数据。

## 三、数据流转全流程

### 阶段 0：准入与部署（一次性）

| 步骤 | 内容 | 对应实现 |
|------|------|----------|
| 0.1 | 医院实名准入：双认证（营业执照/医疗机构执业许可 + 法人/经办人）、数据分级分类备案 | `participant-identity` 准入门 |
| 0.2 | 平台 SM2 CA 为医院连接器签发身份证书；私钥在院内生成，不出域 | SM2 CA |
| 0.3 | 连接器（`apps/agent`）部署于院内隔离区；防火墙配置出站白名单；信息科验收网络策略 | 部署手册 |
| 0.4 | 医院加入静态信任清单；吊销走拉模式 CRL | D-ID-1 |

### 阶段 A：数字合约签订（每个研究一次）

| 步骤 | 内容 | 安全/审计要点 |
|------|------|---------------|
| A.1 | 药企在目录中选定数据产品，发起合约申请 | 目录只含元数据（字段结构、样本量级），不含任何患者数据 |
| A.2 | 合约明确：入组条件、允许的分析类型（L1.5–L4）、输出白名单 schema、差分隐私预算 ε 总额、算法包 SM3 指纹、留存期限、计价 | 最小必要原则的合同化 |
| A.3 | **医院侧审批**：信息科 + 伦理/合规角色在控制台审批；未批不生效 | 医院对每次数据使用有事前否决权 |
| A.4 | 合约哈希上链存证；合约策略同步至连接器 PEP | 事后不可抵赖 |
| A.5 | 合约可随时撤销：撤销即时下发，PEP 立即中止在途任务（fail-closed） | D-DC-1 |

### 阶段 B：任务执行（每个分析任务，七步）

**Step 1 任务下发**
- 药企/研究者向控制面提交任务（分析类型 + 参数），控制面校验后经既有出站通道推送给连接器（连接器主动长连接，无入站）。
- 任务必须引用已生效合约；**PEP 第一道校验**：任务类型、参数、字段范围均须落在合约授权内，越界即拒绝。
- 跨域进入院内的只有代码引用 + 参数，不含任何数据。

**Step 2 通道与算法完整性校验**
- 通道：SM2 双向证书认证 + SM2 密钥协商 + SM4-GCM 加密 + SM3 完整性（全链国密，替代原方案 RA-TLS/AES/SHA256）。
- 算法完整性：连接器计算算法包 SM3 指纹，与合约白名单指纹比对，不符即拒绝执行。
- **诚实表述**：当前阶段算法完整性依赖"平台签名 + 合约指纹比对 + 医院可复核的算法清单"，任务记录中 `attestationLevel = software`。硬件阶段（海光 CSV）升级为硬件度量 + 远程证明，届时该字段升为 `hardware`。**在此之前不向医院声称硬件级保证。**

**Step 3 院内采集与脱敏**
- 采集脱敏模块以只读账号/只读视图访问 HIS/EMR/LIS/PACS；采集范围严格限定于合约入组条件。
- **采集即脱敏**：直接标识符（姓名、身份证号、电话、地址等）剥离；患者 ID 经 SM3-HMAC（院内本地盐）假名化。假名映射表与盐仅存于采集区，永不进入计算区，更不出院。
- 每次采集写签名审计日志（谁、何时、依据哪份合约、取了哪些字段、多少行）。

**Step 4 域内传递**
- 脱敏数据集由采集区主动推送至隔离区连接器（院内传输 SM4 加密；如部署网闸则经协议摆渡）。
- 落盘仅限隔离区加密暂存区（SM4 静态加密），带留存 TTL，任务结束由 retention 服务销毁。

**Step 5 本地计算**
- 计算工作进程（无网络权限）在院内执行，按合约允许的分析阶梯：

| 层级 | 分析类型 | 出域内容 |
|------|----------|----------|
| L1.5 | 失衡信号检测（PRR/ROR） | 四格表汇总计数 a/b/c/d |
| L2 | Meta 分析（DerSimonian-Laird） | 效应量 + SE |
| L3 | 因果推断（PSM + Cox） | 匹配后 HR/ATE + SE |
| L4 | 联邦学习（SecureBoost） | 加密梯度 |

- 全程行级数据不离开计算进程边界；无明文落盘（暂存区除外，见 Step 4）。

**Step 6 输出闸门（出域必经，fail-closed）**

出域前**同步**完成，任一失败 → 结果不出域、任务失败并留痕：

| 防线 | 机制 | 处置 |
|------|------|------|
| 1 | PEP 复核：输出与合约授权二次比对 | 越界即阻断 |
| 2 | 白名单塑形：输出只允许合约声明的 schema（效应量/计数/梯度），其余字段一律剥除 | 非白名单内容不出域 |
| 3 | 小单元格抑制：任何单元格 / 队列人数 n<5 | 自动阻断输出 |
| 4 | 差分隐私：按合约 ε 预算记账注入校准噪声；**预算耗尽即拒绝**（累计记账，防多次查询拼接） | 预算内才放行 |
| 5 | 结果签名：连接器 SM2 私钥对结果 + 元数据（合约 ID、算法指纹、attestationLevel、ε 消耗、cohortSize）签名 | 可验证、不可抵赖 |

出域**后**的旁路义务（上链存证、写结算台账、通知）**异步执行 + 补偿队列**，失败不回滚已合规出域的结果（fail-open，D-UC-2 划线）。

**Step 7 回传、存证与结算**
- 仅签名后的聚合结果经既有出站通道回传控制面；控制面做多中心合并（Meta 合并 / 联邦聚合）。
- 证据包（输入条件哈希、算法 SM3 指纹、结果哈希、attestationLevel、ε 消耗、各院 cohortSize）SM3 哈希后上长安链——**链上只存证据，不存任何数据**。
- 结算：按 cohortSize 贡献度计量写台账并上链清算。
- retention 服务销毁本任务暂存数据并留销毁凭证。

### 阶段 C：持续审计与撤销（贯穿始终）

- 医院控制台可查本院全部任务：每次采集、每次出域、ε 预算余额、结算流水；逐条可回溯至链上证据核验。
- 审计日志 SM3 哈希链式串联，防篡改；日志只含统计效应量与元数据，不含患者数据。
- 合约撤销 / 证书吊销（CRL）→ 连接器 PEP 即时中止，在途任务作废。

| 合规要求 | 对应节点 | 保障机制 |
|----------|----------|----------|

## 五、与原 PDF 方案的差异对照

| 议题 | 原 PDF 方案 | v2 方案 | 理由 |
|------|-------------|---------|------|
| 边界隔离 | 硬件网闸单向摆渡（与 RA-TLS 双向握手矛盾） | 仅出站 + 白名单 + 逐区外拨；网闸可选且如实定位为协议摆渡 | 协议自洽，等保口径等效且可解释 |
| TEE | ARM CCA / Intel TDX / 鸿蒙微内核（不落地、非信创） | 软件隔离如实标注 `software`，硬件路径为海光 CSV | D9 硬约束：不虚标；信创合规 |
| 信任链 | RA-TLS + SHA256 + AES-256（国密仅备选） | SM2/SM3/SM4 全链国密 | D8：医疗密评强制项 |
| 授权模型 | 仅"入组条件限定采集" | 数字合约 + 使用控制（PEP 强制、ε 预算、即时撤销）+ 医院事前审批 | D4：对齐国家数据局 TC609 核心技术体系 |
| 存证 | TEE 内签名日志 | 签名日志 + 证据哈希上长安链（只存证据不存数据） | D6：医院可独立核验，不依赖平台自证 |
| 脱敏 | 无（明文进沙箱） | 采集即脱敏，假名映射表与盐永不离开采集区 | 缩小明文暴露面 |
| 特权分离 | 网络沙箱持有明文（A 被攻破即可外泄） | 明文只存在于无网络进程；联网进程只经手任务规格与已过闸门结果 | 补上原方案最大的残余风险 |
| 算法完整性 | MRENCLAVE（SGX 术语误用） | 算法包 SM3 指纹 + 合约白名单比对；硬件阶段升级为度量+远程证明 | 术语正确、当前可实现 |
| 结算 | 无 | cohortSize 贡献计量 + 上链清算 | D12：医院参与的收益闭环 |
| 分析类型 | 缺 L2 | L1.5–L4 完整阶梯 | 与已实现能力一致 |

## 六、分阶段落地

| 阶段 | 计算隔离 | attestationLevel | 触发条件 |
|------|----------|------------------|----------|
| **现阶段** | OS 级软件隔离（无网络计算进程）+ 合约指纹校验 | `software`（合约/审计/UI 全链如实标注） | 已实现 |
| **硬件阶段** | 海光 CSV 机密虚拟机 + 硬件度量 + 远程证明绑定通道密钥 | `hardware` | 海光 CSV 环境可用后，仅升级 Step 2/5 的隔离与证明强度，流程与闸门语义不变 |

升级不改变七步流程与合约语义——医院侧看到的唯一变化是 `attestationLevel` 字段与证明材料的增强。
