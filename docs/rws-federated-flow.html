完整流程（7 步）

1

准备本地演示数据

仓库根目录 · 终端

将 Synthea FHIR 切分到各院目录，烘焙进 Fly RWS Worker 镜像。

  • pnpm split-synthea → data/synthea/hospitals/{院}/fhir/
  • pnpm ingest-synthea → data/synthea/connectors/{院}/
2

医院发布数据产品

Web · 示范甲账号 · /space/catalog

种子数据自动发布；产品 fhirSchema.dataPath 指向本地路径，供连接器 prefetch 后加载。

API: POST /api/v1/catalog
3

药企申请 → 医院签发数字合约

Web · /space/contracts

药企选择数据产品并申请合约；医院审批后状态为 active。连接器 PEP 按合约约束执行。

API: POST /contracts/requests · POST /contracts/:id/approve
4

药企发起 RWS 任务

Web · 研究院账号 · /space/tasks/new

选择生效合约与分析类型，提交后控制面校验准入并写入持久化表。

  • condition-prevalence — 标签患病率
  • cohort-count — 按 ageBand 队列规模
  • adverse-event-signal — 不良事件信号
API: POST /api/v1/rws/tasks
5

连接器出站拉取（无入站端口）

medtrust-rws-worker-a · CONNECTOR_PARTICIPANT_ID=p-demohospa

ConnectorWorkerService 每 5s 轮询控制面，拉取 pending 分派 → queued → pulled。

API: GET /api/v1/connector/rws/pending
6

本地执行流水线

RWS Worker 进程内 · 数据不出域

prefetch 目录 → 解析 dataPath → LocalStore → PEP → TEE 计算 → 输出门控 → 阅后即焚。

catalog-prefetch data-load pep-check compute output-gate retention complete
7

回传聚合 & 控制面合并

Web · /space/tasks/[taskId]

连接器 POST cohortSize + buckets；任务详情页展示各院进度与合并聚合。

API: POST .../complete · GET /api/v1/rws/tasks/:id

关键 API 速查

方法路径调用方说明
POST/api/v1/rws/tasks药企 JWT发起 RWS
GET/api/v1/rws/tasks/:idJWT任务状态、进度、merged
