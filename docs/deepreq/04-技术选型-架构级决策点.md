## D-RWS-3 · 链上存证真写入 —— **已基本落定:迁移到长安链 ChainMaker**

> **勘误**: 00/01/03 文件中"存证写入仍 mock(FISCO 3.x 无 JS SDK)"的描述已被现实推翻。见 `docs/migration-chainmaker.md`(状态: 阶段 0–4 已通过)与 `fly-services/chain-sdk/`(可用 Java sidecar)。

### 背景
原 FISCO BCOS v3.6 路线在 Fly 上**实测不可控地走不通**:Java SDK 的 JNI native 层在 WS-over-TLS 会话建立后,每个 RPC 请求被节点侧 socket 读超时丢弃(`[RPC][WS][SESSION][drop]`),非应用层可修(详见 migration 文档附录 A)。

### 选项
| 方案 | 评价 |
|---|---|
| **A. 迁移长安链 ChainMaker + Java SDK sidecar(已实现,推荐)** | ChainMaker 纯 Java SDK 无 JNI native(规避 FISCO 死结)、原生 EVM 可直接复用现有 `MedicalDataAttestation.sol`、原生国密 SM2/3/4、信创自主可控(医疗合规叙事契合)。sidecar 保持原 HTTP 契约(`/attest`、`/block-number`、`/health`),上层 NestJS adapter 零改动。 |
| B. FISCO 降链到 2.x 用 npm SDK 进程内写 | 退回旧版、放弃 3.x 特性;且 2.x SDK 维护态差;与已投入的 ChainMaker 工作重复。 |
| C. FISCO 3.x Go/Python SDK sidecar | 可行但 FISCO 在本环境的 native TLS 问题已证伪,换语言 SDK 未必绕开节点侧 socket drop;ChainMaker 已验证通过,无理由回头。 |

### 推荐: A(沿用已实现的 ChainMaker sidecar)
`Sidecar.java` 已实现:`createContractCreatePayload(..., RuntimeType.EVM)` 部署合约、`invokeContract("storeAttestation", evmData(...))` 真实写入(Solidity ABI calldata 编码)、`getBlockHeightByTxId` 回读区块高度。

### 落地步骤(残留收尾)
1. **命名中性化**: `fisco-bcos.adapter.ts` → `chain.adapter.ts`(已见 git status 有 `chain.adapter.ts`/`chain.service.ts` 新增);env `FISCO_BCOS_NODE1_URL` → `CHAIN_SIDECAR_URL`;app label 去 fisco。
2. **合约编译 pin**: 必须 `solc 0.8.17`(ChainMaker v2.3.0 EVM 不支持 0.8.20+ 的 `PUSH0`)。
3. **密钥治理(★ 真残留风险)**: sidecar 现从文件系统读 admin/client 证书与签名私钥(`client1.sign.key` 等),且 `ArchiveConfig` 硬编码 `root:123456@localhost:3306`。生产前:私钥入 Vault、归档配置外置、去除明文口令。→ 见 D-RWS-3-a。
4. **部署形态**: 现为 `wx-org-solo` 单组织单节点(solo 共识)。生产需评估多节点共识 → 见 D-RWS-3-b。

### 残留风险
- **D-RWS-3-a(密钥/口令)**: sidecar 明文证书+硬编码 mysql 口令,须治理后才能称"可信存证"。
- **D-RWS-3-b(单节点信任)**: solo 单节点 = 中心化背书,审计不可抵赖性弱于多节点;第一版可接受,生产需多节点。

## D-RWS-2 · RWS 切口形态:信号检测 vs 队列疗效

### 选项
| 方案 | 适用 | 输出闸门/schema 影响 |
|---|---|---|
| **A. 信号检测(不成比例分析)优先(推荐第一版)** | 药物警戒被动监测;单方即可算;贴 RWS demo | 输出 = 四格表计数 `(a,b,c,d)` + ROR/PRR/χ²/IC;闸门按"信号"类型套 n<5 抑制 |
| B. 队列疗效分析 | 主动随访队列;需人时/删失/协变量 | 输出 = 发生率/HR/KM 点;闸门须防小分层再标识,schema 含队列入排+随访窗 |
| C. 两者皆做(类型判别字段) | 长期目标 | task schema 加 `analysisType` 判别,指标引擎双实现 |

### 推荐: A 先行,schema 预留 C
- 这是**唯一靠调研无法消除**的不确定项,精确形态需真实药企 PV 岗访谈。
- 工程上不必等访谈:先实现信号检测(公式确定、单方可算),用 `analysisType` 字段把队列疗效留作第二实现,降低返工。

### 落地
- `SecretFlowTaskSpec`/RWS analysis spec 增 `analysisType: 'signal' | 'cohort'`(jsonb `analysis` 内);第一版只接 `signal`。
- 指标引擎按 type 分派;闸门规则表按 type 索引(信号: a≥3 + n<5 抑制;队列: 分层最小样本 + 删失处理)。

### 残留风险
- 访谈结论可能要求队列特有指标(如倾向评分匹配),届时补 `cohort` 实现;判别字段保证不动信号路径。

## D-RWS-4 · TEE 软件 fallback 的信任表述 + 何时切海光 CSV

### 现状
Fly 上 `apps/agent` 跑 `runtime=torch` 软件隔离,**无硬件远程证明(remote attestation)**。设计目标硬件 = 海光 CSV(D9)。

### 选项
| 维度 | 方案 |
|---|---|
| **信任表述(推荐)** | 在数字合约/审计/UI 显式标注当前通道 = `software-isolation`(非硬件 TEE);`attestationLevel` 字段贯穿任务记录与上链证据。**绝不向医院声称硬件级机密计算**,直到证明可用。 |
| 切换时机 | 以"可获得海光 CSV 实例 + CSV attestation report 可校验"为硬门;在 TEE 抽象层下做可插拔实现(软件 ↔ CSV),不改上层。 |

### 推荐
- 立即:加 `attestationLevel ∈ {software, hygon-csv, ...}` 字段,默认 `software`,写入任务记录 + 上链证据 + 合约表述。
- 切换:海光 CSV(AMD SEV 同源,x86 兼容、内置国密)通过 TEE 抽象层接入;CSV 提供 attestation report(度量虚机镜像),sidecar 校验报告签名后才标 `hygon-csv`。
- TEE 抽象层接口: `attest() -> AttestationReport`、`run(task)`;软件实现返回 `software` 级空报告,CSV 实现返回真实报告。

### 残留风险
- 海光 CSV 实例获取/运维成本高(design Risks);在拿到硬件前,所有"机密计算"承诺都须降级表述,合规与商务沟通须同步。

## D-DC-1 · 合约撤销对在途 TEE 任务:立即中止 vs 完成当前批

### 选项
| 方案 | 权衡 |
|---|---|
| **A. 立即中止(fail-closed,推荐)** | 撤销即数据主权回收,语义最干净;在途任务收到撤销信号 → orchestrator 走 compensation 丢弃该 provider party,不出其结果。与"使用控制全程可控"一致。 |
| B. 允许完成当前批后停 | 用户体验好、不浪费已算;但撤销后仍出域 = 主权约束被弱化,违反"授权后全程可控"。 |
| C. 宽限期(grace window) | 折中:撤销后 N 秒/当前 step 完成即停;复杂度高。 |

### 推荐: A(立即中止)
- 复用已有 FSM compensation 能力(`OrchestratorFsmService` 已支持 drop party 并继续/失败)。撤销 = 注入一个 `compensation` 事件,等价于该 party 超时丢弃。
- PEP 在每次 step 前校验合约 active;revoke 后下一次校验即拒(B7-1)。对**长 step**(单 step 内已读数据)依赖"关键义务出域前完成"(见 D-UC-2)兜底:未过闸门的中间结果物理无出口。

### 落地
- `ContractService.revoke()` → 发事件到 orchestrator;orchestrator 对匹配 in-flight 任务注入 `COMPENSATE(partyId)`。
- 全 party 被撤 → 任务 `FAILED`;部分 → `COMPENSATED` 出剩余院结果。

### 残留风险
- 已进入 TEE 且本 step 即将产出的计算被丢弃 = 算力浪费(可接受,主权优先)。

## D-UC-2 · 出域义务(上链/结算)失败的处理

### 核心约束
结果一旦出域**不可撤回**(数据主权)。因此义务分两类,处理不同:

| 义务类 | 处理(推荐) |
|---|---|
| **出域前关键义务**(输出闸门校验、ε/小单元格、白名单塑形) | **fail-closed**:任一失败 → 结果不出域。这是数据主权的硬保证。 |
| 出域后旁路义务(上链存证、写结算台账、通知) | **fail-open + 补偿队列**:不阻塞已合规出域的结果;失败进重试队列,最终一致;持续失败告警。 |

### 推荐
- 明确划线:**凡涉及"决定数据能否出域"的义务,必须在闸门内同步完成且 fail-closed**;凡"事后留痕"的义务,异步补偿,不得反向阻断已出域结果(否则等于把不可撤的动作绑死在可失败的动作上)。
- 上链存证属"事后留痕" → 异步 + 重试 + 告警(与 D-RWS-3 sidecar 的异步写一致;migration 文档已记 API 异步存证)。

### 落地
- 出域闸门 = 同步 fail-closed;`onComplete` PXP(anchor + settlement)= 异步,失败入补偿队列(可复用现有调度/审计),状态机加 `released-pending-attest` → `attested`。
- 审计须能区分"已出域已上链"与"已出域待上链"。

### 残留风险
- 出域后、上链前的短窗口内,证据链未闭合;告警 + 补偿队列把窗口压到最小,审计明确标注该中间态。

## D-CN-1 · 两套连接器收敛(`apps/connector` vs `apps/agent`)

### 现状
- `apps/connector`(NestJS): 完整域服务 demo,**不接控制面**(自包含 `demo`/`demo:e2e`)。
- `apps/agent`(Python, Fly connector-a/b): **真正接入控制面**的节点(gRPC 5024 + WS 5023,真 torch FedAvg)。

### 选项
| 方案 | 权衡 |
|---|---|
| **A. agent 为生产接入节点,connector 降级为规格参考/离线 demo(推荐)** | 承认现实:真实链路在 agent。connector 保留为"域服务规格的 TS 参考实现 + 离线验证",不接控制面。职责文档化,避免误用。 |
| B. 把 connector 域服务移植进 agent | agent 用 Python,connector 用 TS;移植成本高、重复造轮。除非要 TS 侧生产化,否则不值。 |
| C. 废弃 agent,生产化 connector(接控制面) | 要重写 connector 的 gRPC/WS + 真实 FedAvg(agent 已有 torch 实现),倒退。 |

### 推荐: A
- 单一事实来源 = `apps/agent`(已验证 e2e、已上 Fly)。`apps/connector` 标注为「域服务规格 TS 参考 / 离线 demo,不接入控制面」,在其 README 与 CLAUDE.md 写清,杜绝把它当生产节点。
- 两者**共享规格**(数据不出域守卫、PEP、output gate、retention 语义)——以文档/spec 对齐,不强求代码共享(跨语言)。

### 落地
- `apps/connector/README` + 仓库 CLAUDE.md 明确二者定位(部分已在 CLAUDE.md);确保 output_guard 语义两侧一致(allowedArtifacts 塑形而非失败,见 01-A4)。

### 残留风险
- 两套实现长期漂移(尤其 output gate 规则);需一份共享 spec 作为对齐基线(本 deepreq 即可充当)。

## D-ID-1 · 跨空间信任清单维护 + 吊销传播

### 现状
跨空间互认靠"本空间信任的其他空间 CA 集合"(信任清单,design D11);`space-interconnect` 已规格化、实现后置。

### 选项
| 维度 | 方案 |
|---|---|
| 清单维护 | **A. operator 手工维护的静态信任清单(推荐第一版)**:每个被信任空间一条(spaceId + CA 公钥/指纹 + 状态)。<br>B. 自动联邦发现 + 互签:复杂,后置。 |
| 吊销传播 | **A. 拉模式 CRL/状态轮询(推荐)**:校验远端证书时查对方 CA 的吊销状态(在线或定期同步 CRL)。<br>B. 推模式吊销广播:需可靠消息层,后置。 |

### 推荐
- 第一版:静态信任清单(operator 增删)+ 校验时核对吊销状态(拉模式)。对齐 NDI-TR-2025-02 "统一身份登记",但不自建广播总线。
- 信任清单变更进审计 + 上链(撤销一个空间的信任是高敏操作)。

### 落地
- 实体 `TrustedSpace{spaceId, caFingerprint, caPublicKey, status, addedBy, addedAt}`;`FederationService` 校验远端连接器证书时:① 证书由清单内某 CA 签发(已测 9.2);② 该 CA 未吊销该证书(查 CRL)。
- 数据产品跨空间寻址按 URN 路由到 homeSpace 连接器,计算仍在源地本地完成(数据不出源)。

### 残留风险
- 拉模式吊销有时延(CRL 同步间隔);高敏场景缩短同步周期或对关键操作强制在线查询。

## D-VS-1 · 贡献度计量口径:`cohortSize` 代理 vs Shapley/CI

### 选项
| 方案 | 公平性 | 算力成本 | 抗刷 |
|---|---|---|---|
| **A. `cohortSize` 样本量代理(已实现,推荐第一版)** | 中(只反映"量"不反映"质") | O(1),零额外训练 | 强(orchestrator 客观计量,使用方不可声明) |
| B. Shapley value(精确边际贡献) | 高 | O(2^N) 或重训,N 多院时爆炸 | 强 |
| C. GTG-Shapley / 梯度近似 / Contribution Index | 较高 | 梯度估计,免逐模型重训,O(N) 级 | 中(依赖梯度,需防投毒) |

### 推荐: A 第一版,C 为升级路径
- 第一版分账已用 `share_i = contribution_i/Σ contribution_j`(drop-penalized),`contribution` = cohortSize 代理。客观、抗刷、零成本,**适合"先证明闭环"**。
- 当业务对"按质分配"提出诉求(如数据质量差异大),升级到 **CI / GTG-Shapley**(梯度估计,避免精确 Shapley 的指数成本)。FL 通道(第二阶段)天然产出梯度,适合接 CI。

### 落地
- `SettlementLine` 已记 `contributionShare`;增 `contributionMethod ∈ {cohort-size, ci, gtg-shapley}` 字段供审计追溯口径(00-X5/03-B9)。
- 升级时只换计量函数,分账与上链逻辑不变。

### 残留风险
- cohortSize 代理对"小而高质量"数据不公平;升级前在合约/分账说明里明示计量口径,避免 provider 预期错配。
