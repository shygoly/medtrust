医院连接器独立部署准备清单

面向院方 IT / 信息科 / 网络安全 团队。说明一家医院在自有机房、自有网络、接入自有数据的前提下，独立部署 MedTrust 院内连接器（Connector）所需的服务器、网络、软件、数据、密钥与人员准备。

依据 ARCHITECTURE.md §6.4（院内连接器推荐部署拓扑）与 2026-09-19 架构实况快照编写 · 演示地址仅供联调，正式接入以平台方提供的生产地址与镜像为准。

0 · 先理解三条架构前提

院方动手前，先让网络与安全团队接受这三条——大部分"要不要开专线 / 要不要给平台开权限 / 原始数据会不会出去"的顾虑会当场消解：

  • 连接器只主动出站，平台无法主动连进院内。任务下发用长轮询（连接器发起 HTTPS，服务端挂起 ≤25s，有新任务即返回）。院内不需要开放任何入站端口，不需要 VPN、专线或端口映射。
  • 原始数据不出域。去标识、本地库守卫、计算、输出闸门全部在院内连接器里完成；跨出医院边界的只有聚合结果与签名的模型增量（LoRA），且都先算 SM3 哈希、由平台验哈希后入库。单行患者数据永不离院。
  • 信任链走国密。连接器对平台的认证强制 SM2 证书；结果完整性用 SM3；连接器注册后由平台 CA 签发证书。非国密算法不进信任链。
一句话给领导："院内只放一个'只往外打电话、不接外线'的盒子，算完只把汇总数字带出去，身份和防篡改都用国密。"

1 · 服务器配置

连接器与计算后端（agent）可合并部署在一台服务器，也可分开。按接入深度分档：

用途组件最低规格生产建议说明
连接器节点（必备）NestJS Connector4C / 8G / 100GB SSD8C / 16G / 200GB SSD脱敏切片、本地审计库、L1.5–L3 统计与输出闸门。本身很轻。
联邦计算后端（L4/因果场景）Python Agent8C / 16G16C / 32G，真实联邦训练建议 +1×GPU仅参与联邦学习（L4）或 L3 因果重计算时需要。可与连接器同机或独立机。
硬件 TEE 节点（可选）海光 CSV / Intel SGX 机型—按国产化要求选型当前实现是软件级 TEE（同进程、无硬件隔离）。测试与初期接入不强制。
联盟链节点（可选，见 §5）长安链 ChainMaker4C / 8G / 100GB8C / 16G / 200GB仅"存证去中心化"演进时需要。当前架构不需要。
  • 操作系统：主流 Linux（Ubuntu 22.04 / 麒麟 / 统信等），x86_64。容器化运行，对宿主发行版不敏感。
  • 存储：连接器本地审计库与脱敏切片需持久化卷（容器重建不丢）。
  • 最小接入配置：一台 8C / 16G / 200GB SSD 普通 x86 服务器即可跑通"连接器 + 计算后端"完整闭环。

2 · 网络及端口配置

核心原则：只放行一条出站，不开任何入站。

2.1 出站（唯一跨院边界）

项目要求说明
出站 HTTPS必须连接器通过 HTTPS(443) 轮询控制面 API 拉任务、回传聚合结果
出站白名单锁定平台域名/IP + 固定端口仅放行平台控制面域名:443。这是唯一需要开通的网络策略。
带宽≥ 10 Mbps出去的是 KB 级聚合结果，非原始数据，带宽要求极低

2.2 入站

项目要求说明
入站端口一律不开架构为"主动外联"，平台不主动访问院内
VPN / 专线 / 端口映射不需要（联盟链节点场景除外，见 §5.2）

2.3 内部端口（仅院内网络，不对外）

组件端口暴露范围说明
连接器本地管理面5022仅 127.0.0.1查状态/日志；生产加固下不向宿主发布端口，经内网终端访问
连接器 ↔ 计算后端 agent5024 (gRPC)仅本院内网，仅连接器可达每次调用带院内共享凭证 AGENT_SHARED_TOKEN

2.4 网络分区（生产建议）

  • 连接器置于医院 DMZ / 前置机区，与 HIS 核心库、业务内网区网络分隔。
  • 连接器经"本地数据访问接口层（最小权限）"读 HIS/数据集市的只读 + 脱敏视图，不直连底层库。
  • 双向 TLS 1.3 + mTLS + 证书校验（连接器验平台任务签名，平台验连接器证书签名）。
常见瓶颈（务必提前启动）：部分医院信息科完成防火墙出口白名单变更需 1–2 周。请尽早报备"放行 平台域名:443 出站"这一条策略。

软件版本用途是否必备

Docker Composev2+编排连接器及其依赖必备

  • 镜像来源：由平台方提供正式镜像仓库地址（或离线镜像包）；国内环境依赖走 npmmirror 等镜像源，无需公网编译。

4 · 数据接入准备

事项工作量说明
只读脱敏视图1–2 天信息科为连接器开只读账号，暴露待分析数据（患者/诊断/用药/检验）的脱敏视图，连接器不直连底层库。项目提供 Deidentifier 做剥标识 + SM3 假名化。
标准化映射（推荐目标态）3–5 天目标态经 OMOP CDM 视图接入；初期可用 FHIR 或 CSV 直接导入。
数据导入0.5 天脱敏数据写入连接器本地库，项目提供 ingest 命令行。
队列与编码确认沟通确认参与计算的队列定义（病种、随访时间范围）；核对 ICD/ATC 等编码版本与研究方案一致。
  • 原始数据始终留在 HIS：脱敏在院内完成后才入连接器本地库，原始/明文数据不出 HIS。
  • 接入初期可用合成数据联调：项目内置 Synthea 合成病历，可在不动真实数据的前提下先跑通全流程。

5 · 加入区块链节点（存证）

务必分清"现状"与"生产演进"，两者对院方的要求完全不同。

5.1 现状：医院不需要部署链节点 ✅

当前架构中，存证由平台控制面统一处理：长安链 ChainMaker 单节点 + Java Sidecar 部署在平台侧，合约、结果、越限记录的哈希由平台上链。院方无需做任何链相关准备——连接器把聚合结果连同 SM3 哈希回传，上链发生在平台边界内。

5.2 生产演进：医院作为联盟链成员节点（可选）

若要把信任从"平台单方存证"升级为"多方共识存证"，院方需自建一个长安链联盟链节点。请院方网络团队特别注意——链节点是联盟里的对等节点，与"只出站"的连接器根本不同：

维度连接器联盟链节点
网络方向仅主动出站双向 P2P，需与其他成员机构节点互通
入站端口不开须开放 P2P 端口给联盟成员

准备事项（端口仅链节点，院内 + 联盟成员间）：

端口方向说明
8090平台/本机Sidecar 存证 HTTP 契约（/health、/block-number、/attest）
12301本机节点 RPC（Sidecar ↔ 节点）
11301双向，联盟成员间节点 P2P 共识与区块同步——需与其他 org 节点互通
  • 组织身份：为本院申请联盟链组织 CA 证书 + 节点签名密钥（wx-org-<医院>），纳入联盟链成员治理（共识、准入）。
  • 软件约束（实测）：长安链 v2.3.0；合约用 solc 0.8.17 编译（v2.3 EVM 不支持 0.8.20+ 的 PUSH0）；Sidecar 走 JDK 17。
  • 交付方式：节点 + Sidecar 以合并容器镜像交付，由平台方协助初始化证书与配置。
结论：如只做数据分析接入，跳过本节；如要"上链存证也去中心化"，本节是院方唯一需要开放入站端口的场景，须单独走网络安全评审。

6 · 国密与密钥准备

项目准备方说明
连接器 SM2 证书平台 CA 签发连接器在平台注册后签发；院方保管 CONNECTOR_SM2_PRIVATE_KEY、配置指纹 CONNECTOR_CERT_FINGERPRINT
平台 CA 公钥平台提供CONNECTOR_PLATFORM_CA_PUBKEY，验平台下发任务签名（与 Wasm 模块签名共用）
院内共享凭证院方生成AGENT_SHARED_TOKEN（≥32 字节），连接器 ↔ agent 调用鉴权
令牌降级通道生产关闭生产须 CONNECTOR_TOKEN_AUTH_ALLOWED=false（强制证书认证）

7 · 安全加固基线（容器运行）

连接器/agent 容器按以下基线运行（平台提供的加固配置已内置，院方核对即可）：

  • 非 root 运行（连接器 1000:1000，agent 10001:10001）
  • 只读根文件系统（read_only:true），仅 /tmp 与命名卷可写
  • 去除全部 Linux capability（cap_drop:ALL）、禁止提权（no-new-privileges）
  • 资源限额：内存 / CPU / 进程数封顶（连接器 1G/1CPU/256 进程，agent 2G/2CPU/512 进程为参考起点）
  • 不向宿主发布端口：对外仅一个带鉴权的 GET /connector/audit
  • 本地审计：操作日志本地留存（命名卷）+ 关键证据上链，全链路可追溯
  • 管理面仅内网：运维经内网终端查状态/日志，不直接触达原始数据

8 · 人员与接入时序

角色投入职责
IT / 运维工程师1–2 天部署容器、配置出站白名单、核对加固基线、验证 health
信息科0.5–1 天开只读脱敏视图账号、确认 HIS/数据集市视图范围
临床数据分析师2–4 小时确认队列定义、审核脱敏规则、验证结果合理性
网络安全评审出口白名单评审；如上联盟链节点，额外评审入站 P2P

参考时序（真实数据接入，不含合成数据联调）：关键路径通常是网络出口白名单审批（1–2 周），请最先启动。

阶段动作
第 1–2 周网络开通（出站白名单）报备 + 服务器就绪（并行）
第 3 天IT 部署连接器容器 → health 通 → 出站到平台通
第 4–5 天信息科开只读脱敏视图 → 脱敏 → 导入本地库 → catalog 可见
第 6 天国密证书签发（注册连接器 → 平台 CA 签发）
第 7 天端到端联调：建合约 → 医院审批 → 消费方发任务 → 拉取→本地计算→回传→验证

9 · 医院明确不需要做的

项目原因
开放入站端口 / VPN / 专线连接器主动外联，平台不入站（联盟链节点场景除外，见 §5.2）
部署区块链节点当前存证由平台统一处理（除非选择 §5.2 的联盟链演进）
提供原始 / 明文数据数据在院内脱敏后入库，原始数据不出 HIS
采购硬件 TEE（初期）初期可用软件 TEE 模式；但不得对外声称"硬件级机密计算"，须标注 software-isolation
购买公网域名 / TLS 证书连接器不需要公网域名，不接受入站，无需对外证书
数据库集群 / 负载均衡（初期）单连接器节点 + SQLite 即可起步

附 · 接入检查清单

服务器

  • 连接器服务器就绪（≥8C/16G/200GB SSD，Linux x86_64）
  • 持久化卷已规划（本地审计库 + 脱敏切片）
  • （L4/因果场景）计算后端资源就绪，需 GPU 已确认

网络

  • 出站白名单：放行 平台域名:443（已报备信息科）
  • 确认不开任何入站端口
  • 内部端口 5022 仅 127.0.0.1、5024 仅院内可达

软件

  • Docker 24+ / Compose v2+
  • 获取平台正式镜像仓库地址（或离线镜像包）

数据

  • 信息科开只读脱敏视图账号
  • 队列定义与编码版本已与研究方案对齐
  • 导入验证：catalog 数据产品可见

国密 / 密钥

  • 连接器已注册、平台 CA 已签发 SM2 证书
  • CONNECTOR_PLATFORM_CA_PUBKEY 已配置
  • AGENT_SHARED_TOKEN（≥32B）已生成，令牌降级已关

加固

  • 非 root / 只读根 / 去 cap / 资源限额 已核对
  • 本地审计留存 + 管理面仅内网 已确认

（可选）联盟链节点

  • 组织 CA 证书 + 节点密钥已申请
  • P2P(11301) 与联盟成员互通已评审开通
