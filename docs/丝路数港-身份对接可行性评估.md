# 丝路数港 身份对接可行性评估

> 调研日期：2026-08-15。依据：国家数据局与西安市数据局公开信息（信源见文末）。
> **一句话结论：丝路数港不是 OIDC/政务身份源，不宜作为 P2-3「权威身份注册平台」；它是国家数据基础设施的区域功能节点，正对应 P2-8「与区域/行业功能节点对接」。其身份能力是「主体注册 + 身份互认」，而非「个人/组织权威身份断言」。**

## 1. 丝路数港是什么（已核实）

丝路数港是西安市建设的**省级数据产业集聚区 + 城市普惠性可信数据空间**，西部数据流通枢纽。已核实的核心事实：

- **能力全链条**：数据接入、加工、流通、应用；智能合规检测、数据安全防护、链上可信存证、跨区域协同开发；**基础型/标准型/拓展型三类接入连接器**；隐私保护计算平台。
- **已接入国家主干网**：2026-01-07 率先完成「丝路数港」西安节点与国家数据基础设施全域功能节点正式对接；2026-01-20「丝路数港数据流通利用平台」「丝路可信数据空间」双业务节点稳定运行，成为首家接入国家数据流通利用主干网络的城市。
- **接口与场景**：完成 **93 个接口测试 + 6 项业务场景测试**，验证三大场景——数据主体「一点接入、全国通行」、数据产品「一点发布、全域可见」、数据应用「一点部署、跨区通用」。
- **规模**：已同步 **296 个注册主体 + 1805 个数据产品**；遵循《数据基础设施接入指南》与「三统一」规范。

### 1.1 与国家数据基础设施（NDI）生态的关系：全域功能节点 vs 信通院 NDI 开放平台

两者**不是同一个东西**，但同属国家数据基础设施（NDI）生态：

| | 是什么 | 运营/主导 | 定位 |
|---|---|---|---|
| **丝路数港接入对象** | 国家数据基础设施**全域功能节点**（国家数据流通利用主干网） | 国家数据局主导 | 生产业务系统（接入/登记/流通/交易/交付，93 接口、三统一） |
| **ndi.caict.ac.cn** | **数据基础设施开放平台** | 中国信通院（CAICT）主办，指导单位国家数据局 | 生态**公共信息查询/登记公示**（"数据设施查询"） |

信通院在 NDI 生态中的角色是**标准制定方 + 开放平台运营方 + 评测方**：本仓 `DECISIONS.md` D10 对齐的 **NDI-TR-2025 系列**（连接器 NDI-TR-2025-05、互联互通 02/03、目录 06）即其标准；本仓 TC609 整改冲的正是信通院「可信数据空间基础能力专项检验」。

## 2. 它的「身份」能力边界

- **有**：数据空间层面的**主体注册**（注册主体 296 个），依托国家数据基础设施全域功能节点做**跨域主体互认**（「一点接入、全国通行」）。
- **没有**：它**不提供 OIDC / 政务身份源**（公安、电子政务、法人库等对个人/组织的权威实名断言）。公开资料未见任何 OIDC/政务身份源接口，其职责是数据流通基础设施，不是身份认证服务商。

## 3. 与 MedTrust 整改项的映射

| 整改项 | 适配度 | 理由 |
|---|---|---|
| **P2-3** 对接权威身份注册平台（6.1 扩展，OIDC/政务身份源 + 注册联动） | ❌ 不适合 | 丝路数港非身份源，无 OIDC/政务身份断言接口 |
| **P2-8** 与区域/行业功能节点对接（身份互认/目录同步/日志上报） | ✅ 正对 | 它正是国家数据基础设施全域功能节点的西安区域节点 |

> 补充：本空间内的密码学身份仍由自有 **SM2 CA（D-ID-1）+ 静态信任清单 + 拉模式 CRL** 负责。外部节点（如丝路数港）只做「主体注册 + 身份互认」，**不替代本空间 CA**——这与 P0-4 已接线的 `CaService` 签发链路正交、可叠加。

## 4. 若走 P2-8 的对接方式（身份互认）

- **接入规范**：《数据基础设施接入指南》「三统一」，93 接口（需向节点运营方索取具体接口文档）；**标准对齐 NDI-TR-2025 系列**（连接器 05 / 互联互通 02·03 / 目录 06），本仓 `DECISIONS.md` D10 已在册。
- **身份互认**：MedTrust 作为数据空间节点，主体身份经「注册主体」跨空间互认；本空间仍由自有 CA 签发密码学身份（连接器证书），外部节点只做主体注册/互认断言。
- **目录同步 / 日志上报**：按区域节点接口对拍（P2-8 原列项：日志上报 / 目录同步 / 身份互认）。

## 5. 结论与下一步

1. **不要**把丝路数港当 P2-3 的「权威身份注册平台」；对接目标应**改挂到 P2-8**。
2. 若需「个人/组织权威身份断言」，另选 OIDC/政务身份源（如政务统一身份、法人库），走 P2-3 适配器。
3. 若推进 P2-8：先取《数据基础设施接入指南》接口文档，做接口对拍表（对拍 pull/complete/progress 之外的目录同步与身份互认消息语义），再建 openspec change set。
