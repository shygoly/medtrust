| 项 | 内容 |
|---|---|
| 产品名称 | MedTrust · 医疗可信数据空间（Federated Trusted Data Space for Healthcare） |
| 出品方 | 苏州数说信息科技 |
| 一句话定位 | 三闭环驱动的联邦可信数据空间——数据不出域、可用不可见、按贡献分账 |
| 形态 | 原型 / 演示系统（数据为合成/模拟，核心能力在代码中已实现、可对照验证） |

## 1. 背景与目标

### 1.1 问题
医疗数据价值巨大，却困在三道墙里：
- **数据孤岛**：病历、影像、基因散落各家医院，难以联合建模。
- **隐私红线**：原始数据一旦出域，即触碰《数据安全法》《个人信息保护法》合规风险。
- **信任缺失**：数据被谁使用、用途为何，难以追溯与对账。

### 1.2 目标
构建一座**联邦可信数据空间**：原始数据始终留在各参与方本地，只有聚合结果流动；让医疗数据**既能流动，又始终安全可控**，支撑多中心科研、真实世界研究与 AI 模型联邦训练。

### 1.3 核心理念：三闭环 + 合规护栏
三条相互咬合的「流」，统一运行在一座合规护栏之内：
- **编排闭环（技术）**：声明式任务驱动跨域计算——下发 → 回传 → 补偿，形成闭环控制。
- **数据闭环**：原始数据留本地——去标识 → 域守卫 → 可信执行 → 输出门 → 阅后即焚。
- **商业闭环（价值）**：数据产品挂牌 → 合约准入 → 按贡献计量 → 链上存证 → 自动分账。
- **合规护栏**：国密 + 等保贯穿三链，事前资质分级、事中存证授权校验、事后审计追溯与删除权。

## 2. 参与方与角色

| 角色 | 典型主体 | 职责 |
|---|---|---|
| 数据提供方 | 医院 / 科室（华山、瑞金、中山等肾内科） | 本地持有去标识数据，经连接器守卫与输出门放行聚合结果，按贡献获益 |

| 技术提供方 | 隐私计算厂商 | 提供 TEE、密算运行时与编排适配（对接 FATE / MP-SPDZ / SGX 等） |

## 3. 总体架构

```
                 ┌──────────────── 控制面（NestJS）────────────────┐
  产品门户 /      │  身份 CA(SM2) · 数字合约+PEP · 目录(URN) · 联邦   │
  管理平台 /dashboard ─►  SecretFlow 编排器(异构适配/转译/FSM/gRPC/WS) │
  控制台 /space   │  结算(按贡献分账) · 存证(FISCO BCOS)              │
                 └───────────────┬───────────────────────────────┘
                       gRPC 下发 / WS loss 回传
                                 ▼
  ┌────────── 数据面 · 各参与方本地（数据不出域）──────────┐
  │ 连接器: local-store 守卫 · in-TEE 计算 · 输出门 · PEP · 阅后即焚 │
  │ Local Data Agent(Python): 真实多模态 LoRA FedAvg · 输出门      │
  └──────────────────────────────────────────────────────────────┘
```

- **控制面**：`apps/api`（NestJS）。仅见聚合与元数据，永不接触原始行。
- **数据面**：`apps/connector`（连接器，TS）+ `apps/agent`（Python Local Data Agent，真实 torch 多模态 LoRA FedAvg）。
- **统一场景数据**：`packages/demo-scenario`（CKD 肾病场景，供 web 控制台与 API 共用）。

## 5. 核心演示场景：慢性肾病（CKD）进展预测 · 多模态联邦微调

贯穿全系统的统一演示场景（`packages/demo-scenario`）：

- **业务目标**：联邦微调一个 CKD 进展预测模型，预测患者未来 12 个月 eGFR 下降速率与 ESRD（终末期肾病）风险。
- **参与方**：华山 / 瑞金 / 中山医院肾内科（数据提供方）；创新药企（需求方，研发 SGLT2i/CKD 新药）。
- **所需数据（模态）**：
  - 结构化 EHR：eGFR、血肌酐(Scr)、UACR、血压、HbA1c、用药（ACEI/ARB/SGLT2i）时序；
  - 肾活检病理：全切片影像（WSI）；
  - 肾脏超声（DICOM）；
  - 肾内科电子病历文本。
- **基础模型**：Meditron-7B（医疗大模型基座，冻结骨干）。
- **算法**：多模态编码（CNN/Transformer/MLP）→ perceiver 融合 → **LoRA(r=8) 联邦微调** → FedAvg（HEU 加性掩码聚合）+ DP-SGD；**仅回传 LoRA 增量与聚合指标**。
- **数据产品（目录）**：CKD 结构化随访队列、DKD 随访队列、肾活检 WSI、肾脏超声、肾内科文本、肾病用药结局——共 6 项，均**只挂元数据**。
- **结算**：任务完成后按各院样本量×参与轮次自动分账，链上存证对账。

## 6. 安全与合规需求

- **国密**：SM2（CA/签名/加密）、SM3（摘要/存证）、SM4（列级加密）；密钥由 HashiCorp Vault 托管（5 分钟缓存）。
- **数据不出域不变量**：原始行级数据无任何外部读取路径；计算仅在 TEE 密态内存进行；输出门做小单元格抑制 + 行级拦截；合约声明即焚则任务结束销毁中间产物。
- **使用控制**：数字合约 + 连接器 PEP（策略执行点）在每次计算前 fail-closed 判定授权；撤销即时生效。
- **可审计**：操作全程审计日志 + 关键操作哈希上链（FISCO BCOS），形成监管认可的证据链。
- **法规对齐**：《数据安全法》《个人信息保护法》、等保——数据最小化、计算本地化、输出受控、全程可溯。

## 7. 非功能需求

- **性能**：控制台/后台首屏可观测；密算任务实时 loss 经 WebSocket 流式回传。
- **可测试**：连接器、编排器、Agent 均有自动化测试；演示数据确定性可复现，不依赖外部 GPU/真实 SecretFlow 即可跑通。
- **端口约定**：前端 5020、后端 API+WS 5021（5022–5029 备用）。
- **可移植**：SecretFlow/Ray 机密运行时 import-guarded，本机以 PyTorch 真实联邦回退运行。

## 8. 已实现 vs 对接边界（诚实口径）

- ✅ **已实现、有测试**：联邦控制面与 SecretFlow 编排器（异构/转译/FSM/补偿）、Python Agent 真实多模态 LoRA FedAvg、连接器五道锁、SM2 CA / 数字合约 / PEP、目录、按贡献分账、国密算法。
- ⚠️ **对接 / 支持（需外部运行时）**：SecretFlow/Ray 机密运行时、FATE/Flower、MP-SPDZ、Intel SGX/TEE、FISCO BCOS（适配层对接，非内置部署）。
- ⚠️ **演示数据**：Agent 编码器使用合成但结构忠实的张量；真实落地时替换为 MONAI/HF 编码器与真实 DICOM/VCF 感知层即可，FedAvg/输出门/结算不变。

## 10. 名词表

| 术语 | 含义 |
|---|---|
