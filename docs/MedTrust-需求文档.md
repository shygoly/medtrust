## 1. 背景与目标

### 1.1 问题
医疗数据价值巨大，却困在三道墙里：
- **数据孤岛**：病历、影像、基因散落各家医院，难以联合建模。
- **隐私红线**：原始数据一旦出域，即触碰《数据安全法》《个人信息保护法》合规风险。
- **信任缺失**：数据被谁使用、用途为何，难以追溯与对账。

### 1.2 目标
构建一座**联邦可信数据空间**：原始数据始终留在各参与方本地，只有合规的聚合结果流动；让医疗数据**既能流动，又始终安全可控**，支撑多中心科研、真实世界研究（RWS）、药物警戒与 AI 模型联邦训练。

### 1.3 核心理念：三闭环 + 合规护栏
三条相互咬合的「流」，统一运行在一座合规护栏之内：

- **编排闭环（技术）**：声明式计划驱动跨域计算——编译 → 要约 → 本地复核 → 凭证 → 执行 → 回传补偿。技术上由 **MDOP 协议核**承担（§4.4）。
- **数据闭环**：原始数据留本地——去标识 → 本地守卫 → 受控执行 → 出域闸门 → 阅后即焚。
- **商业闭环（价值）**：数据产品挂牌 → 数字合约准入 → 按贡献计量 → 链上存证 → 自动分账。
- **合规护栏**：国密 + 等保贯穿三链，事前资质与合规预审、事中存证与授权校验、事后审计追溯与删除权。

### 1.4 当前阶段
系统已从「单一 CKD 多模态联邦微调演示」扩展为**可编排的多场景平台**：MDOP 协议 v0.3 承接 RWS 分析阶梯（L1.5–L4）、节点间安全聚合、可信空间节点（C2）链路；存证链迁至长安链 ChainMaker；控制台扩展为六个分区（工作台 / 数据与合约 / 研究与任务 / 合规与监查 / 平台 / 能力与准入）。各能力的真实边界集中在 §8，不在正文里拔高。

## 2. 参与方与角色

控制台按角色门控（`apps/web/src/nav.manifest.json` 的 `roles`），共五类：

| 角色 | 典型主体 | 职责 |
|---|---|---|
| 数据提供方 `provider` | 医院 / 科室（示范甲、示范乙等参与医院） | 本地持有去标识数据；经连接器守卫与出域闸门放行聚合结果；按贡献获益 |
| 数据需求方 `consumer` | 科研机构 / 药企 | 通过数字合约申请数据产品，发起任务、获取聚合洞见，为价值付费 |
| 运营方 `operator` | 平台运营 | 治理目录、审计全程、协调跨院任务、合规监督，见全局结算 |
| 合规 `compliance` | 合规官 / 监查员 | 合规预审与裁决、RBQM 站点监查、审计与告警处置 |
| 管理员 `admin` | 平台管理员 | 用户、机构认证、系统状态、基础设施、对外互认配置 |

**技术提供方不是系统内角色**：TEE、密算运行时、联邦聚合服务等由外部厂商提供，系统以「对接 / 支持」表述（见 §8）。原先并列写的 FATE / MP-SPDZ / SGX 需分开看：SecretFlow 与 Flower 是可选对接项，**MP-SPDZ 已定为不采购**（理由见 §6.1 末段）。

```

控制台  └───────────┬──────────────────────────────┬───────────────┘
:5020               │ 长轮询下发（≤25s）/ WS         │ 存证
                    ▼                               ▼
     ┌──────────────────────────┐        ┌──────────────────────┐
     │ 协议核 @medtrust/mdop     │        │ 长安链 ChainMaker     │
     │ 标签格 C0–C3 · 计划编译   │        │ 存证合约 + Java       │
     │ 信封/凭证/回执/锚定       │        │ Sidecar（:8090）      │
     └───────────┬──────────────┘        └──────────────────────┘
                 │ 计划 + 凭证（控制面）；C1/C2/C3 数据面点对点

  ┌──────────── 数据面 · 各参与方本地（数据不出域）──────────────┐
  │ 连接器 apps/connector（TS）: 本地存储守卫 · 复核 · 受控执行  │
  │   出域闸门 · PEP · 阅后即焚 · 本地审计                       │
  │ 计算后端 apps/agent（Python）: 多模态 LoRA FedAvg · 本地推理 │
  │ 可信空间节点（C2，可选）: 硬件证明 + 条件式密钥释放          │
  └──────────────────────────────────────────────────────────────┘
```

- **控制面**：`apps/api`（NestJS，`:5021`）。只见聚合与元数据，永不接触原始行。
- **协议核**：`packages/mdop`（领域中立，零医疗词）。平台编译器与连接器复核**共用同一份实现**，连接器用本地合约库、白名单、算子清单重算，不采信平台的编译结果。
- **数据面**：`apps/connector`（连接器）+ `apps/agent`（Python 计算后端）。控制面不再直连 agent，只经连接器中转。
- **辅助服务**：`apps/chat-agent`（`:5032` 对话式任务配置）、`apps/connector-ml`（ML 侧）、`apps/web`（Next.js 控制台）。
- **空间与能力包**：`packages/space-kernel` / `space-kernel-spi` 提供空间（space）与能力包（pack）的正交装配，控制台按空间 `enabledPacks` 过滤导航。
- **统一场景数据**：`packages/demo-scenario`（CKD 多模态、AMR 药敏、去重队列、疫苗效果 TND 等种子，供 web 与 API 共用）。

### 4.4 编排与执行

**MDOP 作业链（主路径）**：提交 → 编译（标签 C0–C3 校验、算子白名单、`plan_hash`）→ 要约 → 连接器本地复核（七项，只用本地输入）→ 凭证 → 执行 → C3 出域 → 合并 → 销毁 → 锚定。协议规格见 [`MDOP v0.3`](./医疗数据跨节点算子编排协议规范（MDOP）v0.3.md)，流程见 `FLOWS.md` FLOW-MDOP-01。

**RWS 分析阶梯**（`apps/api/src/runtime/rws-analytics-ladder`、`FLOWS.md` §RWS）：

| 层 | 内容 | 现状 |
|---|---|---|
| L0 | 算法验证（识别算法准确性，混淆矩阵） | 已实现，`attestationLevel` 如实标 `software` |
| L1.5 | 失衡信号检测（PRR/ROR）多中心合并 | 已迁 MDOP（模板 `rws.l15.disproportionality`） |
| L2 | 比较效果 Meta 分析 | 已实现 |
| L3 | 因果推断（PSM/IPTW + Cox/KM） | 已实现，院内重计算 |
| L4 | 联邦预测 | 已实现，`/api/v1/flower` 通道可选（`:5023`） |

**联邦训练**：`apps/agent` 真实多模态 LoRA FedAvg；节点间安全聚合走 MDOP `secure_aggregate`（平台只路由密文；其安全边界见 §6.1 末段）。**SecretFlow** 为可选对接运行时（import-guarded，本机以 PyTorch 真实联邦回退）。

**下发通道**：控制面 → 连接器 `长轮询`（服务端上限 25s，`CONNECTOR_LONG_POLL_WAIT_MS`）；训练 loss 与任务状态经 `WS` 回流。

### 4.5 数据与合约
- **数据产品目录**：只挂元数据（字段、记录数、分级、计费、驻留位置），URN 全局标识。种子含 CKD 多模态 6 项、AMR 药敏、去重队列、疫苗效果 TND 等场景。
- **数字合约**：条款含用途、参与方、`outputPolicy`（`allowedArtifacts` + `minCell` + 预留 `dp`）、参与方签署与平台副署；撤销即时生效（FLOW-DC-01）。
- **使用控制**：连接器 PEP 在每次计算前 fail-closed 判定授权。
- **结算**：按样本量 × 参与轮次计量，按贡献占比分账，任务与结果哈希上链对账（FLOW-SETTLE-01）。
- **院内数据源接入**：OMOP CDM 双权限域（CDM 视图只读 + `results` schema），接入校验 → 覆盖元数据上报 → 目录登记（D-CN-6 / D-CN-7、FLOW-DS-01）。

### 4.6 合规与监查
- **合规预审**：L2 规则引擎按维度打分并裁决，三保障级 `basic < federated < enhanced`（D-CMP-1）；合约申请前须先有裁决（`/space/atlas/pre-review`）。
- **合规总览与告警**：规则命中聚合视图，指向审计告警。
- **RBQM**：站点级 KRI 聚合观测 → QTL 越限 → 存证；连接器只回传聚合三元组，无行级数据（FLOW-RBQM-01）。
- **审计与存证**：全动作审计日志；关键操作哈希上链，配合 SM2 背书可由第三方独立核验（CTL-23）。

### 4.7 平台治理
用户与角色、机构认证审核（注册 → 双认证 → 领证，FLOW-ID-01）、系统状态、基础设施视图、丝路数港互认配置（`runtime/silk-road` + `/space/admin/interop`；真实对端联调按项目进度，不列入已完成项）。

### 4.8 AI 助手
- **对话式任务配置**（`apps/chat-agent`，`:5032`）：自然语言 → Card Message → MDOP 作业草稿；无外部模型密钥时走确定性回退，问题文本不出平台。
- **控制台助手**（`/space/assistant`）：研究设计、合约、码表、运维、合规证据、结果解读入口。
- **结果解读**：只引用已发布数字（`result-interpreter` 的 C3 facts + 数字回查）；未配置推理服务时返回 503，不影响结果页。

## 6. 安全与合规需求

- **数据不出域不变量**：原始行级数据无任何外部读取路径；只有过闸的聚合结果可出域。**执行隔离等级如实标注**：当前院内连接器 `attestationLevel` 恒为 `software`（D-RWS-4 / CTL-09），硬件飞地（C2）未接真实证明链前不得声明机密计算（§6.1、§8）。
- **出域闸门**：合约绑定 `outputPolicy`——`minCell`（缺省 5，可调区间 5–20）逐格抑制、罕见病列另按 `minCellRare`（缺省 10）置零并标 `rareSuppressed`、行级制品一律拦截；C2 节点另有二次抑制与查询预算（D-TEE-2）。**差分隐私预留但未启用**：`outputPolicy.dp` 恒 `mode=none`，无 ε 加噪与预算账本（P-CTL-3）。
- **使用控制**：数字合约 + 连接器 PEP 在每次计算前 fail-closed 判定授权；撤销即时生效。
- **国密**：SM2（CA/签名/加密）、SM3（摘要/存证）、SM4（列级加密）。**平台三钥分离**：CA 根钥 / 平台节点密钥 / 注册中心密钥用途隔离，私钥以 SM4 密文落库，KEK 来自 `PLATFORM_KEK`，生产缺 KEK 拒绝启动（CTL-26）。参与方密钥**自持**，注册只提交公钥。
- **密钥托管**：Vault 与 KMS 的现状对照见 §6.1；任何材料不得表述为「密钥已全部托管」。
- **可审计**：全动作审计日志 + 关键操作哈希上链（长安链 ChainMaker，D-RWS-3），形成可独立核验的证据链。
- **法规对齐**：《数据安全法》《个人信息保护法》、等保——数据最小化、计算本地化、输出受控、全程可溯。

### 6.1 密钥管理现状对照（2026-11-05）

系统里有两个都被叫「密钥管理」的机制，**不可互换**：

- **Vault**（平台凭据库，`apps/api/src/security/vault/`）回答「密钥存在哪、谁能取、取了记不记」——token → policy → 路径 ACL + 租期 + 审计；解密发生在**应用进程**，运营方是平台自己。
- **KMS**（可信空间节点的条件式密钥释放，`packages/mdop/src/attestation/`）回答「**此刻、这台机器、这段代码**上该不该给」——判据是硬件远程证明 + 度量白名单 + TCB + 执行凭证 + 合约状态 + 密钥归属（`release.ts#evaluateKeyRelease`），密钥用证明报告里的一次性公钥封装，只存在于**飞地实例内存**，由数据持有方自建或与运营方共管（D-TEE-1：平台永不接触数据密钥）。

| 能力 | 状态 | 证据 |
|---|---|---|
| Vault KV / Transit / DB 动态凭据 | 已实现 | `apps/api/src/security/vault/vault.service.ts` |
| Vault 生产化（持久存储、auto-unseal、非 root token、按路径 policy） | **未实现**：两处配置都是 `server -dev`（内存存储 + 固定 root token） | `docker-compose.yml`、`fly-services/vault/fly.medtrust-vault.toml` |
| 业务列加密真正走 Vault（`@EncryptedColumn`） | **未接入**：`setEncryptionServices()` 只在 spec 里被调用，实体列仍是注释 | `apps/api/src/shared/transformers/encryption.transformer.ts`、`packages/database/src/entities/patient.entity.example.ts` |
| Sidecar 链证书私钥入 Vault（D-RWS-3-a） | **未完成**：仍从 `CHAIN_CONFIG_DIR` 读文件 | `fly-services/chain-sdk/src/main/java/medtrust/Sidecar.java` |
| 连接器 SM2 发证 / 链证书由 Vault 签发 | **未实现**：`VaultService` 只有 KV / Transit / DB 三类，无 PKI 引擎调用 | 同上 |

**如实边界**：最小集里 Vault 的状态是「生产环境必须部署（`NODE_ENV=production` 且健康检查失败时 API 拒绝启动）、但业务主路径还没真正依赖它」。任何材料不得表述为「密钥已全部托管」。**MPC 网关不采购**，跨院聚合走 MDOP `secure_aggregate`；其当前性质是「对平台保密、对参与方不保密」，见 `docs/deploy/部署硬件需求-v2.md` §4.6.2。

## 8. 已实现 vs 边界（诚实口径）

### 8.1 ✅ 已实现、有测试
- **MDOP 协议核与作业链**：标签格 C0–C3、计划编译与 `plan_hash`、信封四步校验、凭证、本地七项复核、出节点 C3 守卫、回执与链锚定；节点间 `secure_aggregate`（平台只路由密文）。
- **RWS 分析阶梯 L1.5–L4** 与 L0 算法验证。
- **存证**：长安链 ChainMaker v2.3.0 + Java Sidecar（`/attest`、`/block-number`、`/health`）+ `MedicalDataAttestation` 合约 + 按贡献方的 SM2 背书与独立核验脚本。
- **数字合约 / PEP / 合规预审引擎 / 目录 / OMOP-CDM 接入校验 / 结算分账 / RBQM / 审计**。
- **连接器守卫**：本地存储守卫、受控执行（`SoftwareSealedCompute`，生产模式有独立闸门校验）、出域闸门（`minCell` / `minCellRare`）、PEP、阅后即焚、本地审计。
- **平台三钥分离**与密钥用途隔离验签；国密 SM2/SM3/SM4。
- **AI 助手**：对话式任务配置（Card Message → MDOP 作业）、控制台助手、结果解读（C3 facts + 数字回查）。

### 8.2 ⚠️ 已实现但形态受限（不得按目标态表述）
- **执行隔离为软件级**：院内连接器 `attestationLevel` 恒 `software`；生产模式下 `SoftwareSealedCompute` 构造即抛错（装配失败、进程不启动），不得用软件实现冒充 C2（D9 / CTL-09 / `check-software-sealed-compute-prod.mjs`）。
- **C2 可信空间节点**：协议语义、节点运行时与可部署组件已落地，判定开关已翻转；**硬件证明链与真实 KMS 未落地，C2 在任何真实部署里仍为零**（P-CTL-8）。
- **存证链现网为 solo 单节点**（平台运营）：多节点共识与医院背书节点未落地（D-RWS-3-b / P-CTL-4）。
- **Flower 通道、SecretFlow 运行时**：可选对接，未配置时健康检查显示未配置。
- **结果解读 LLM**：未配置推理服务时返回 503（确定性回退），不影响结果页。
- **跨空间互认**：信任清单与目录联邦、丝路数港互认接口与页面已实现；真实对端联调按项目进度。
