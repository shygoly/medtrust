# 连接器部署安装步骤（内部运维）

> **内部文档**：MedTrust 团队在医院节点**独立部署**连接器的实操步骤。院方视角的准备清单见《[医院连接器独立部署准备](./医院连接器独立部署准备.md)》。
> **一条贯穿全程的前提**：连接器**无入站端口**、管理面**仅 127.0.0.1**——所以运维**必须经跳板机（bastion）接入，VPN 可选**。这不是选配，是这套"仅出站"架构的必然结果。
> 依据：ARCHITECTURE.md §6.4、`deploy/ali29/compose.hardening.yaml`、`apps/connector/.env.example`。

---

## 0 · 总览

一个医院节点 = **连接器（NestJS）** +（按需）**计算后端 agent（Python）**，两个容器，跑在院内 DMZ 的一台服务器上。部署顺序：

```
跳板机就绪 → 拉/载镜像 → 配 .env → 一次性前置(卷/权限) → compose up(加固) → 平台注册+签证书 → 导数据 → 健康核验 → 交付
```

运维全程经**跳板机**操作；连接器自己只对平台**主动出站**，对院内只开一个带鉴权的 `GET /connector/audit`。

---

## 1 · 服务器与网络前提检查（部署前逐项确认）

- [ ] 服务器：≥8C/16G/200GB SSD，Linux x86_64，Docker 24+ / Compose v2+
- [ ] 出站白名单已放行：`<平台域名>:443`（在服务器上 `curl -sS -o /dev/null -w '%{http_code}\n' https://<平台域名>/api/v1/health` 应连通）
- [ ] **不开任何入站端口**（联盟链节点场景除外）
- [ ] 跳板机可达连接器主机内网（见 §2）
- [ ] 镜像来源确认：私有 registry 地址，或离线镜像 tar
- [ ] 平台侧已为该院分配 `participantId`（如 `p-huashan`）并可签发 CA 证书

---

## 2 · 跳板机（bastion）搭建 ★重点

### 2.1 为什么必须有

连接器管理面绑定 `127.0.0.1:5022`、且容器**不向宿主发布端口**，院内 LAN 也直连不到。运维要部署/升级/看日志/跑导入，只能**先进到能触达连接器宿主的院内网络里**。跳板机就是这个**受控入口**：它在院内 DMZ，运维 SSH 到它，再由它内网直达连接器宿主。

> 这条 SSH 通道是**运维面的受控入站**，与**数据面（仅出站）严格分离**——数据面永不接受入站，跳板机只做运维，且触达不到原始数据。

### 2.2 两种拓扑

| 拓扑 | 说明 | 适用 |
|------|------|------|
| **A · 独立跳板机** | 跳板机与连接器分两台；运维 → 跳板机 → （内网 SSH）→ 连接器宿主 | 院方有既有堡垒机规范，推荐 |
| **B · 合并** | 连接器宿主自身承担跳板角色（对外仅开 SSH，管理面仍 127.0.0.1） | 单节点小规模，最省 |

### 2.3 跳板机加固（两种拓扑通用）

- 仅**密钥认证**（`PasswordAuthentication no`）+ **MFA**（`pam_google_authenticator` / 硬件密钥）
- SSH 非标准端口 + `AllowUsers ops` + `fail2ban`
- 源 IP 白名单：只放行 MedTrust 运维出口 IP（或 VPN 网段）
- 跳板机**不存业务数据、不装数据库**；只做跳转与运维工具

### 2.4 VPN 可选（二选一）

| 路径 | 做法 | 取舍 |
|------|------|------|
| **走 VPN（推荐）** | 院方给 MedTrust 运维一个 client-to-site 或 site-to-site VPN；运维连 VPN 后 SSH 到跳板机**内网 IP**。跳板机**不暴露公网** | 最安全；多数三甲要求如此 |
| **不走 VPN** | 跳板机开一个**加固公网 SSH 口**：仅密钥+MFA、源 IP 白名单、非标端口、fail2ban | 无 VPN 时的兜底，务必把白名单和 MFA 做严 |

### 2.5 运维接入 SSH 配置（ProxyJump）

MedTrust 运维本机 `~/.ssh/config`（拓扑 A）：

```ssh-config
Host hosp-a-bastion
  HostName <跳板机 公网IP 或 VPN内网IP>
  Port    2222
  User    ops
  IdentityFile ~/.ssh/medtrust_ops_ed25519

Host hosp-a-connector
  HostName 10.20.0.11          # 连接器宿主内网IP
  User     ops
  ProxyJump hosp-a-bastion     # 经跳板机跳转，不直连
```

之后 `ssh hosp-a-connector` 即落到连接器宿主，`docker`、`curl https://127.0.0.1:5022/...` 都在这里跑。

## 3 · 部署连接器

### 3.1 获取镜像

```bash
# 在线：从私有 registry 拉
docker pull <registry>/medtrust-connector:<tag>
docker pull <registry>/medtrust-agent:<tag>        # 仅 L3/L4 场景

# 离线：载入镜像包
docker load -i medtrust-connector_<tag>.tar
```

> 镜像由 `fly-services/connector/Dockerfile.connector`（连接器）与 `Dockerfile.agent`（agent）构建；`better-sqlite3` 走 npmmirror 预编译二进制，院内无需公网编译。

### 3.2 配置 `.env`（依据 `apps/connector/.env.example`）

```dotenv
CONNECTOR_PORT=5022
CONNECTOR_PARTICIPANT_ID=p-huashan
CONTROL_PLANE_URL=https://<平台域名>/api/v1

# 生产强制证书认证——令牌降级通道必须关
CONNECTOR_TOKEN_AUTH_ALLOWED=false
CONNECTOR_CERT_FINGERPRINT=SM2:<平台签发后回填>
CONNECTOR_SM2_PRIVATE_KEY=<院方生成/保管，勿入库>
CONNECTOR_PLATFORM_CA_PUBKEY=<平台提供>

# 院内计算后端（仅本院内网，仅连接器可达）
AGENT_GRPC_URL=127.0.0.1:5024
AGENT_SHARED_TOKEN=<≥32字节，院方生成>

CONNECTOR_LONG_POLL_WAIT_MS=25000
CONNECTOR_TASK_CONCURRENCY=4
CONNECTOR_VERSION=1.0.0
```

> ⚠ `CONNECTOR_SM2_PRIVATE_KEY` / `AGENT_SHARED_TOKEN` 是密钥材料，走密钥管理（或 Vault），**不进 git、不进镜像**。

### 3.3 参考 compose（单院节点，已含加固）

`compose.hospital.yaml`（叠加加固基线，语义同 `deploy/ali29/compose.hardening.yaml`）：

```yaml
x-hardened: &hardened
  read_only: true
  cap_drop: [ALL]
  security_opt: ["no-new-privileges:true"]

services:
  connector:
    <<: *hardened
    image: <registry>/medtrust-connector:<tag>
    env_file: .env
    user: "1000:1000"
    tmpfs: ["/tmp:size=64m,mode=1777"]
    mem_limit: 1g
    cpus: 1.0
    pids_limit: 256
    volumes:
      - connector-local:/repo/apps/connector/data   # 本地审计库，命名卷持久化
    networks: [hosp]
    # 不发布任何端口：管理面仅容器内 127.0.0.1

  agent:                       # 仅 L3/L4 场景
    <<: *hardened
    image: <registry>/medtrust-agent:<tag>
    user: "10001:10001"
    environment: { PYTHONDONTWRITEBYTECODE: "1", HOME: /tmp }
    tmpfs: ["/tmp:size=256m,mode=1777"]
    mem_limit: 2g
    cpus: 2.0
    pids_limit: 512
    networks: [hosp]           # 仅本院内网，仅连接器可达

networks:
  hosp: { internal: true }     # 无外网出口；连接器出站另由宿主/防火墙白名单放行
volumes:
  connector-local:
```

> `internal: true` 让容器网络无外网；连接器对平台的出站由**宿主网络 + 防火墙白名单**承载（宿主能出 `<平台域名>:443` 即可）。若用容器直接出站，则把 connector 放到一个非 internal 网络并只白名单平台域名。

### 3.4 一次性前置（卷 + 权限）

```bash
# 建网络与卷（不启动）
docker compose -f compose.hospital.yaml create --no-recreate connector agent
# 命名卷 chown 到容器内用户（只读根下仍可写审计库）
docker run --rm --user 0 --entrypoint chown \
  -v $(docker volume ls -q -f name=connector-local):/d \
  <registry>/medtrust-connector:<tag> 1000:1000 /d
```

### 3.5 启动

```bash
docker compose -f compose.hospital.yaml up -d
docker compose -f compose.hospital.yaml ps
docker compose -f compose.hospital.yaml logs -f connector   # 看到出站轮询即正常
```

## 4 · 平台注册与国密证书签发

1. **平台侧**：在 `participant-identity` 为该院注册连接器（机构认证 → 连接器登记），平台 CA 签发 SM2 证书，得到**证书指纹**与**平台 CA 公钥**。
2. **连接器侧**：把指纹回填 `CONNECTOR_CERT_FINGERPRINT`、平台 CA 公钥填 `CONNECTOR_PLATFORM_CA_PUBKEY`、SM2 私钥填 `CONNECTOR_SM2_PRIVATE_KEY`，重启连接器。
3. 确认 `CONNECTOR_TOKEN_AUTH_ALLOWED=false`（强制证书认证，令牌通道关闭）。

> 连接器请求带 CA 证书签名、平台下发任务带平台 SM2 签名——双向签名，验签失败即拒（fail-closed）。

## 5 · 数据导入

- **合成数据联调**：`pnpm --filter @medtrust/connector ingest-synthea`（内置华山/瑞金 Synthea 切片，走 `scripts/ingest-synthea.ts`）。
- **真实数据**：信息科开 HIS/数据集市**只读脱敏视图** → 连接器经最小权限接口层读 → `Deidentifier` 剥标识 + SM3 假名化 → 写入连接器本地库。原始数据不出 HIS。
- 导入后确认平台 `catalog` 能看到该院数据产品（只有元数据）。

## 6 · 健康核验（逐项）

```bash
# 1) 宿主能出站到平台
curl -sS -o /dev/null -w '%{http_code}\n' https://<平台域名>/api/v1/health      # 200

# 2) 连接器容器在轮询（日志无 401；若 401 见 §9）
docker compose -f compose.hospital.yaml logs --tail=50 connector | grep -i poll

# 3) 对外唯一接口带鉴权可达（容器内）
docker compose -f compose.hospital.yaml exec connector \
  curl -sk https://127.0.0.1:5022/connector/audit -H 'authorization: <token>' | head
```

- [ ] 出站 200 · [ ] 轮询无 401 · [ ] audit 端点鉴权可达 · [ ] 平台端能看到该连接器心跳
- [ ] 端到端：平台建合约 → 医院审批 → 消费方发 RWS/FL 任务 → 连接器拉取→本地计算→回传→平台验 SM3

## 7 · 运维日常（全部经跳板机）

```bash
ssh hosp-a-connector    # 经 ProxyJump 跳转
docker compose -f compose.hospital.yaml logs -f connector      # 日志
docker compose -f compose.hospital.yaml ps                     # 状态
docker stats --no-stream                                       # 资源
```

管理面（`127.0.0.1:5022`）只在宿主本机访问，不经院内 LAN、不公网暴露。

## 8 · 升级 / 回滚

```bash
# 升级：拉新镜像 → 改 tag → 重建（数据卷不动）
docker pull <registry>/medtrust-connector:<newtag>
docker compose -f compose.hospital.yaml up -d --no-deps --force-recreate connector

# 回滚：改回旧 tag 重建即可；connector-local 卷持久，审计不丢
```

> 平台侧升级注意（不在院内）：控制面 CA 根密钥须挂卷持久化，重建 API 必须带 CA 持久化 overlay，否则已签发证书全线失效——见 `compose.hardening.yaml` 顶部注释。

## 9 · 排障速查（真实坑）

| 症状 | 根因 | 处理 |
|------|------|------|
| 长轮询领任务恒 **401** | 无体 GET 的请求体 SM3 未归零，或证书未签发/指纹不匹配 | 确认 `CONNECTOR_CERT_FINGERPRINT`/私钥/平台 CA 公钥三者匹配；连接器镜像含无体 GM3 归零修复（见 commit `1b72a56`） |
| 连接器**启动即崩** | 早期 `ConnectorTaskDedupe` provider 注册问题 | 用含修复的镜像（commit `6a84a28`） |
| 登录/注册等 POST 读不到 body | 全局 body parser 被跳过 | 平台侧显式注册全局 parser（commit `5e9855f`），非院内问题 |
| `better-sqlite3` 装不上 | 源码编译走公网失败 | 镜像已走 npmmirror 预编译二进制（commit `9ef6d6f`），勿在院内源码编译 |
| 平台重建后连接器全 401 | 控制面 CA 根密钥未持久化被重生 | 平台侧带 CA 持久化 overlay 重建（§8 注释） |
| 出站不通 | 防火墙白名单未生效 | 核 `<平台域名>:443` 白名单；DNS 能解析 |
