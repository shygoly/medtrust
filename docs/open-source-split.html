开源可信空间内核，医疗知识留在商业包

底层最适合开源的，是一套与行业无关的可信数据空间内核：院内连接器、控制面治理（身份、目录、合约、使用控制、编排、存证、结算）、国密信任链和零能力 Wasm 沙箱。它单独就能跑通 TC609 基础级的完整闭环，所有安全机制公开可审计。RWS 研究方法学、医疗数据接入与合规规则、联邦 AI、RBQM 和定价是核心商业模块；商密认证、硬件 TEE、高可用与区域节点对接归企业版。

五个决定

开源进开源内核 拆分通用与领域混写，需先拆 医疗包医疗领域商业模块 企业版通用但收费 / 项目交付 删除遗留或不发布
开什么
可信数据空间内核：连接器、控制面治理、国密信任链、Wasm 沙箱与算法准入闸、存证审计、控制台通用页，以及治理契约和它的校验器。按模块映射，可覆盖 TC609-6-2025-16 整理版列出的基础级全部 38 项（安全计算为软件级；能否通过以检验实测为准）。
不开什么
医疗领域包：RWS L0–L4 与 EVIDENCE 效度契约、FHIR / OMOP / HIS 接入、医疗脱敏与合规规则、联邦 LoRA 与因果内核、RBQM、任务设计助手、定价。企业版：商密认证密码模块、海光 CSV、高可用与多节点存证、区域节点适配。
许可证
Apache-2.0，保留 MedTrust 商标。开源版用中性名（工作名 tds-core，发布前查重与商标检索）。
仓库

顺序
清仓并修残留 → 抽通用任务内核 → 连接器去医疗化 → 补齐通用件 → 拆契约 → 定插件边界后发布。

切分原则

判断一个模块归哪边，只问三件事：它是不是安全机制，它含不含医疗知识，它要不要厂商或项目投入。

安全机制全部开源

连接器要装进医院 DMZ，院方安全团队能逐行审计是准入前提。闸门、PEP、验签、沙箱的安全性来自设计本身，不靠代码保密；公开之后，「数据不出域」可以被第三方验证，而不只是你的承诺。

领域知识闭源

RWS 方法学、医疗数据语义、医疗合规规则、临床 AI 是做项目积累出来的，拿到内核也补不齐。开源内核里不出现患者、诊断、用药这类概念，只有「参与方、数据产品、合约、任务、聚合结果」。

认证、硬件与交付收费

商密产品认证、硬件可信执行、高可用、对接区域功能节点，都要厂商合作或项目投入，天然是企业版。它们是同一套接口的更强实现，不改变开源内核的行为。

护城河不在代码里

此前的战略结论（2026-07-12）：核心是「有数据不敢用」与「要数据买不到」之间的可信枢纽位置，加上每次接入沉淀下来的网络。开源把连接器变成标准件，加速的正是这张网。你运营的空间里，CA 根密钥和算法模块签名权仍在你手上：第三方算法进网必须过平台签名的五道准入闸（CTL-24）。

架构 × 开源边界

按 docs/architecture-overview.html（2026-09-19 实况）重绘，按本页归属着色。结构不变：平台只碰元数据，计算在院内连接器里完成，跨越医院边界的只有连接器主动发起的出站连接。

常规场景跑通

用一个中性示例（两家数据提供方 + 一家使用方做联合统计）走完七步，每一步只用开源内核的模块。这也是开源版 docker compose up 之后应该能直接演示的闭环。

  1. 入网

    机构注册、认证审核、平台签发 SM2 证书；连接器注册，此后每个请求都带证书签名。

    organization · participant-identity · auth · control-plane-client
    6.16.27.1
  2. 上架

    连接器声明本地资源，封装数据产品并配置分级标签与出域策略；平台目录只登记元数据。

    data-product-local-source · catalog · output-policy
    6.37.38.2
  3. 签约

    使用方申请并确认知悉规则，提供方签发；合约 SM3 哈希上链备案。撤销即中止进行中的任务。

    digital-contract · attestation · l2-compliance
    6.47.48.1
  4. 受控使用

    使用方提交任务，平台签名；连接器长轮询领取、验签，PEP 按合约校验，在零能力 Wasm 沙箱里计算，结果过输出闸门。

    connector-tasks · task-puller · connector-task-signature · policy-enforcement · sandbox · output-gate
    6.67.68.2
  5. 交付

    聚合结果带 SM3 与连接器 SM2 背书回传；平台验真后合并（求和，或 CKKS 盲聚合），交付给使用方。

    result-endorsement · he-aggregator · endorsement-verification · 通用任务内核
    7.5
  6. 存证审计

    平台与连接器两侧写链式哈希日志，关键证据上链；可按合约追溯全链路并导出证据包。

    audit · connector-audit · chain.adapter · evidence-package
    6.108.3
  7. 计量

    按贡献（先用样本量代理）写结算台账并上链。

    settlement

运营服务 · 不是代码

空间运营与连接器驻场部署：DMZ / 前置机部署、院内网络与安全评审配合。算法市场守门：第三方模块进你运营的网络必须过五道闸并由平台签名，签名权就是生态入口。网络本身：每接入一家机构沉淀一个永久节点，这部分别人复制不了。

拆分步骤

按依赖顺序排列，前一步不完成后一步会返工。

  1. 清仓

    新建仓库；删 flower / privacy / fhir / compute-task 旧集中式、/dashboard、lite / mp-spdz / fate 等历史部署（快照统计约 1.55 万行，其中 web3 旧链路约 0.8k 行已于 2026-09-21 先行删除）；gitleaks 扫全量。

  2. 抽通用任务内核

    从 rws-orchestrator 抽出任务与派发记录生命周期、连接器拉取协议、持久化与背书验真；cp_rws_task / assignment 改为 cp_task / cp_assignment + workloadKind + spec JSON。RWS 与 FL 改为注册进来的 workload 插件：本地执行器 + 合并器 + 规格 schema + 闸门预设。

  3. 连接器去医疗化

    InternalRecord（conditions / medications / adverseEvents）换成按 schema 声明的通用表格记录；deidentifier 改为按列分级标签驱动（丢弃 / SM3 加盐假名 / 泛化），盐只能来自部署配置；加载器保留框架与路径守卫，FHIR、Synthea、临床文本、OMOP 移入医疗包。

  4. 补齐通用件

    CSV 与 PostgreSQL 只读视图适配（沿用现有凭据边界设计）；分组计数、求和、均值、列联表四个 Wasm 基础算子；中性示例数据；docker compose 一键演示（控制面 + 两个连接器，长安链可选）。

  5. 拆契约

    TRUST / FLOWS / DOMAIN / DECISIONS 拆出通用版，check-meta-docs.mjs 随开源发布；EVIDENCE 与 RWS / RBQM 的流程、控制点留在医疗包仓库，用同一个校验器增量校验。

  6. 定插件边界后发布

    医疗包作为独立私有 npm / PyPI 包，只依赖开源内核的公开接口（workload 注册、数据适配器、合规规则包、能力种子、计算后端协议）；开源内核不得反向依赖医疗包，CI 用依赖检查守住这条线。

    web3 已删除，剩全量扫描。唯一的 LGPL-3.0 依赖 web3 已于 2026-09-21 随未接线的旧链路删除。其余直接依赖（NestJS、Next.js、TypeORM、sm-crypto、node-seal 等）均为宽松许可，发布前再跑一次全量许可证扫描。
