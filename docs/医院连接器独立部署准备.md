# MedTrust 医疗可信数据空间 — 医院连接器独立部署准备清单

> 面向院方 **IT / 信息科 / 网络安全** 团队。说明一家医院在**自有机房、自有网络、接入自有数据**的前提下，
> 独立部署 MedTrust 院内连接器（Connector）所需的服务器、网络、软件、数据、密钥与人员准备。
>
> **与《[医院配合测试清单](./医院配合测试清单.md)》的区别**：那份面向 POC 联调（合成数据、软件 TEE、SQLite 零运维、单机即可）；
> 本文面向**生产级独立部署**（接入真实脱敏数据、DMZ 分区、国密证书、加固基线、可选硬件 TEE 与联盟链节点）。
> 数据流转细节见《[医院端数据流转流程 v2](./医院端数据流转流程-v2.md)》；架构权威以 [ARCHITECTURE.md](../ARCHITECTURE.md) §6.4 为准，全景图见 [architecture-overview.html](./architecture-overview.html)。

---

## 0. 先理解三条架构前提（它们决定了准备工作的边界）

院方在动手前，先让网络与安全团队接受这三条——大部分"要不要开专线 / 要不要给平台开权限 / 原始数据会不会出去"的顾虑会当场消解：

1. **连接器只主动出站，平台无法主动连进院内。** 任务下发用长轮询（连接器发起 HTTPS 请求，服务端挂起 ≤25s，有新任务即返回）。**院内不需要开放任何入站端口**，不需要 VPN、专线或端口映射。
2. **原始数据不出域。** 去标识、本地库守卫、计算、输出闸门全部在**院内连接器**里完成；跨出医院边界的只有**聚合结果**与**签名的模型增量（LoRA）**，且都先算 SM3 哈希、由平台验哈希后入库。单行患者数据永不离院。
3. **信任链走国密。** 连接器对平台的认证强制 SM2 证书；结果完整性用 SM3；连接器注册后由平台 CA 签发证书。非国密算法不进信任链。

> 一句话给领导：**"院内只放一个'只往外打电话、不接外线'的盒子，算完只把汇总数字带出去，身份和防篡改都用国密。"**

## 1. 服务器配置

连接器与计算后端（agent）可**合并部署在一台服务器**，也可分开。按接入深度分档：

| 用途 | 组件 | 最低规格 | 生产建议 | 说明 |
|------|------|----------|----------|------|
| **连接器节点**（必备） | NestJS Connector | 4C / 8G / 100GB SSD | 8C / 16G / 200GB SSD | 承载脱敏切片、本地审计库、L1.5–L3 统计计算与输出闸门。本身很轻。 |
| **联邦计算后端**（L4/因果场景需要） | Python Agent（SecretFlow / LoRA / Cox·PSM） | 8C / 16G | 16C / 32G，真实联邦训练建议加 **1×GPU** | 仅当参与联邦学习（L4）或 L3 因果重计算时需要。可与连接器同机或独立机。 |
| **硬件 TEE 节点**（可选，生产增强） | 海光 CSV / Intel SGX 机型 | — | 按国产化要求选型 | 当前实现是**软件级 TEE（同进程、无硬件隔离）**；如需对外声称硬件级机密计算，须上此类机型。**测试与初期接入不强制。** |
| **联盟链节点**（可选，见 §5） | 长安链 ChainMaker 节点 + Sidecar | 4C / 8G / 100GB | 8C / 16G / 200GB | 仅当从"平台中心化存证"演进到"多方联盟链共识"时需要。**当前架构不需要。** |

- **操作系统**：主流 Linux（Ubuntu 22.04 / 麒麟 / 统信等），x86_64。容器化运行，对宿主发行版不敏感。
- **存储**：连接器本地审计库与脱敏切片需**持久化卷**（容器重建不丢）；预留数据脱敏中间产物空间。
- **最小接入配置**：一台 **8C / 16G / 200GB SSD** 的普通 x86 服务器即可跑通"连接器 + 计算后端"完整闭环。

## 2. 网络及端口配置

**核心原则：只放行一条出站，不开任何入站。**

### 2.1 出站（唯一跨院边界）

| 项目 | 要求 | 说明 |
|------|------|------|
| 出站 HTTPS | ✅ 必须 | 连接器通过 HTTPS(443) 轮询控制面 API 拉任务、回传聚合结果 |
| 出站白名单 | ✅ 锁定平台域名 / IP + 固定端口 | 仅放行**平台控制面域名:443**（部署时提供正式生产地址；勿沿用演示地址）。**这是唯一需要开通的网络策略。** |
| DNS | 能解析平台域名 | — |
| 带宽 | ≥ 10 Mbps | 出去的是 KB 级聚合结果，非原始数据，带宽要求极低 |

### 2.2 入站

| 项目 | 要求 | 说明 |
|------|------|------|
| 入站端口 | ❌ 一律不开 | 架构为"主动外联"，平台不主动访问院内 |
| VPN / 专线 / 端口映射 | ❌ 不需要 | — |

### 2.3 内部端口（仅院内网络，不对外）

| 组件 | 端口 | 暴露范围 | 说明 |
|------|------|----------|------|
| 连接器本地管理面 | 5022（可映射） | **仅 127.0.0.1** | 查状态/日志用；生产加固下**不向宿主发布端口**，经内网终端访问 |
| 连接器 ↔ 计算后端 agent | 5024（gRPC） | **仅本院内网，仅连接器可达** | 每次调用带院内共享凭证 `AGENT_SHARED_TOKEN`；agent 不对平台暴露端口 |

### 2.4 网络分区（生产建议）

- 连接器置于**医院 DMZ / 前置机区**，与 HIS 核心库、业务内网区**网络分隔**。
- 连接器经"本地数据访问接口层（最小权限）"读 HIS/数据集市的**只读 + 脱敏视图**，**不直连底层库**。
- 双向 TLS 1.3 + mTLS + 证书校验（连接器验平台任务签名，平台验连接器证书签名）。

> **常见瓶颈（务必提前启动）**：部分医院信息科完成防火墙出口白名单变更需 **1–2 周**。请尽早报备"放行 平台域名:443 出站"这一条策略。

## 3. 软件系统

| 软件 | 版本 | 用途 | 是否必备 |
|------|------|------|----------|
| Docker | 24+ | 容器化运行连接器 | ✅ |
| Docker Compose | v2+ | 编排连接器及其依赖 | ✅ |
| Node.js | 20 LTS | 连接器 NestJS 运行时（随镜像，不需宿主单独装） | 随镜像 |
| SQLite / PostgreSQL | 3.x / 15+ | 连接器本地库（元数据 + 审计）；接入初期 SQLite 零运维即可，数据量增大或高可用需求再迁 Postgres | ✅（二选一） |
| Python | 3.10+ | L4 联邦学习 / L3 因果计算后端（随 agent 镜像） | 仅 L4/L3 场景 |
| Wasmtime | 目标态 | 在独立进程内跑签名 `.wasm` 算法模块（无网络/文件/系统调用）；当前起步版在连接器进程内以零能力方式实例化 | 目标态 |

- **交付方式**：连接器与 agent 以**容器镜像**交付，院方 `docker compose up` 即起，不需在宿主逐个装依赖。
- **镜像来源**：由平台方提供正式镜像仓库地址（或离线镜像包）；国内环境依赖走 npmmirror 等镜像源，无需公网编译。

## 4. 数据接入准备

| 事项 | 工作量 | 说明 |
|------|--------|------|
| 只读脱敏视图 | 1–2 天 | 由信息科为连接器开**只读账号**，暴露待分析数据（患者/诊断/用药/检验）的**脱敏视图**，连接器不直连底层库。项目提供 `Deidentifier` 组件做剥标识 + SM3 假名化。 |
| 标准化映射（推荐目标态） | 3–5 天 | 目标态经 **OMOP CDM 视图**接入；接入初期可用 FHIR 或 CSV 直接导入 |
| 数据导入 | 0.5 天 | 脱敏数据写入连接器本地库，项目提供 `ingest` 命令行 |
| 队列与编码确认 | 沟通 | 确认参与计算的队列定义（病种、随访时间范围）；核对 ICD/ATC 等编码版本与研究方案一致 |

- **原始数据始终留在 HIS**：脱敏在院内完成后才入连接器本地库，原始/明文数据不出 HIS。
- **接入初期可用合成数据联调**：项目内置 Synthea 合成病历，可在不动真实数据的前提下先跑通全流程。

## 5. 加入区块链节点（存证）

**这里要分清"现状"与"生产演进"，两者对院方的要求完全不同。**

### 5.1 现状：医院不需要部署链节点 ✅

当前架构中，存证由**平台控制面统一处理**：长安链 ChainMaker 单节点 + Java Sidecar 部署在平台侧，合约、结果、越限记录的哈希由平台上链。**院方无需做任何链相关准备**——连接器把聚合结果连同 SM3 哈希回传，上链发生在平台边界内。

### 5.2 生产演进：医院作为联盟链成员节点（可选，网络姿态与连接器不同）

若要把信任从"平台单方存证"升级为"多方共识存证"（这是可信数据空间的自然演进方向），院方需**自建一个长安链联盟链节点**。请院方网络团队特别注意——**链节点是联盟里的对等节点，与"只出站"的连接器根本不同**：

| 维度 | 连接器 | 联盟链节点 |
|------|--------|------------|
| 网络方向 | 仅主动出站 | **双向 P2P**，需与其他成员机构节点互通 |
| 入站端口 | 不开 | **须开放 P2P 端口**给联盟成员 |

准备事项：

- **服务器**：见 §1（4C/8G/100GB 起）。
- **端口**（仅链节点，院内 + 联盟成员间）：

  | 端口 | 方向 | 说明 |
  |------|------|------|
  | 8090 | 平台/本机 | Sidecar 存证 HTTP 契约（`/health`、`/block-number`、`/attest`） |
  | 12301 | 本机 | 节点 RPC（Sidecar ↔ 节点） |
  | 11301 | **双向，联盟成员间** | 节点 P2P 共识与区块同步——需与其他 org 节点互通 |

- **组织身份**：为本院申请联盟链**组织 CA 证书 + 节点签名密钥**（`wx-org-<医院>`），纳入联盟链成员治理（共识、准入）。
- **软件约束**（来自实测，运维需知）：长安链 v2.3.0；合约用 `solc 0.8.17` 编译（v2.3 EVM 不支持 0.8.20+ 的 PUSH0）；Sidecar 走 JDK 17。
- **交付方式**：节点 + Sidecar 以合并容器镜像交付，由平台方协助初始化证书与配置。

> **结论**：如只做数据分析接入，跳过本节；如要"上链存证也去中心化"，本节是院方唯一需要**开放入站端口**的场景，须单独走网络安全评审。

## 6. 国密与密钥准备

| 项目 | 准备方 | 说明 |
|------|--------|------|
| 连接器 SM2 证书 | 平台 CA 签发 | 连接器在平台注册后，由平台 CA 签发；院方保管 `CONNECTOR_SM2_PRIVATE_KEY`、配置证书指纹 `CONNECTOR_CERT_FINGERPRINT` |
| 平台 CA 公钥 | 平台提供 | `CONNECTOR_PLATFORM_CA_PUBKEY`，用于验平台下发任务的签名（与 Wasm 模块签名共用） |
| 院内共享凭证 | 院方生成 | `AGENT_SHARED_TOKEN`（≥32 字节），连接器 ↔ agent 调用鉴权 |
| 令牌降级通道 | 生产关闭 | 生产须 `CONNECTOR_TOKEN_AUTH_ALLOWED=false`（强制证书认证）；仅本地开发可临时开令牌 |

> 密钥私钥类材料（SM2 私钥、共享令牌）由**院方生成/保管**，不外传；证书签发是"连接器注册 → 平台 CA 签发"的一次性流程，纳入接入 checklist。

## 7. 安全加固基线（容器运行）

连接器/agent 容器按以下基线运行（平台提供的加固配置已内置，院方核对即可）：

- **非 root 运行**（连接器 `1000:1000`，agent `10001:10001`）
- **只读根文件系统**（`read_only: true`），仅 `/tmp` 与命名卷可写
- **去除全部 Linux capability**（`cap_drop: ALL`）、**禁止提权**（`no-new-privileges`）
- **资源限额**：内存 / CPU / 进程数封顶（连接器 1G/1CPU/256 进程，agent 2G/2CPU/512 进程为参考起点，按机器上调）
- **不向宿主发布端口**：对外仅一个带鉴权的 `GET /connector/audit`
- **本地审计**：操作日志本地留存（命名卷，容器重建不丢）+ 关键证据上链，全链路可追溯
- **管理面仅内网**：运维经内网终端查状态/日志，不直接触达原始数据

## 8. 人员与接入时序

| 角色 | 投入 | 职责 |
|------|------|------|
| IT / 运维工程师 | 1–2 天 | 部署容器、配置出站白名单、核对加固基线、验证 health |
| 信息科 | 0.5–1 天 | 开只读脱敏视图账号、确认 HIS/数据集市视图范围 |
| 临床数据分析师 | 2–4 小时 | 确认队列定义、审核脱敏规则、验证结果合理性 |
| 网络安全 | 评审 | 出口白名单评审；如上联盟链节点，额外评审入站 P2P |

**参考时序**（真实数据接入，不含合成数据联调）：

```
第 1–2 周  网络开通（出站白名单）报备 + 服务器就绪（并行）
第 3 天    IT 部署连接器容器 → health 通 → 出站到平台通
第 4–5 天  信息科开只读脱敏视图 → 脱敏 → 导入连接器本地库 → catalog 可见
第 6 天    国密证书签发（注册连接器 → 平台 CA 签发）
第 7 天    端到端联调：平台建合约 → 医院审批 → 消费方发任务 → 连接器拉取→本地计算→回传→验证
```

> 关键路径通常是**网络出口白名单审批（1–2 周）**，请最先启动。

## 9. 医院明确不需要做的

| 项目 | 原因 |
|------|------|
| 开放入站端口 / VPN / 专线 | 连接器主动外联，平台不入站（联盟链节点场景除外，见 §5.2） |
| 部署区块链节点 | 当前存证由平台统一处理（除非选择 §5.2 的联盟链演进） |
| 提供原始 / 明文数据 | 数据在院内脱敏后入库，原始数据不出 HIS |
| 采购硬件 TEE（初期） | 初期可用软件 TEE 模式；但**不得对外声称"硬件级机密计算"**，须标注 `software-isolation` |
| 购买公网域名 / TLS 证书 | 连接器不需要公网域名，不接受入站，无需对外证书 |
| 数据库集群 / 负载均衡（初期） | 单连接器节点 + SQLite 即可起步 |
