# 前端信息架构改进计划

> 依据：[前端信息架构审计与导航重构提案](./前端信息架构审计与导航重构提案.md)（下称"审计"）。
> 日期：2026-10-07。范围：`apps/web` 控制台 `(console)/space/*`。
> 性质：执行计划。每个阶段落地时各开一个 OpenSpec change，本文件不替代 change 内的 `tasks.md`。

## 1. 与审计提案的三处调整

审计的目标 IA（§4）照用，落地顺序与做法改三处：

1. **契约先行，与止血合并。** 审计把 `nav.manifest.ts` + `check:nav` 放在 P1、止血放在 P0。本计划把两者合成阶段 0：先落 manifest 与守护，让孤儿页、门控不一致、菜单过严这些问题先变成红的检查，再逐条修绿。原因是这些问题的共同根因是导航没有单一事实源也没有守护，单修症状会再漂。
2. **门控收到布局层一处。** 审计建议给 8 个页面逐个补 `RoleGate`。改为在 `(console)/layout.tsx` 加一个读 manifest 的路由守卫，页面内的整页门控全部删除。四种写法并存的问题一次消掉，新页面不会再漏。
3. **去重与 MDOP 二期绑定。** 任务类重复（A1/A2/A9）的根因是后端三条并行编排，而 2026-09-24 已裁决由 MDOP 二期下线 RWS / FL 预测 / SecretFlow 三条旧编排（一期 `mdop-kernel` 70/70 已完成，二期尚未立项）。前端统一任务面只做薄适配层，旧通道退一条删一个适配函数；L1.5 双通道详情（A2）不手工合并，等旧通道下线自然消失。

## 4. 分阶段计划

工期为粗估，按一人全职计。

### 阶段 0：导航契约与止血（约 1 周）· change `ia-nav-contract`

目标：导航有单一事实源和守护；现有断链、门控偏差清零。菜单分组本阶段不变，用户看到的结构不变。

> 实施状态（2026-10-07）：0.1–0.4、0.6 已完成，守护全绿；0.5 中的总览去 mock 由并行会话承担（见该行）。实施中对本表做了三处调整，已在下方各行体现，依据见 `openspec/changes/ia-nav-contract/design.md`。

| 工作项 | 做法 |
|---|---|
| 0.1 导航清单 | 新增 `apps/web/src/nav.manifest.json`（JSON 而非 TS，零依赖守护可直接读）与类型化访问层 `lib/nav.ts`，登记全部 31 个路由：`route / label / entry(menu｜contextual) / group / viewLayer / entities / roles / parent / flows / guards(服务端端点)`。`SpaceNav` 改为由清单生成 |
| 0.2 守护 | 新增 `scripts/check-nav.mjs` 与 `.test.mjs` 负例，接入根 `pnpm test`。本阶段启用：无孤儿、无死链、入口可达、`FLOWS.md` 的 web actor 在册、角色枚举四处一致、页面角色与服务端 `@ParticipantRoles` 相等（不严也不松）、门控单点。"无重复列表"带显式豁免名单启用（现 4 条），名单只减不增。"标签同源"推迟到阶段 1：现在启用需要 15 条以上豁免，而阶段 1 会让页头标题直接取自清单 |
| 0.3 布局层门控 | `(console)/layout.tsx` 增加路由守卫：按 pathname 查清单，角色不符渲染统一的无权限卡片。删除页面内整页门控（`compliance`、`compliance/alerts`、`rbqm`、`deliverables` 两页）。按角色切换列或按钮的条件渲染保留 |
| 0.4 修断链 | `tasks/new/rws/page.tsx:698` 按通道分流到 `/space/mdop/jobs/{id}`；`infer/[taskId]` 登记为 `contextual`，`parent` 指任务详情；interop 菜单角色改 `operator, admin` |

| 0.6 治理同步 | `DECISIONS.md` 新增 D-UI-2（导航清单为唯一事实源）；`DESIGN.md §8` 与 `ARCHITECTURE.md:267` 角色表改 5 角色并写明门控在布局层 |

验收：`pnpm test` 全绿且负例生效；无 404 深链；5 个角色各登录一次，菜单项与可打开页面一致；`/space` 数值与 `connectors` / `tasks` / `attestations` 页一致。

### 阶段 1：导航骨架（约 1 周）· change `ia-nav-shell`

> - compose 回链 atlas（H6）由分区 tab 条解决，未另加链接。
> - 发起任务的三个表单页按服务端守卫限定为 `consumer`（原先任何角色可打开，提交时才失败）。
> - atlas 布局补了与其余页面一致的页边距；admin 页只换了页头，正文仍是浅色样式，留给阶段 3。
> - 结算归入"数据与合约"、存证归入"合规与监查"，可在清单里一行调整。
> - 验收里的"16 条 FLOW-x 逐条走查"未做完整走查，只覆盖了审计列出的断点（H1 / H2 / H4 / H6）。

### 阶段 2：去重合并（约 2–3 周）· change `ia-task-surface`

目标：同一批数据只有一个列表、一个详情。前置：第 3 节第 2 项已定。

> 实施状态（2026-10-07）：已完成，豁免名单清空，守护全绿，依据见 `openspec/changes/ia-task-surface/design.md`。与本表的出入：
> - **推理页没有内联**。它的可达性已由阶段 0、1 解决；搬动它要改写 `FLOWS.md` 的 actor 和 `TRUST.md` CTL-13 的强制点，用户得不到新东西。`/space/infer/[taskId]` 保留。
> - **没有做通用"关联对象"区**。真实断点只有账本行不可点：结算行按任务 ID 经统一任务列表反查详情地址；存证行已带归属对象链接。
> - **任务列表分面是通道、状态、我方角色三个**，没有时间分面（列表已按时间倒序）。
> - 联邦任务的两个详情按"视图"合并（技术视图 / 交付物），两个视图内部各自的结算与哈希展示未做深度去重，留给 MDOP 二期后的统一详情骨架。
> - `/capability/{layer}` 的查询键核对后已是一致的层级键，未改；`/catalog` 收敛了合规总览的一处。
> - 未在真实后端上联调：适配函数靠类型与单测保证，上线前需在预发环境对四类任务各点一遍。
