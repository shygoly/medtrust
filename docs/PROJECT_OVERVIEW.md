# MedTrust 医疗可信数据空间 — 项目全面介绍

> 本文基于仓库实际实现撰写,并如实标注实现状态:**[已实现]** 有代码且通过测试/可演示;**[Mock]** 有抽象与接口、底层为占位实现;**[后置]** 已规划未实现。

---

## 一、项目背景

### 1.1 政策与产业背景
数据已被列为继土地、劳动力、资本、技术之后的第五大生产要素。国家数据局《"数据要素×"三年行动计划》《可信数据空间发展行动计划(2024—2028年)》明确把**可信数据空间(Trusted Data Space)**作为数据要素流通利用的关键基础设施。全国数据标准化技术委员会(TC609)随之发布《可信数据空间 技术架构》(TC609-6-2025-01)及配套技术要求,确立了"基于共识规则、连接多方、数据可用不可见"的技术路线。

### 1.2 医疗行业的数据流通痛点
医疗数据(诊疗、用药、检验、影像、基因)价值极高,但**高度敏感、强监管、不可逆**:
- **不敢共享**:原始数据一旦出院即失控,违反《个人信息保护法》《数据安全法》及医疗数据分级分类要求;
- **不能汇聚**:把多院数据集中到一个平台,本质是"数据中台",法律与伦理风险巨大;
- **难以协作**:药企做上市后真实世界研究(RWS)、药物警戒,需要跨多家医院的真实诊疗数据,却无合规通道。

### 1.3 项目的方向性判断
MedTrust 最初按"中心化多租户数据平台"设计(数据脱敏后汇聚到中心库再做隐私计算)。经评审判定该方向错误——**数据汇聚 = 数据中台,不是数据空间**。项目据此转向**联邦可信数据空间**:数据永远留在源端(医院/药企本地),只有聚合结果在受控规则下流通。权威依据为 OpenSpec change `federated-data-space-rws`(proposal/design/specs/tasks 完整)。

---

## 二、项目目标

1. **数据可用不可见**:原始行级数据物理上不离开参与方本地连接器,只有经输出闸门的聚合结果可流通。
2. **以合约为授权核心**:授权不再是一次性审批,而是"数字合约 + 使用控制(PEP)",随数据流转持续强制执行。
3. **国密 / 等保 / 国标合规**:国密 SM2/3/4 贯穿身份、通信、存证;对齐 TC609 / NDI-TR 系列标准。
4. **最小切口先跑通**:以"药企-医院真实世界研究(RWS / 药物警戒)"为最窄切口,端到端可演示、可测试,再横向扩展。

---

## 三、使用场景

| 场景 | 参与方 | 价值 |
|---|---|---|
| **RWS / 药物警戒(首版切口)** | 药企(使用方)× 多家医院(提供方) | 药企对医院脱敏诊疗数据做不良反应信号检测、队列疗效分析,原始数据不出院 |
| **多院联邦建模** | 医院 × 医院 / 高校 | 跨机构联合训练疾病预测模型(联邦学习),数据不出域 |
| **跨院加密统计** | 多医院 + 发起方 | 同态加密盲聚合:中心连聚合都看不到,只有发起方能解密合并结果 |
| **监管与审计** | 卫健委 / 监管方 | 全流程日志上链存证,只读监督,不接触原始数据 |
| **数据产品流通** | 提供方发布、使用方申请 | 连接器对外提供"数据产品"(元数据/确权/分级),非裸数据集 |

## 四、功能

### 4.1 连接器(本地节点)`apps/connector` :5022 — **[已实现]**
部署在每个参与方本地,原始数据永不离开:
- **FHIR 数据网关**:接入医院 HIS/FHIR,映射为内部模型;
- **本地脱敏**:计算前去除直接标识符(姓名/电话/身份证/精确生日),生成假名;
- **数据不出域守卫**:任何外部读取行级原始数据的请求一律拒绝并审计;
- **本地 TEE 执行**:RWS 分析在可信执行环境内运行,原始数据不出 enclave;
- **输出闸门**:小单元格抑制(count<阈值置零)+ 行级/可识别数据整体拦截;
- **使用控制 PEP**:每次计算前校验数字合约(目的/有效期/撤销);
- **留存强制**:"阅后即焚"任务结束销毁中间数据;
- **端到端编排**:跨连接器任务分发、合并、跨域存证。

### 4.2 身份与可信通信 `apps/api/participant-identity` — **[已实现]**
- **SM2 CA**:中心签发/吊销连接器证书;
- **安全信道**:SM2 加密 + SM3 完整性 + 签名,篡改即丢弃;
- **准入门禁**:主体+数据双认证、数据确权、分级分类(对齐医保试点四维规则)。

### 4.3 数字合约 + 使用控制 `apps/api/digital-contract` — **[已实现]**
- 数据提供方批准 → 生成数字合约(目的/留存/输出/有效期 + 状态机 + SM3 哈希);
- 合约哈希上链存证;连接器 PEP 强制执行。

### 4.4 同态加密盲聚合 `apps/connector` HE 通道 — **[已实现 PoC + 接入编排]**
- CKKS 加法同态(node-seal / Microsoft SEAL WASM,连接器进程内);
- 各院密文上报 → 中心**无私钥盲求和** → 仅发起方解密合并结果;
- 已接入 `RwsOrchestrator.runEncrypted`,中心连聚合都看不到。

### 4.5 控制台 UI `apps/web` :5020 `/space` — **[已实现]**
- 控制室风格仪表盘:招牌"数据不出域"拓扑图、连接器状态、RWS 任务、数字合约、上链存证;
- **真实登录 + 按角色控权**:provider 见发布/审批、consumer 见发起任务、operator 只读;前后端双重控权。

### 4.6 角色与鉴权 — **[已实现]**
- 登录用户绑定参与方角色(provider/consumer/operator),JWT 携带角色;
- 路由级 `ParticipantRolesGuard` + 数据级数字合约/PEP 两层授权。

### 4.7 存证上链 `apps/api/blockchain` — **[Mock]**
- 任务/合约/输出的哈希、指纹、参与方上链(FISCO BCOS);链上无任何医疗数据明文。底层链适配为占位 mock。

### 4.8 价值共创结算 `apps/connector` + `apps/api/settlement` — **[已实现 最小]**
- 数字合约带计价(按记录/按任务/订阅);任务完成后按各院真实贡献(队列规模)**按贡献占比分账**(收益占比=贡献占比);结算摘要关联任务存证;`/settlements` 端点按角色控权(提供方见自身收益、使用方见费用、运营方见全局)。对齐"数据二十条"。

### 4.9 跨空间互联 `apps/api/federation` + `apps/connector` 网关 — **[已实现 最小]**
- 数据产品全局标识 `urn:tds:<space>:<id>`;跨域身份互认(联邦信任清单 + 外部 CA 验签);目录联邦(只读发现远端产品);**跨空间任务执行**(引用远端产品 → 源空间本地执行 → 仅回传聚合,数据不跨空间);互通网关握手/路由决策(国际 DSP 适配预留)。对齐 NDI-TR-2025-02/03。

## 五、技术架构

### 5.1 两个平面
```
┌─────────── 中心控制面(空间运营方,不碰原始数据)apps/api :5021 ───────────┐
│  身份信任源/CA   数据目录(仅元数据)  数字合约+使用控制   存证清算(上链)      │
│  SM2 证书/双认证  数据产品/分级分类    目的/留存/输出约束   FISCO BCOS         │
└──────────────────────────┬──────────────────────────────────────────────┘
              任务下发 / 结果回传(只传聚合或密文,绝不传原始行)
        ┌──────────────────┼──────────────────┐
   ┌────┴────┐        ┌────┴────┐        ┌────┴────┐
   │ 连接器   │        │ 连接器   │        │ 连接器   │  apps/connector :5022
   │ 医院 A   │        │ 医院 B   │        │ 药企     │
   │ FHIR网关 │        │ 本地TEE  │        │ 发起任务 │
   │ 本地脱敏 │        │ 输出闸门 │        │          │
   │ PEP/审计 │        │ HE 加密  │        │          │
   └─────────┘        └─────────┘        └─────────┘
   原始数据始终留在各参与方本地内网 ────────────────────
```

### 5.2 技术栈
| 层 | 技术 |
|---|---|
| 中心控制面 / 连接器 | NestJS 10 + TypeScript |
| 前端控制台 | Next.js 16 + React 19 + Tailwind v4 |
| 数据库 / ORM | TypeORM + SQLite(控制面元数据 / 连接器本地双 DataSource) |
| 国密 | sm-crypto(SM2/SM3/SM4) |
| 同态加密 | node-seal(Microsoft SEAL · CKKS) |
| 可信执行 | 可插拔 TEE 抽象 + 软件机密计算(AES-256-GCM 加密内存模拟),硬件目标海光 CSV |
| 区块链存证 | FISCO BCOS(适配 mock) |
| 密钥管理 | HashiCorp Vault(dev 可降级) |
| 工程 | pnpm monorepo,OpenSpec 规范驱动 |

**端口约定 5020–5029**:前端 5020、后端 5021、连接器 5022。

### 5.3 RWS 数据流(端到端)
药企连接器发起任务(队列定义+分析逻辑+目的)→ 中心校验数字合约/授权 → 下发到有生效合约的医院连接器 → 各院本地 **TEE** 执行 → **输出闸门**(聚合/抑制)→(可选 **HE** 密文)回传 → 中心合并 → 结果哈希**上链存证** → 药企取结果。**原始数据出域行数:0。**

## 六、案例(可运行验证)

> 全部为仓库内真实可跑的 demo / 测试,非示意。

### 6.1 单院本地闭环 `pnpm --filter @medtrust/connector demo` — **[已实现]**
华山医院 40 名患者本地脱敏 → 外部读原始数据**被拒** → TEE 内信号检测 → 输出闸门抑制小单元格 → **原始数据出域 0 行**。

### 6.2 端到端 RWS + 结算 `demo:e2e` — **[已实现]**
创新药企 ×(华山+瑞金):无生效合约的院被跳过;有合约的院本地 TEE 执行;仅回传聚合;跨域哈希上链;**按贡献分账**(使用方付 96 CNY,华山贡献29→58、瑞金贡献19→38,收益占比=贡献占比)。

### 6.3 同态加密盲聚合 `demo:he` — **[已实现]**
两院密文上报 `[6,4,3,2]`+`[5,0,1,2]` → 中心盲求和 → 药企解出 `[11,4,4,4]`,**中心看到单院明文 0 行**。

### 6.4 角色控权(浏览器实测) — **[已实现]**
华山(provider)登录 → 真实 `POST /catalog` 发布数据产品成功;研究院(consumer)发布按钮隐藏、可发起任务;未登录访问 `/space` 跳转登录。结算页按角色显示(提供方仅见自身收益)。

### 6.5 跨空间 RWS `demo:cross` — **[已实现]**
创新药企(sh-med)引用远端产品 `urn:tds:bj-med:...` → 网关解析归属空间 + 互信握手 → bj-med(北京协和)**本地执行** → 仅回传聚合 → **跨空间传输原始数据 0 行**。

**测试覆盖**:连接器 37 单测、API 30+ 单测全绿;真实 NestJS API 可启动并服务于 :5021。

## 七、可扩展性

1. **可插拔计算原语**:TEE 为抽象层(软件机密计算 → 可替换海光 CSV / 鲲鹏 iTrustee);HE 引擎可从 node-seal 升级为 OpenFHE / 隐语 SecretFlow 微服务。
2. **隐私计算多通道并存**:TEE(本地计算)/ 输出闸门(出域控制)/ HE(跨院盲聚合)/ 联邦学习 / MPC 各司其职,按场景选择,互不替代。
3. **横向扩参与方**:连接器为独立可部署单元,新增医院/药企即接入,不改中心。
4. **互联互通预留**:接口对齐 NDI-TR-2025-02/05,为接入区域/行业功能节点、跨数据空间互联预留。**[后置]**
5. **规范驱动演进**:OpenSpec change 管理需求-设计-规格-任务,新能力按 spec 落地。
6. **切换可回滚**:`LEGACY_CENTRALIZED` 开关在新旧路径间平滑切换,零风险灰度。
