## 1. 为什么必须有这个东西

C2 首个场景（D-TEE-4 首选 A）是**跨院队列交集**：A 院有暴露、B 院有结局，需按**同一主体**配对。
这是 C3 数学上做不到的事——只用两院边际计数求交，可行区间宽度恒 > 0（本仓已用
`joinableBounds` 做了证明式表述，不是估计）。

要在节点内把同一主体的记录对上，就必须让两院对同一患者**产生同一个可比的键**。
但「标识符出域」是 TRUST 的红线（原始标识符不得出现在任何跨域边，见 FLOWS `raw-local` 红线）。

**关键认识：C2 没有消除这条红线，而是把它替换成一个新问题**——
不能送原始标识符，那就必须存在一套**可对齐的假名键基础设施**。本材料要决定的就是这套基础设施长什么样。

---

## 2. 两个候选方案

### 方案 A：全空间共享盐（shared salt）

各院用同一个盐对本地标识符做单向函数，得到空间内统一的假名键：

```
假名键 = SM3( 共享盐 ‖ 归一化标识符 )          # 各院算，结果可跨院直接比对
```

节点内配对退化为一次普通 join。

| 维度 | 评价 |
|---|---|
| 实现复杂度 | **极低**。一个 SM3，无交互协议，无新增通信轮次 |
| 性能 | 好。配对是普通哈希 join |
| 泄露面 | **大**。两处都能致命：① **盐泄露 = 万能钥匙**——医疗标识符空间很小（尤其「姓名+出生日期」这类组合），拿到盐即可对候选标识符**字典攻击**重算全部假名；② 即使盐不泄露，**任一院拿到另一院的假名列表**也能用本院标识符枚举出来比对（假名列表本身即敏感物，不是可以随便流转的中间产物） |
| 信任单点 | 盐的托管方成为新的信任单点，且必须长期存在（盐不能每次会话换，否则假名不可比） |
| 与 C2 会话模型 | **不契合**。C2 是会话级、一次性密钥、会话结束销毁（`PurgeOrder`）；共享盐必须**长期、跨会话稳定**，是一个与 C2 信任模型相反的长期秘密 |
| 审计 | 难。谁在何时用盐算过哪些标识符，无法从假名反查 |

### 方案 B：跨院 PSI（隐私集合求交）——建议细化为 DH-PSI（两次幂）

各院不共享任何长期秘密。用经典 DH-PSI，只需**两轮**交互：

```
① 各院生成一次性私钥 a，上传盲化集合 { H(x)^a }            （上行，一次）
② 节点（或对端）用一次性私钥 b 再幂一次 → { H(x)^ab } 作为本次会话的配对键
   并把 { H(y)^b } 回给各院                                （下行，一次）
③ 各院用本地 a 再幂 → { H(y)^ab }，与本地 { H(x)^ab } 求交
```

| 维度 | 评价 |
|---|---|
| 实现复杂度 | 中。需要一个 PSI 协议实现（DH-PSI 是其中最简单的一类）+ 新增一轮消息类型 |
| 与「院内唯一出站」的兼容性 | **可行，但要设计**。D-CN-4 定「院内唯一出站组件 = 连接器，长轮询下发 + 双向签名」，即院内是被动拉取、不主动互连。多轮 PSI 不能用院间直连，必须**由节点中转**——DH-PSI 恰好只需上行/下行各一次，可映射到既有长轮询消息通道 |
| 泄露面 | **最小**。只泄露「交集本身」与「交集大小」（这是配对必须泄露的）；无长期共享秘密，节点只看到 `H(x)^a`（a 未知，无法反推 x）；每轮会话一次性密钥 |
| 信任单点 | 无长期秘密可托管。但**节点成为 PSI 的一方**：半诚实（semi-honest）模型下安全；若要防节点恶意（例如用不同 b 试探），需要额外机制（如承诺或零知识证明），本期可先按半诚实假设并在合约与文档里写明 |
| 与 C2 会话模型 | **高度契合**。一次性密钥、会话内有效、会话结束即失效——与 `PurgeOrder` 语义天然一致 |
| 性能 | 中等。幂运算量 ∝ 集合规模；需评估两院队列规模下的耗时与预算计入 |
| 审计 | 好。可审计「本轮会话发生过一次 PSI、交集规模为 N」，但无法从记录反查任何个体 |

## 3. 一个两边都要处理的残余泄露：交集大小

**无论选 A 还是 B，配对结果的规模本身就是敏感量。**
对罕见暴露/罕见结局（药物警戒正是这类），「交集 = N」且 N 很小时，接近直接报出个体数。

因此两条方案都必须附带以下约束（**建议写成硬要求**）：

1. **交集大小不得回传给申请方**——它只作为节点内发布审查（`NodePublicationReview`，minCell）
   的输入，以及审计回执里的一行，不进 C3 载荷；
2. 配对结果出域前必经 `minCell` 与小单元格二次抑制（既有闸门，已落地）；
3. 查询预算账本（`NodeQueryBudgetLedger`）必须把**配对查询**计入（`kind: 'query'`），
   防止反复试探不同亚组的交集规模反推个体。

## 4. 技术倾向（**仅为技术判断，不替代合规取向**）

**倾向方案 B（DH-PSI）**，理由按权重排序：

1. **没有万能钥匙**。方案 A 的盐一旦泄露（或假名列表被任一院拿到），全空间患者可被重算重识别，
   这是不可逆的、且与 C2「不信任运营方」的信任方向直接冲突；B 不产生任何长期秘密。
2. **与 C2 会话模型同构**。B 的一次性密钥天然融入「会话内有效、结束即销毁」，
   不需要为 A 去维护一个例外的长期秘密——那个例外会成为整个架构里最脆弱的一点。
3. **可映射到既有部署约束**。DH-PSI 只需上行/下行各一次，能挂进既有长轮询通道，
   不必让院内连接器改为主动互连（后者会破坏 D-CN-4）。
4. 工程代价（一个 PSI 实现 + 一类消息）与它避免的风险不成比例，**值得**。

**若选方案 A**，则至少必须补齐（否则不建议启用）：
- 盐由**医院共管**（门限/双签），不得由运营方单独持有；
- 假名列表**禁止流转**，配对只在节点内对密文/信封做；
- 盐轮换机制与历史假名的可比性方案（轮换即历史队列不可配对，需明确代价）。

## 5. 需要医院 / 合规回答的问题（决策输入）

> 以下问题属于**医院与合规的取向**，不是工程可以自行决定的。工程侧只提供上表的判据。

1. **接受的泄露面**：能否接受「两院之间存在一个可对齐的假名基础设施」这一事实？
   若不能，则 D-TEE-4 首选 A 不成立，应退回备选 B（亚组/切点重算，仅演示链路）。
2. **盐（若选 A）的托管归属**：由谁持有、是否门限共管、谁能审计其使用？是否写入委托处理协议？
3. **PSI 的信任假设（若选 B）**：是否接受「节点是 PSI 的一方、按半诚实模型安全」这一假设？
   若要求防恶意节点，成本与排期需另议。
4. **多轮交互的合规定性**：PSI 过程本身是否被认定为「数据出域」？是否需要单独告知与授权？
5. **交集大小的处置**：是否同意「交集大小不回传申请方、仅用于闸门与审计」这一约束？
6. **是否要求国密算法**：DH-PSI 的幂运算若要求国密，需用 SM2/SM9 体系实现（工程代价另行评估）；
   方案 A 的 SM3 已是国密。
7. **可审计性要求**：医院需要什么样的证据来相信「只求了交、没拿走别的」？
   （这决定协议是否要加承诺/证明，以及回执里要记什么。）
