## 2. 禁止的表述

| 禁止 | 理由 / 应改为 |
|---|---|
| 「已具备硬件机密计算能力」 | 一次试点验证 ≠ 能力上线；只能用 §1 第一行的上限表述 |
| 「C2 已生产可用 / 可信空间节点已上线」 | 生产 KMS 归 D-TEE-1（未做）；真实部署里 C2 目标仍为零（能力通告由真跑证明得出）；改为「端到端验证完成」 |
| 「数据绝对安全」 | 试点只覆盖证明链本身；安全承诺受 TRUST 红线与 REG 闸门约束 |
| 「基于 Intel SGX 的（联合）方案」 | D9：目标链型是 TDX（VM 级），**非 SGX**；材料里 SGX 只作历史沿革一句带过 |
| 「已支持海光 CSV / AMD SEV-SNP」 | 两链仅有协议抽象与软件替身，无实测（D-TEE-3 ① 分支维持推断）；只能说「同一契约预留了换链能力」 |
| 「本试点用了 GPU / Arc B70 加速 agent 推理」 | 试点拓扑 A 案**无 GPU**：推理在至强 6 AMX CPU（OpenVINO Model Server）上；B70 属后续阶段，不得提前写进本试点材料 |
| 「医院/agent 执行环境具备硬件隔离」 | 院内 `attestationLevel` 恒 `software`（D9 / CTL-09）；试点说的是**云上可信空间节点**，不是院内平面 |
| 推理速度 / 吞吐 / 「高性能推理」类主张 | 推理机为 2 vCPU / 8G 的演示规格，不构成性能证据；材料里不出现速度数字 |
| 「模型在 TEE 内运行 / 机密推理」 | 推理机不是 TDX 机型；模型只收已出域的聚合结果（C3） |
| 「AI 给出研究结论 / 自动解读」 | 小模型输出不可信，数值由服务端计算、模型只措辞，产物是待确认草稿 |
| 「节点运营方也看不到数据」 | 本试点度量不含节点程序、TD 内保留 root 登录：TDX 防住的是云厂商与宿主机，运营方可替换程序或读内存而证明照过。只能说「云厂商与宿主机读不到明文」 |
| 「换一段代码 / 换一台机器就拿不到密钥」 | 度量值目前只覆盖机密虚拟机初始镜像（MRTD），未建立节点程序镜像 ↔ 度量的可复现映射（任务 1.2 未完成）；只能说「证明不通过，密钥不释放」 |
| 「已具备生产级密钥管理 / KMS」 | 密钥保管为试点形态（与校验方同进程、密钥只在内存）；D-TEE-1 未决 |
| 「两家医院各有一台 TEE」 | 两台 TDX 主机是「可信空间节点」与「校验方」，分属两个网络域；医院侧是软件连接器 |
| 「发现了某疫苗的心肌炎风险」/ 把 RI 4.45 当成真实结论 | 心肌炎事件是**人为注入的合成信号**（真 RI=4，基线为功效放大）；只能说「合成数据里注入的信号被如实找出」，并注明不代表任何疫苗的真实风险 |
| 在代码/UI/对外文档把执行环境自述写成 hardware 级 | `check-tee-claims.mjs` R1 判红；口径变更只能走受控来源与决策登记 |

## 3. 使用说明

- 材料出稿后自查两步：`node scripts/check-tee-claims.mjs` 全绿 + 对照本清单两栏；
- 实测状态变化（D-TEE-3 补注、DEPLOY §4.3 现状表更新）时**本清单同步改版**，引用处标注日期与版本；
- 「与 Intel 生态对话的技术底账」= 5.1 实测记录，不是本清单；**证据先行，叙事后行**（design P6）。
