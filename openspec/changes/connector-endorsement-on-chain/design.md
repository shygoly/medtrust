## Context

存证现状（本会话核实）：连接器回传结果时对请求做传输层 SM2 签名（`ts:pid:bodySm3`，`ConnectorTokenGuard` ingress 验一次即弃）；平台验哈希后把**合并后的单个 `resultHash`** 锚到**单节点** ChainMaker（`attestation.anchor(resultHash)`，payload `{dataHash, source}`）。链上无连接器签名 → 存证只能证「平台锚了这个哈希」，不能脱离平台独立归因到某院。信任锚已有：连接器证书（平台 CA 签发）+ `ConnectorAuthService.verifyPayloadSignature`（已存在，可验连接器对某摘要的签名）。

## Goals / Non-Goals

**Goals:**
- 让存证记录**可脱离平台独立归因并核验到每个贡献医院**——读链者凭平台 CA 证书链即可验，医院**无需运行链节点、无需开入站口**。
- 用现有 PKI（连接器证书 + 平台 CA），最小改动。

**Non-Goals:**
- 不做医院链节点 / 多节点共识（L2/L3，归 P-CTL-4）。
- 不改 `attestationLevel`（仍 `software`，D-RWS-4）。
- 不解决「平台**遗漏/不锚**某条记录」——见 Decisions D4（L1 防伪造，不防遗漏）。

## Decisions

### D1. 签结果哈希（`resultSm3`），不复用传输签名
连接器对稳定的 `resultSm3` 单独做**结果级** SM2 签名，而非复用 `ts:pid:bodySm3` 传输签名。
- 理由：传输签名绑时间戳、只在 ingress 验、不是对「结果」这一稳定对象的背书；结果级签名对 `resultSm3` 稳定可复验，才能上链后被第三方独立核验。

### D2. 上链 payload = 合并 `resultHash` + 各院背书数组
`anchor` 从锚单哈希扩展为锚 `{ resultHash, endorsements:[{participantId, resultSm3, sig, certFingerprint}] }`。
- 理由：多院任务需**按院**归因；合并哈希证「整体结果」，各院背书证「该院对其贡献的背书」。

### D3. 复用现有 PKI，零新密钥
验签复用 `ConnectorAuthService.verifyPayloadSignature`（连接器证书公钥）；第三方核验只需平台 **CA 公钥**（公开）验证书链 + 连接器证书公钥验签。
- 上链带**证书指纹**还是**整证书**：带指纹更省链上空间，但第三方要能按指纹取到证书；带整证书自包含。**取舍**：链上带指纹 + 证书由平台目录/存证附带发布（见开放问题）。

### D4. L1 防伪造、不防遗漏——如实划界
L1 让**已锚的**记录可独立归因：平台**无法伪造**某院背书（没有该院私钥）。但平台仍单节点、仍控制**锚不锚/锚什么**——**遗漏或不锚**某院贡献是 L1 堵不住的，那是 L2（多节点共识/医院背书节点）的职责。对外表述必须如实：L1 = 「链上记录可独立归因」，不是「无单一可信运营方」。

### D5. 链不可达时降级不丢背书
`anchor` 已有降级（链错时本地回执，`0x…` txHash）。背书数据**先持久化**到派发记录，链恢复后可补锚；降级不丢背书。

## Risks / Trade-offs

- **只防伪造不防遗漏** → 如实标注（D4）；遗漏留给 P-CTL-4 的 L2。
- **第三方需拿到平台 CA 公钥** → 公开发布 CA 公钥（本就是公钥）；或链上带整证书自包含。
- **两道签名（传输 + 结果级）** → 轻微开销；传输签名管 auth、结果签名管背书，职责不同，保留两者。
- **合并前需保留各院 `resultSm3`** → meta-merge 合并各院结果，必须在合并前把各院 `resultSm3` + 签名收集齐再 anchor（改 `l0-validation-merge`/`comparative-effect-merge` 的收集点）。
- **旧连接器无结果级签名** → 见迁移：先渐进（不破坏），再强制。

## Migration Plan

- **渐进上线**：连接器加结果级签名（新版）；平台**先渐进**——有签名则验+锚背书，无签名则该院背书缺失但任务不破（对齐 L2-sap-lock 的「签名验证渐进」）。两院连接器都升级后，**再切 fail-closed**（无/错签名即拒该院贡献）。
- **向后兼容**：anchor payload 加字段，旧读取方忽略新字段即可。
- **回滚**：背书是增量；关掉「锚背书」即回到只锚 `resultHash`，链与连接器不受影响。
- **ali29**：连接器 + api 重建（连接器带 hardening overlay）；CA 已挂卷持久化（连接器证书/CA 公钥不变，背书验签链不断）。

## Open Questions

- 结果级签名**渐进 → 强制**的切换时机（两院都升级后即切？）。
- 链上带**证书指纹**还是**整证书**？指纹省空间但需证书分发通道；整证书自包含但更大。
- 平台 **CA 公钥/证书**对外发布在哪（存证详情页附带？目录？），让第三方能独立验？
- 背书粒度：只锚**最终合并结果**的各院背书，还是也锚**各院原始贡献**的背书（后者更细但上链更多）？
- 是否需要一条 DECISIONS（存证按院背书的口径）+ 是否在 `P-CTL-4` 现状标注「L1 可独立归因已落地、L2 多节点未落地」。
