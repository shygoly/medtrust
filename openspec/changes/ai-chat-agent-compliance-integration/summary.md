# AI 助手合规集成 - 执行摘要

## 🎯 核心问题

**当前状态**：AI 助手可以直接提交任务到 MDOP，跳过了数据合约创建环节。

**风险**：
- ❌ 违反数据治理要求
- ❌ 无法追溯数据使用授权
- ❌ 与现有"数据 → 合约 → 任务"流程脱节

## 💡 解决方案

**在保持 AI 助手便捷性的同时，无缝集成现有合规流程。**

### 核心设计

```
用户提需求
  ↓
Agent 识别场景
  ↓
[检查权限和合约] ← 新增
  ↓
  ├─ 有合约 → 直接配置任务
  ├─ 无合约但可自动创建 → 返回 [合约审批 Card]
  └─ 需要管理员审批 → 返回 [合约申请 Card]
  ↓
配置任务参数
  ↓
提交 MDOP（带 contractId）
  ↓
执行 + 审计
```

### 三种场景流程

#### 场景 A: 已有合约（3 步）
```
1. 用户: "我想做单臂对照"
2. Agent: [返回配置表单] (自动检测到合约 ct-123)
3. 用户: [填写并提交]
✅ 完成
```

#### 场景 B: 无合约但可自动创建（5 步）
```
1. 用户: "我想做单臂对照"
2. Agent: "我需要创建数据合约..." [返回合约审批 Card]
3. 用户: [点击"同意并创建"]
4. Agent: [返回配置表单]
5. 用户: [填写并提交]
✅ 完成
```

#### 场景 C: 需要管理员审批（引导式）
```
1. 用户: "我想做单臂对照"
2. Agent: "此合约需要管理员审批..." [返回申请指引]
3. 用户: [提交申请]
4. 管理员: [审批通过]
5. 用户: 返回 AI 助手继续配置
✅ 完成
```

## 🏗️ 技术实现

### 新增组件

1. **ComplianceOrchestrator** - 合规编排器
   - 权限检查
   - 合约状态查询
   - 自动创建合约逻辑

2. **新增 Tools**
   - `check_data_access` - 检查数据访问权限
   - `check_contract_status` - 查询合约状态
   - `create_contract_draft` - 创建合约草稿
   - `activate_contract` - 激活合约

3. **新增 Card 类型**
   - `ContractApprovalCard` - 合约审批确认
   - `ContractRequestCard` - 合约申请引导

4. **审计增强**
   - 记录所有合约操作
   - 记录权限检查结果
   - 任务提交时关联 contractId

## 🔍 关键决策点

### 决策 1: 是否支持自动创建合约？
**建议**: ✅ 是
- 大幅提升用户体验
- 有审计日志，可追溯
- 设置互信白名单控制风险

### 决策 2: 合约有效期多长？
**建议**: 30 天（可配置）
- 足够完成一次分析
- 避免长期授权风险
- 到期后需重新审批

### 决策 3: 是否需要对方确认？
**建议**: 分情况
- 互信伙伴：自动审批
- 新伙伴：需双方确认
- 敏感数据：需管理员审批
