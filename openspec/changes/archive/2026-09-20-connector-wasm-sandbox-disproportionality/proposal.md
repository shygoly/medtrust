## Why

连接器现在在自身 Node 进程里直接执行分析逻辑。SoftwareTee 只是同进程的软件实现，不提供隔离，也没有远程证明（CTL-09、D9）。D-CN-2 已把目标定为「签名 Wasm 模块 + 能力受限沙箱」，但仓库里还没有任何沙箱、算法包签名或模块固定机制（TRUST P-CTL-5/6 仍是缺口）。

要说明的是：药企目前只能提交参数（药物、结局、纳排条件），跑在数据上的是连接器自带代码。所以把 L1.5 失衡检测放进沙箱，对这一个分析类型本身的安全收益有限。第一步真正的价值是**在最简单的内核上把整套机制跑通**：签名、合约固定、运行前校验、资源上限、执行隔离如实标注。之后更复杂的分析类型，以及 D-CN-2 真正防范的「外来算法代码」，都沿用这套机制迁入。

## What Changes

- **新增 Wasm 沙箱执行器（连接器）**：用 Node 自带的 WebAssembly，在独立 worker 线程里运行算法模块。模块只允许导入一块由宿主提供、有上限的内存，其他导入一律拒绝，因此没有网络、文件、进程和系统调用能力。执行有超时和内存上限，超限即终止并判任务失败。
- **首个 Wasm 化分析类型 L1.5 失衡检测**：宿主在本地库守卫（`aggregateInternal`）内部，把行数据投影成最少的几列整数标记：是否入组、是否暴露、每个事件词条是否发生。沙箱只输出每个词条的 2×2 计数 a/b/c/d，词条文本始终留在宿主一侧。结果照常经过输出闸门。输出必须与现有 TS 实现逐字段一致。
- **算法包签名与合约固定**：模块源码在仓库内，可复现构建。平台用现有 SM2 CA 签名模块的 SM3 摘要。数字合约新增「固定算法模块」条款，写明分析类型对应的模块 SM3。连接器运行前做两项校验：SM3 必须等于合约固定值；SM2 签名要用部署配置里固定的平台 CA 公钥验证。任一项失败即拒绝执行，**不回退到 TS 实现**。
- **执行隔离如实标注**：`attestationLevel` 保持 `software` 不变（CTL-09：沙箱不等于 TEE）。另加一个正交字段 `executionIsolation: none | wasm-sandbox` 和模块 SM3，写在聚合结果**内部**随结果回传，从而被既有的 SM3 验哈希覆盖、无法篡改。控制面按每家医院的派发记录入库、写入存证元数据，并在界面上显示。
- **不改现有行为**：合约没有固定模块时，仍走现有 TS 路径，并如实标注 `executionIsolation: none`。
- **治理文档**：修订 D-CN-2（运行时起步用 V8，Wasmtime 为目标；模块只允许导入有上限的内存）；新增一个 TRUST 控制点；DOMAIN 状态词汇表登记 `executionIsolation`；FLOWS 更新 L1.5 步骤；DEPLOY 登记新的连接器环境变量。

## Capabilities

### New Capabilities
- `algorithm-sandbox`：连接器侧的能力受限 Wasm 执行。覆盖运行前校验（合约固定的 SM3 + 平台 SM2 签名）、零能力实例化、资源上限与超限失败、最小列投影输入、每次运行写本地审计。

### Modified Capabilities
- `rws-compute`：「本地 TEE 执行」改为如实表述：软件级、同进程、无隔离。新增执行隔离标注随结果回传，并受结果哈希保护。合约固定了模块的 L1.5 任务必须在沙箱内执行。
- `usage-control`：PEP 增加校验：合约为该分析类型固定了模块时，任务携带的模块 SM3 必须一致，否则拒绝执行。
- `digital-contract`：数字合约可以包含「固定算法模块」条款（分析类型 → 模块 SM3），该条款计入合约哈希一起存证。

## Impact

- **连接器**：新增 `apps/connector/src/domain/sandbox/`（模块校验、worker 内实例化、失衡检测宿主适配）；`rws-executor.ts` 按合约选择执行路径；任务执行器和控制面客户端在算哈希**之前**把执行标注写入聚合结果；`ContractView` 增加固定模块字段；PEP 增加一项校验。
- **控制面 API**：新增模块分发接口（连接器鉴权，返回模块字节、SM3、签名）；CA 增加对模块摘要签名的能力；派发记录携带模块引用；结果入库时读取执行标注并做枚举校验，缺省为 `none`；存证元数据增加执行标注；合约增加固定模块条款。
- **数据库**（`packages/database` 控制面实体）：合约表增加固定模块列；RWS 派发表增加 `executionIsolation`、`moduleSm3` 两列。
- **新包** `packages/wasm-algorithms`：AssemblyScript 源码，编译器版本锁定，构建产物带 SM3 清单。只是开发依赖，不引入新的运行时原生依赖。
- **前端**：RWS 任务详情按医院显示执行隔离（Wasm 沙箱 + 模块指纹 / 无隔离），信任级别仍显示 software。
- **部署**：连接器需要新增平台 CA 公钥等环境变量。上线 ali29 要重建 API（会清空控制面 SQLite，须在演示之后、预跑任务之前做）和连接器镜像（镜像里有不在 git 的注入数据，要按 09-15 的补丁镜像方式构建）。
- **测试**：与 TS 实现的逐字段一致性；验签失败、SM3 不符、非法导入、超时、内存超限都必须拒绝且不回退；含执行标注的结果在连接器和控制面两侧哈希一致（09-15 回传被拒故障的回归测试）。
