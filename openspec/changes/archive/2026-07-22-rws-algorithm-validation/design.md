## Context

`rws-compute` 现有的四级阶梯（L1.5 失衡信号 / L2 比较 / L3 因果 / L4 预测）都建立在一个未经检验的前提上：**任务规格里的人群与结局是被正确识别的**。药监《RWD 支持药品安全性主动监测的研究设计和分析指导原则》§2.1 把这个前提拆成两层——概念性定义（涉及哪些数据元素）与操作性定义（编码或算法 + 评估时间窗）——并在 §2.6 / §2.7.4 要求**必须报告所用编码/算法的准确性**，在 §2.8 把"信息/错分偏倚"列为常规诊疗数据最常见的偏倚类型，其控制措施第一条就是"对变量识别算法开展验证研究"。

本仓当前的 `TteSpec.inclusion` / `exclusion` / `TteOutcomeSpec.event` 均为自由文本字符串：算法既无法表达，更无法验证（[EVIDENCE.md](../../../EVIDENCE.md) 覆盖矩阵第 11、12 项）。

**约束**：
- 金标准（gold standard）来自人工病历审阅，必须接触原始记录 → 比对只能在连接器本地做，出域的只能是聚合量。
- 连接器是唯一碰原始数据的部件，任何来自消费方的"算法"在其上执行都是攻击面（TRUST 红线所在）。
- 验证研究样本量天然不大（病历审阅昂贵），统计方法必须在小样本下稳健。

## Goals / Non-Goals

**Goals**
- 让识别算法成为可表达、可下发、可执行、可验证的一等对象。
- 产出符合规范要求的准确性指标（Se / Sp / PPV / NPV + 95%CI），按数据源分别报告。
- 复用既有闸门与存证链路，不为 L0 新开一条数据通道。

**Non-Goals**
- 不产生金标准（人工审阅是院内医学行为，系统只消费既有标注）。
- 不做定量偏倚分析（用准确性去校正效应量，属 P-EVD-6）。
- 不做算法自动生成/推荐。
- 不实现通用临床质量语言解释器（见 D4 备选）。

## Decisions

### D1. 金标准标注 = 独立的 connector-local 实体，不塞进 `local_record`

**选择**：新增 `local_gold_standard`（connector-local 平面），字段含被标注记录的 `subjectKey`、所针对的变量定义标识、判定结论（阳性/阴性）、标注来源（登记库 / 专病库 / 本研究审阅）、依据的诊断标准、标注时间。

**理由**：金标准是"针对某个变量定义的判定结论"，不是记录的固有属性。同一条记录会被多个不同结局定义分别标注（一对多）；且标注的来源与依据本身就是准确性报告必须交代的内容（§2.6 要求报告"算法来源与准确性"）。

**备选**：`local_record` 加 JSON 标注列——否决：表达不了一对多，且让记录表随研究数量膨胀。

**影响**：DOMAIN.md 覆盖矩阵新增一行 connector-local 表；TRUST.md 需登记该表的敏感分级（含判定结论，等同临床诊断）。

### D2. 95% 置信区间用 Wilson score interval

**选择**：Wilson，作为四个指标 CI 的默认方法。

**理由**：验证研究样本量通常在几百例量级。Wald 区间在比例接近 0 或 1 时会给出越界的界（<0 或 >1），而**高特异度算法的 Sp 恰恰接近 1——正是最常见的场景**。Clopper-Pearson 保证覆盖率但过于保守，区间偏宽会系统性低估算法质量。Wilson 在小样本与极端比例下均稳健。

**备选**：Clopper-Pearson——监管语境下有人偏好其保守性，保留为可配置项，但不做默认。

**影响**：DOMAIN.md 派生公式区登记指标定义与 CI 方法，作为唯一出处。

### D3. 混淆矩阵任一格被抑制 → 该算法全部指标不出域（fail-closed）

**选择**：全有或全无。

**理由**：Se / Sp / PPV / NPV 四个指标共享同一组 TP/FP/TN/FN。抑制任一格至少让两个指标失真；若只放行"未受影响"的指标，使用者仍会拿残缺结果做整体判断。这与 D-UC-2「出域前关键义务同步 fail-closed」一致。

**有意为之的后果**：样本量不足的验证研究拿不到任何数字。这是正确行为——样本量不足本就不该报告准确性（§3.2 同理要求样本量理由说明）。UI 必须把"因抑制而无结果"与"算法表现差"显著区分，避免误读。

**备选**：逐指标放行——否决，理由如上。

### D4. 算法表达 = 受限布尔组合，不引入通用表达式求值

**选择**：闭合语法 —— `AND` / `OR` / `NOT` + 编码集成员判定 + 时间窗约束，由连接器解释执行。编码集显式声明编码系统、版本、取值来源（门诊 / 出院诊断）与诊断顺序（§2.7.4 示例要求的四要素）。

**理由**：通用表达式求值器（`eval` / JS 沙箱 / 自定义 DSL 解释器）意味着在**唯一能碰原始数据的部件上执行来自消费方的代码**，这是直接的注入面与不可预测的计算成本。受限语法可静态校验、可估算成本、可完整审计。

**备选**：采用 CQL（Clinical Quality Language，HL7 标准）——表达力足够且是行业标准，但需完整解释器与大量测试，且同样引入求值风险；列为后续升级路径，不在本 change。

**关联**：算法定义是跨域入站载荷（`crosses: control→connector`，`payload: task-spec`），受限语法是其安全前提，须在 TRUST 登记。

### D5. L0 第一版不强制前置，但已验证算法必须带出准确性

**选择**：不阻断"引用未验证算法"的 L1.5–L4 任务；但当所引用算法在该数据源已有验证结果时，报告 MUST 附带其准确性指标。

**理由**：硬前置会让能力上线即不可用——当前零个算法有验证结果，且金标准可得性是本系统控制不了的外部前提。渐进路径：先让"有验证就自动带出"成为默认，形成正向压力。

**备选**：硬前置——否决，理由如上。何时转强制见 Open Questions。

### D6. 跨源结果分列，MUST NOT 合并

**选择**：L0 任务跳过 `MetaAnalysisService`，结果按 `providerId` 分列呈现。

**理由**：规范 §2.1 明示同一概念性定义在不同数据库的操作性定义可能不同，§1.1 要求讨论多源异质性。把各院准确性平均成一个数，等于**假定算法在各院表现一致——而这恰恰是验证要回答的问题**。

## Risks / Trade-offs

- **金标准不可得**（外部前提，本系统不可控）→ 先用 Synthea 合成数据造标注跑通 e2e 与闸门；真实准确性数字待院端接入。须在 UI 与报告中标注数据来源性质，合成数据的验证结果 MUST NOT 用于申报。
- **小样本导致整体抑制**（D3 的有意后果）→ 提交时按标注集规模给出预警；UI 区分"抑制"与"表现差"。
- **受限语法覆盖不了真实临床算法**（D4）→ 先收集真实算法样本评估覆盖率；覆盖不足时按 D4 备选升级 CQL。
- **金标准标注本身是敏感数据**（含判定结论，敏感度等同临床诊断）→ 分级在 TRUST 登记；标注永不出域，出域的只有混淆矩阵计数。
- **算法迭代导致验证过期** → `IdentificationAlgorithm` 带版本；验证结果绑定算法版本 + 数据源 + 标注集版本三元组，任一变更即视为需重验。

## Migration Plan

纯增量，无 BREAKING：
1. connector-local 新增 `local_gold_standard`（SQLite `synchronize` 环境自动建表）。
2. 连接器新增算法求值与比对域服务，注册 `algorithm-validation` 分析类型。
3. 闸门增混淆矩阵抑制联动规则。
4. 控制面增 L0 编排（分列，不合并）+ 存证。
5. 七份治理契约同步（见 proposal·Impact），`pnpm check:meta` 绿。

**回滚**：L0 是独立分析类型，停用即回到现状；已产生的验证结果与存证保留。

## Open Questions

- **金标准标注集是否需要独立的合约条款授权？** 它是本地数据的一种，但用途特殊（判定结论而非观测事实）。倾向：复用现有数字合约，但 `purpose` 须显式含"算法验证"。
- **L0 何时从"不强制"转为"强制前置"（D5）？** 倾向挂钩合约条款——由数据提供方（医院）在合约中要求"本数据产品上的研究须使用已验证算法"，把决定权交给数据主权方而非平台。
- **同一算法在同一数据源的多次验证如何呈现？** 倾向按三元组（算法版本 / 数据源 / 标注集版本）保留全部历史，不覆盖——准确性的时间趋势本身是有价值的信息。
