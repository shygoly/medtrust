## Context

《指导原则》有两条贯穿全文、且互相支撑的硬要求：**方案先行**（§1：初始方案须在数据收集前完成；§1.2：任何实质性修改须留痕——版本号 + 修改日期 + 修改内容 + 修改原因）与**预先设定**（§3.1 SAP 事先制订；附1·2 监管要点原文："建议在制定研究方案或分析计划时预先指明用于构建倾向评分模型的变量，避免为获得'理想'或'预期'结果而反复调整倾向评分模型"）。

两者对抗的是同一件事：**事后调整分析以迎合期望结果**。这类问题的特征是——从最终产物上看不出来。一份 p<0.05 的报告，无法从结果本身判断它是第一次分析的结果还是第七次调参的结果。因此**唯一有效的控制点在事前**：把规格冻结在执行之前，让任何变更留下痕迹。

本仓现状（[EVIDENCE.md](../../../EVIDENCE.md) 待接入项 P-EVD-1/3/4/5/6/7/8）：`cp_rws_task` 无版本字段；`matchingCovariates` 可随时改；SAP / 敏感性分析 / 缺失值 / 设计类型均无承载；`outcome.event` 与 `exposureArm` 都是自由文本，**§2.7.4 的硬红线"结局定义必须独立于暴露"无任何校验**。

**约束**：
- 既有 e2e、demo 与 Fly 上的在跑任务不能被打断——但本 change 的核心恰恰是新增必填字段（BREAKING）。
- 系统能校验"是否声明"，不能校验"声明得是否科学合理"——后者是人的责任，误判会比不判更糟。

## Goals / Non-Goals

**Goals**
- 研究方案成为可版本化、可冻结、要素完备的一等对象。
- 把三条能机检的规范红线落成 fail-closed 校验：结局-暴露独立性、预先指定字段冻结、敏感性分析全报。
- 保持"系统只判形式、不判实质"的边界清晰。

**Non-Goals**
- 不判断 SAP 内容的科学合理性（只校验是否声明）。
- 不自动化 P-EVD-9（阴性结果重审检验效能）——人工评审项，只在报告模板留位。
- 不引入 DAG 结构化协变量分类（§2.7.5）——复杂度不同质，单独立项（见 Open Questions）。

## Decisions

### D1. 冻结边界 = 首次派发（而非提交）

**选择**：任务规格在**首次向任一连接器派发 assignment 时**冻结，而非在提交时。冻结后规格字段不可变，修改 = 新版本 + 必填理由。

**理由**：提交到派发之间存在合法的准入失败与修正窗口（合约校验不过、参与方不可达、字段填错）。在提交时即冻结会迫使用户为纠正笔误开新版本，制造无意义的版本噪声，反而稀释了版本记录的信噪比。而一旦数据被触及（派发即意味着连接器将读取本地数据），任何规格变更都构成"看到数据后改方案"，正是要防的行为。

**备选**：提交即冻结——否决，理由如上。执行完成才冻结——否决，那时防护已失效。

### D2. 结局-暴露独立性 = 引用图检查，不做语义判断

**选择**：校验 `outcome` 定义所引用的变量集合与 `exposureArm` / `comparatorArm` 所引用的变量集合**无交集**。当规格使用 `IdentificationAlgorithm` 引用（`rws-algorithm-validation` change 引入）时做算法标识与编码集层面的交集检查；当规格仍为自由文本时**降级为警告**而非阻断。

**理由**：§2.7.4 的红线是"药品暴露不应作为结局定义的组成部分"。这在结构化引用下是可判定的（集合交集），在自由文本下不可判定（"心梗"和"服用 X 后心梗"的区别需要语义理解）。对不可判定的情形硬阻断，会产生大量假阳性并逼用户绕过校验——比不校验更糟。

**依赖**：本决策的完全生效依赖 `rws-algorithm-validation` 落地。这是 A → B 的实质依赖点。

**备选**：自由文本做关键词匹配——否决，假阳性率不可接受且易被绕过。

### D3. 冻结集 = 影响分析结论的字段，不是全部字段

**选择**：冻结 `designType` / `rationale` / `tte`（全部子字段）/ `matchingCovariates` / `allowedArtifacts` / SAP / 缺失值策略 / 敏感性分析声明。**不冻结** `title` / 描述性文本 / 目标参与方列表。

**理由**：版本控制的目的是防"改分析"，不是防"改错别字"。把标题笔误也纳入冻结会制造版本噪声。目标参与方列表不冻结是因为参与方可能因合约撤销而合法减少（D-DC-1 补偿语义），那是系统行为不是研究者行为。

**备选**：全字段冻结——否决，噪声大于收益。

### D4. SAP 必填按分析层级分级

**选择**：L2 / L3 / L4 任务 MUST 声明 SAP（显著性水平、检验效能、样本量假设、多重性校正）；**L1.5 单纯信号检测豁免**，但涉及多亚组比较时 MUST 声明 α 校正方式。

**理由**：§3.1 的 SAP 要求针对的是"信号评价"的因果推断，L1.5 失衡信号是**假设生成**而非假设检验，强制其填写检验效能没有方法学意义。但多重性问题在 L1.5 同样存在（扫多个药-事件组合本质是多重比较），故 α 校正按"是否多重比较"而非"层级"来判定。

**备选**：全层级强制 SAP——否决，会让 L1.5 信号扫描变得极其笨重且填写内容无意义。

### D5. 敏感性分析全报 = 声明与回传的集合对账

**选择**：规格中声明的每一项敏感性分析，其结果 MUST 全部随主分析回传；缺项时结果 MUST NOT 出具（fail-closed）。

**理由**：§3.5 报告要求原文是"完整报告所有敏感性分析结果"，且"结果与主分析不一致时须深入探讨原因"。选择性省略不一致的那一项，是最隐蔽也最有害的报告偏倚。集合对账是纯形式检查，可靠且无假阳性。

**注意**：这条约束的是"声明了就必须报"，不阻止研究者一开始就少声明几项。少声明是可见的（规格里能看到），选择性省略是不可见的——把不可见的问题转化为可见的问题，是这条设计的实质价值。

### D6. 报告口径补绝对风险

**选择**：`EffectEstimatePayload` 增绝对风险表达（率差 / 风险差 + CI）；§3.1 要求"提供风险估计（绝对风险 + 相对风险）的点估计值、假设检验结果（P 值）、置信区间"。

**理由**：当前只有相对量（`log_or` / `log_hr` / `ate`）。相对风险在基线风险极低时会严重误导——OR=3 在基线 0.001% 与基线 10% 时的公共卫生含义天差地别，而药品安全性信号恰恰常处于低基线区间。

**约束**：绝对风险需要基线率，出域时须确认其本身通过闸门（是聚合量，但可能触及小单元格）。

## Risks / Trade-offs

- **BREAKING 打断既有任务与 demo** → 存量 `cp_rws_task` 回填 `protocolVersion = 1`；既有 e2e / demo 任务定义补齐必填字段；分阶段：先加字段可选并告警，一个迭代后转必填。
- **冻结引发的用户摩擦**（改一个字段要开新版本）→ D3 缩小冻结集；UI 明确展示"哪些字段冻结后不可改"，在提交前而非提交后告知。
- **自由文本下 D2 只能降级为警告** → 依赖 `rws-algorithm-validation`；在其落地前，独立性校验的实际覆盖率有限，须在 EVIDENCE.md 如实标注为"部分承载"而非"已承载"。
- **Form 栈选型被本 change 逼出** → DESIGN.md §4 已标注 Form 原型栈未定（缺 `react-hook-form + zod`）。规格表单是本仓迄今最复杂的表单，选型须在本 change 内定并登记为 `D-UI-1`。
- **系统只判形式的边界被误解** → 用户可能以为"校验通过 = 研究设计合格"。UI 与文档必须明说：系统校验的是要素完备性与形式一致性，方法学合理性由研究者与伦理审查负责。

## Migration Plan

1. **阶段一（可选 + 告警）**：新字段全部可选；缺失时任务可执行但报告标注"要素不完备"。存量任务回填 `protocolVersion = 1`。
2. **阶段二（转必填）**：补齐既有 e2e / demo / Fly 上的任务定义后，`designType` + `rationale` 转必填，SAP 按 D4 分级转必填。
3. **阶段三（冻结生效）**：启用派发时冻结与变更拒绝。
4. 治理契约同步（见 proposal·Impact），`pnpm check:meta` 绿。

**回滚**：阶段三可单独关闭（冻结开关）而保留字段；阶段二回退为可选。字段本身不回滚（新增列无害）。

## Open Questions

- **DAG 结构化协变量分类（§2.7.5）是否单独立项？** 倾向是——它引入图结构与因果语义（时依混杂 / 中介 / 效应修饰 / 碰撞的区分直接影响调整集选择），与本 change 的"字段硬化"不同质。若不做，EVIDENCE.md 覆盖矩阵第 8 项将长期停在"部分承载"。
- **规格版本与数字合约版本如何关联？** 研究方案改版是否需要重新走合约授权？倾向：改动涉及 `purpose` 或扩大 `allowedArtifacts` 时须重新授权，其余不须——但这需要与 `digital-contract` 的语义对齐后确定。
- **阶段二转必填的时机由谁决定？** 涉及外部使用者（药企侧已提交的任务模板），需要一个通知窗口。
