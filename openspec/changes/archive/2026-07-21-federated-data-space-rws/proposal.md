## Why

MedTrust 当前是一个**中心化多租户数据平台**:原始数据被上传汇聚到中心库(`data-asset` + 单库 SQLite),隐私计算/区块链/国密作为模块挂在中心平台上。这与"可信数据空间"的定义性特征相反——按国家数据局《可信数据空间技术架构》(2025.4)及 IDS-RAM,数据空间的本质是**数据不出域、留在各参与方本地,靠部署在各方的连接器(Connector)按可强制执行的共识规则让数据"可用不可见"地流通**。

若不重构,项目会做成一个"换皮的数据中台",无法对齐国家级可信数据空间标准,也无法获得医院对"数据不出院"的信任。

本次变更将架构定位从"中心化平台"转为"联邦数据空间",并以**药企-医院真实世界研究(RWS / 药物警戒)**作为最小切口跑通核心闭环——这是国家数据局医保试点已验证、药企有明确付费动机的场景。

## What Changes

- **新增连接器(Connector)** —— 部署在每个医院/药企本地的核心组件:本地数据网关(FHIR 适配)、本地脱敏、策略执行点(PEP)、本地 TEE 计算执行、审计代理。原始数据永不离开参与方本地。
- **新增输出闸门(Output Gate)** —— 只允许聚合统计/模型参数/红旗信号离开连接器(差分隐私 / 小单元格抑制),原始行级数据永不出域。
- **新增 RWS 任务编排** —— 药企发起研究任务(队列定义+分析逻辑)→ 中心校验合约与授权 → 下发到相关医院连接器 → 本地 TEE 执行 → 仅回传聚合结果 → 结果哈希上链存证。第一版仅支持 TEE 通道(联邦学习留作后续通道)。
- **BREAKING** 重构 `data-asset`:从"数据汇聚"拆为「中心只存元数据目录」+「连接器持有真实数据」。
- **BREAKING** 重构 `access-request`:从"一次性审批"升级为 **Usage Control(持续使用控制)**——授权后仍随数据强制执行的策略(目的限定、留存策略、输出约束)。
- 增强 `auth`:加入**主体+数据双认证、数据确权、分级分类**(对齐医保试点四维规则:准入/授权/安全/审计)。
- 中心数据库降级为控制面元数据小库,**不再作为数据汇聚库**。
- 复用既有技术储备(国密 SM2/3/4、TEE 模块、FISCO BCOS 存证、FHIR)下沉为连接器原语。
- **后置(本变更不实现)**:贡献挂钩的结算/激励(价值共创层)、与其他数据空间互联(预留接口)、前端改造。

## Capabilities

### New Capabilities
- `data-space-connector`: 部署在参与方本地的连接器——本地数据网关、脱敏、策略执行点、本地计算执行、审计代理;连接器与中心控制面、连接器之间的可信通信(国密)。接口对齐《数据基础设施 接入连接器技术要求》NDI-TR-2025-05。
- `digital-contract`: 数字合约——授权的标准载体(数据产品/双方/目的/留存/输出/有效期/状态机),是 `usage-control` 的强制执行对象(对齐《可信数据空间 技术架构》"数字合约管理")。
- `usage-control`: 使用控制——数字合约的持续强制执行(目的限定、留存约束、输出约束),取代一次性访问审批(对齐 TC609-6-2025-15)。
- `data-product`: 数据产品——连接器对外提供数据产品(元数据/分级分类/确权)而非裸数据集;RWS 输出亦作为数据产品管理并可溯源到数字合约与存证。
- `rws-compute`: 药企-医院真实世界研究计算闭环——RWS 任务定义、合约校验、任务下发、本地 TEE 执行、输出闸门(差分隐私/单元格抑制)、结果上链存证。
- `participant-identity`: 主体+数据双认证、数据确权、分级分类、国密证书/CA;身份登记/认证接口对齐《数据基础设施 用户身份管理和接入规范》NDI-TR-2025-03。
- `space-interconnect`: 跨空间互联——数据产品全局标识、跨域身份互认(联邦信任清单)、目录联邦、跨空间任务执行(数据不出源连接器),对齐 NDI-TR-2025-02/03。
- `value-settlement`: 价值共创——数字合约计价、按贡献度计量、结算与按贡献分配、结算上链与按角色查询,对齐"数据二十条"三权分置/按贡献分配。

## Impact

- **代码**:新增 `apps/connector/`(连接器);重构 `apps/api/src/data-asset`(拆为元数据目录)、`apps/api/src/access-request`(→ usage-control)、`apps/api/src/auth`(双认证/确权);中心 API 去除数据汇聚逻辑。
- **复用**:`apps/api/src/security`(国密)、`apps/api/src/privacy/tee`、`apps/api/src/blockchain`(FISCO BCOS)、`apps/api/src/fhir` 下沉为连接器原语。
- **数据**:`packages/database` 拆分——中心控制面元数据 schema(目录/合约/身份/存证)与连接器本地 schema 分离;中心库不再持有原始医疗数据。
- **部署**:从单体平台部署,转为「中心控制面 + N 个本地连接器」的分布式部署模型(连接器需可在医院内网/药企侧独立部署)。
- **标准对齐**:架构需对齐国家数据局《可信数据空间技术架构》三大核心能力(可信管控/资源交互/价值共创)及医保试点四维规则。
- **不影响**:既有 Fly.io 的 `medtrust-lite` 演示栈(独立 mock,与本变更无关)。
