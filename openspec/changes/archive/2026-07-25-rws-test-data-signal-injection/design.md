## Context

RWS 阶梯需要一份**带已知真值信号**的测试数据,才能演示"管道把注入的信号复原出来"。已实测:Synthea 默认数据无胰腺炎、无药→AE 因果,连接器 loader 拿共病假冒 AE。本 change 用受控注入替换假信号。

关键约束(均已实测确认):
- **事件数,不是人头,决定合格**。10k 队列 @ ~7% 发病率 → ~700 事件,两院分列后每站 ~350,四格全过闸;200 队列仅 13 事件,过不了闸。
- **队列 = 糖尿病人**。若 10k 是随机人口、仅 ~15% 糖尿病,有效队列塌到 ~1500,事件不够。
- Synthea 本地 JAR 可跑(`java -jar`,免 Docker);但 `-m` 模块标志需修正(实测那次糖尿病产 0)。

## Goals / Non-Goals

**Goals**
- 一份 10k 队列测试数据,含**注入的三重结构**:信号(L1.5/L2)、混杂(L3)、错分(L0),各方向正确。
- **answer key**:记录注入的真值(HR / 混杂 / 真实病态 / Se-Sp),供 e2e 断言复原。
- 注入逻辑**可 jest 单测**、确定性(seeded)。

**Non-Goals**
- 不追真实流行病学率(拔高发病率靠溯源标注兜底)。
- 不用 FAERS / GMF(见 proposal Non-Goals)。
- 不碰 RWS 阶梯计算逻辑。

## Decisions

### D1. 注入层用 TS,不用 Synthea GMF 模块

**选择**:Synthea 只产**真实人口基座**(人口学/共病/就诊/化验);信号(暴露臂/胰腺炎/时间/编码噪声)由**独立 TS 注入层**在基座之上注入。

**理由**:验证"数据合格"需**精确知道注入真值并断言复原**。TS 注入层可 jest 单测、精确控 HR/Se/Sp、真值显式落 answer key;GMF 模块据 Meeker 2022 需迭代 6 版、只支持单变量分布、真值藏在 FHIR 里难断言。对"可验证的测试数据"这一目标,TS 更短更可控(用户 instruction #2)。

**备选**:纯 GMF(否决:脆、真值隐式);纯合成无 Synthea 基座(否决:丢真实协变量与 FHIR 摄取路径演示)。

### D2. 数据生成模型(注入的真值 = answer key)

**选择**:逐患者 logistic 生成,参数即 answer key:
- 混杂 `Z` ~ Bernoulli(0.30)(如胆石史)。
- 暴露分配(混杂 by indication):`P(暴露=X) = clamp(0.5 + 0.2·Z, 0, 0.95)`——高危 Z 更易被开 X 药。
- 真实胰腺炎:`logit(p) = ln(0.03/0.97) + ln(2.5)·暴露 + ln(2.0)·Z`(基础率 3%,暴露真 HR 2.5,混杂 OR 2.0)。
- 发病时间:暴露窗内按注入 hazard 采样(供 L3 Cox/KM)。
- 编码噪声:`观测 = 真? Bernoulli(0.88) : Bernoulli(0.02)`(Se 目标 88%、Sp 目标 98%,供 L0)。

**理由**:这套参数实测产出三重偏倚方向全对——信号(合并 OR≈2)、混杂(crude 2.03 > 分层 MH 1.87)、错分向零衰减(观测 OR < 注入 2.5)。**参数即答案键**,e2e 直接拿它断言复原。

**注意(诚实)**:观测 OR(~2.0)**低于**注入 HR 2.5,是编码噪声的**非差异错分向零衰减**——这是**正确**的流行病学现象,不是 bug,且正好证明 L0 的价值。e2e 断言须**容许这个衰减**(断言"信号存在且方向对 + Se/Sp≈注入",不断言"OR 精确等于 2.5")。若要 L3 混杂演示更醒目,可调强 Z 效应(留作参数)。

### D3. 队列规模默认 10k,验收以事件数计

**选择**:默认 10k **队列内**患者(糖尿病人),两院各 ~5k;验收标准 = **每站真事件数 ≥ 300**(实测 10k → ~350/站)。

**理由**:合格与否由事件数决定。10k 舒服;可下探(~5k 实测仍过闸,格 >5),但 DoD 守的是事件数阈值,不是人头。

**生成含义**:须保证 10k 落在糖尿病队列内——**强制糖尿病基座**(修正 Synthea 模块配置)或**超量生成再筛**。design 倾向前者(生成即队列,省算力)。

### D4. answer key 落盘,e2e 对拍

**选择**:注入时落一份 `answer-key.json`(注入 HR / 混杂 OR / 基础率 / Se-Sp / 每站真事件数)。e2e 读它断言管道复原(容许 D2 的衰减)。

**理由**:测试数据的价值在"知道正确答案"。answer key 让 e2e 从"跑不崩"升级为"**复原了注入的真值**"——这才是"管道对不对"的真验证。

### D5. 溯源标注,不得用于申报

**选择**:每记录标 `provenance: synthetic-injected`;UI/报告顶栏 amber 警告(复用现有 §7.3 标签契约)。拔高的胰腺炎率(3–7% vs 真实低得多)MUST NOT 被当真实流行病学读。

**理由**:合成 + 拔高率 = 双重"不真实",必须显著标注,否则误导。

## Risks / Trade-offs

- **丢 FHIR 摄取路径演示**:注入层在基座之上,若直接产 InternalRecord 会绕过 FHIR→deid 路径。缓解:注入写回 FHIR-ish 或 ingested 形状,保留摄取演示;或明确 demo 分两段(FHIR 摄取用基座、信号复原用注入队列)。design 落地时定。
- **观测 OR ≠ 注入 HR 引困惑**(D2):e2e 断言与文档必须说清"衰减是对的"。
- **Synthea 模块配置坑**(实测 `-m` 产 0 糖尿病):基座生成须先跑通糖尿病队列,列为 tasks 第一项。
- **10k 数据体量**:约几十 MB ingested,连接器 SQLite 可承受;不落 2GB FHIR(注入队列走 ingested 形状)。

## Migration Plan

1. 修正 Synthea 基座生成(糖尿病队列真生成)。
2. 写 TS 注入层 + jest 单测(断言注入 HR/Se/Sp ↔ 产出四格/混淆矩阵)。
3. 落 answer key;两院切分。
4. 连接器 loader 下线 `deriveAdverseEvents`,接注入 AE;L0 金标准接注入真值。
5. e2e 改消费新数据,断言复原(容许衰减)。
6. 治理契约同步(D-DATA-1 / EVD-05 / TRUST 溯源 / FLOW-RWS-05),`pnpm check:meta` 绿。

**回滚**:测试数据层独立,可切回旧 loader 行为(保留开关一个迭代)。
