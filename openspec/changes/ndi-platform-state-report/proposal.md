# 平台运行状态上报（连接器状态聚合 → 区域/行业功能节点）

> 上游：TC609-6-2025-16 §6.2 c)（**平台**运行监测：接收连接器状态，并**向区域/行业功能节点上报接入连接器状态**）；TC609-6-2025-11（区域/行业功能节点每 5 秒接收心跳）；NDI-TR-2025-05 §6.2.6（连接器标准能力，适用于**注册单元**）
> 前序：`tc609-p1-heartbeat`（已落地：连接器 → 平台，60 秒）

## Why

先纠正一个归属：**向区域节点上报状态的是平台，不是每家医院的连接器。**

- TC609-6-2025-16 §6.2 c) 的原文把两件事都放在**平台**侧：「应支持**接收**接入连接器上报的运行状态……应支持**向区域/行业功能节点上报**接入连接器状态」。
- TC609-6-2025-11 的「每间隔 5 秒接收心跳」是**区域/行业功能节点**的接收要求，对端是**在该节点注册的单元**，不是空间内部的每一个院内节点。
- NDI-TR-2025-05 §5 a) 要求连接器「对接重要功能设施」做状态上报——这适用于**直接挂在国家基础设施上的接入连接器**；可信数据空间形态下，连接器对接的是本空间的**服务平台/业务节点**，由平台代理向上。

现状：

- 连接器 → 平台：已有，`HEARTBEAT_INTERVAL_MS = 60_000`，POST `/connector/heartbeat`（`apps/connector/src/domain/connector-worker.service.ts`、`apps/connector/src/tee-node/registration.ts`）。**这条够用，不必为 5 秒口径改造。**
- 平台 → 区域节点：**完全缺失**。平台只有 `reportAudit`（审计摘要）与 `pushCatalog`（目录）两条出站，没有任何状态上报。
- 平台侧没有「连接器状态」的正式聚合视图（离线判定、水位、任务数）供上报使用。

**不做的代价**：区域节点侧看不到本空间的连接器状态；16 §6.2 运行监测（扩展级）与 11 的接收要求都对不上。

## What Changes

1. **平台侧状态聚合**（`apps/api`）：
   - 以现有心跳为输入，维护 `connector_state` 视图：在线/离线（3 个心跳周期无上报即离线，可配置）、版本、任务数与阶段、资源水位。
   - 对外提供一个**聚合快照**：`{connectorId, ndiId, status, lastSeenAt, version, load}`。
2. **平台 → 区域节点上报适配器**：
   - 新增 `RegionStateReporter`（可配置 endpoint/鉴权，随 `docs/丝路数港-接口对拍表.md` §4 接口文档）；
   - 周期缺省 **5000 ms**（`REGION_STATE_REPORT_INTERVAL_MS`），载荷 = 平台自身状态 + 连接器聚合快照 + 空间标识（NDI-TR-2025-04 编码）；
   - 未配置时**不上报但不报错**，在系统状态页显示 `regionReporting: "unconfigured"`。
3. **能力声明**：平台在注册/上报时声明本空间的能力集（哪些连接器以什么形态接入、哪些 05 标准能力归属注册单元）。
4. **注册形态登记**：明确本空间的注册单元是**平台（业务节点）**，医院侧节点为空间内部节点、不单独注册为接入连接器——这条写入文档后，05 的标准能力才不会被逐条套到院内机器上（见差距文档 §3）。
5. **连接器侧只做一件小事**：心跳载荷补 `connectorId` 的 NDI 标识（与 `ndi-identifier-alignment` 联合），其余不动。

## 不做（范围外）

- 不把心跳周期改成 5 秒（那是区域节点的接收口径，不是连接器→平台的内部要求；如需更快聚合可单独调 `CONNECTOR_HEARTBEAT_INTERVAL_MS`）。
- 不做区域节点侧的「停用/筛选」管理界面（节点侧能力）。

## 离线可用性（外部未对接时必须成立）

> 现网尚未对接丝路数港。本变更不得把基线抬高为「必须有外部才能跑」。总闸见 [`ndi-external-absent-e2e`](../ndi-external-absent-e2e/proposal.md)。

- **未配置即 noop**：`RegionStateReporter` 缺 endpoint 时装配 `NoopRegionReporter`（**不是** `FailClosedSilkRoadClient`），只 `warn`，不抛、不计错误率。
- **独立预算**：上报循环独立定时器与超时预算（单次 ≤ 5s），不与长轮询共用线程/超时；失败退避 + 熔断，绝不阻塞连接器领任务。
- **聚合不依赖外部**：平台侧连接器状态视图只吃心跳输入，外部缺失时照常可用。
- **启动不失败**：外部未配置只记 warning，禁止让 API 启动失败。

## Impact

- 代码：`apps/api/src/runtime/connector-*`（聚合视图）、新 `runtime/region-reporting`、`apps/connector`（心跳载荷补标识）、`DEPLOY.md`（新增变量）。
- 兼容：不改长轮询；院内机器出站口不新增目的地（上报由平台发起）。
- 风险：区域节点地址/鉴权未定时通道处于 `unconfigured`，**不得**在材料里写成"已向区域节点上报"。

## 验收

- [ ] 停掉任一连接器，平台 3 个心跳周期内标记离线，并在聚合快照中体现。
- [ ] 区域上报适配器可按 5s 周期发出（mock 端点可观测），载荷含平台状态 + 连接器快照 + NDI 标识。
- [ ] 未配置时主链路不受影响，系统状态页显示 `unconfigured`。
- [ ] 文档写明注册单元为平台，医院侧节点不单独注册为接入连接器。
