## Context

- 已有能力：MDOP 作业（jobs → fragments → tickets → stages）、C2 封装（`seal.envelope`）→ 可信空间节点（teeA，阿里云 g8i Intel TDX）→ 会话证明（TDX quote V5，Intel PCS 背书链）→ 校验方/试点 KMS（teeB）按证明释放密钥 → 节点内 Wasm 执行 → 发布审查（minCell）→ C3 出域 → 回执链上链（长安链）→ 销毁。场景 1（两院胰腺炎配对队列）已在该链路上真跑。
- 场景 1 的短板：两院各自持有暴露与结局，协同计算（各算各的、只出聚合）也能做，「为什么非 TEE 不可」讲不清。
- 公共卫生里的典型反例：疫苗接种登记在疾控，就诊记录在医院；安全性信号判定依赖**同一个人两边日期之差**。

## Goals / Non-Goals

**Goals:**
- 在现有 C2 链路上增加一个「协同计算做不到、TEE 能做到」的真实场景：疾控 × 医院的 mRNA 疫苗接种后心肌炎/心包炎 SCRI 主动监测。
- 全链真跑：真实 TDX quote、真实密钥释放、节点内真实 Wasm 模块、结果与答案键逐格一致、销毁 + 上链。
- 结果解读（至强 6 推理机，Qwen3-1.7B int4）对 SCRI 输出可用：数字与结论都不能错。

**Non-Goals:**
- 不做真实疫苗安全性结论；数据全部合成，信号为注入。
- 不做时间变化混杂调整（季节、年龄随时间）、不做条件泊松回归/多剂次模型；只做 SCRI 计数 + 精确区间。
- 不做机密推理（模型不进 TDX）；不做生产 KMS；不做节点 OS 加固（RTMR、关 SSH，另立项）。

## Decisions

### D1 设计选 SCRI（自身对照风险期），不选队列/病例对照
只用受种者自身：比较同一人风险期与对照期的事件数。不需要未接种对照人群（疾控登记只有受种者），自动抵消不随时间变化的个体混杂。RI = (风险期事件/风险期天数)/(对照期事件/对照期天数)；95% CI 用条件二项 + Clopper-Pearson 精确法（风险期占比 π 的区间换算成 RI）。

### D2 窗口：风险期接种后第 1–7 天，对照期**接种前**第 42–22 天
mRNA 两剂间隔约 21 天，若对照期放在接种后第 22–42 天，会与下一剂风险期重叠、同一事件被重复计入。接种前对照期避开重叠；代价是「健康受种者效应」（身体不适者推迟接种，对照期事件偏少、RI 偏高）——事实清单与解读里如实写出。模板拒绝重叠窗口（模块返回码 5，模板层先拒）。

### D3 为什么必须 TEE（选型依据，写进对外物料）
| 方案 | 能否做 | 原因 |
|---|---|---|
| 数据不出域 / 协同计算 | 否 | 风险期计数需要逐人「事件日 − 接种日」；疾控无事件日、医院无接种日，任何一方单独算不出，只能交换行级日期（C0）——越线。 |
| 联邦学习 | 否 | 联邦学习横向切分同构样本训练模型；这里是**纵向**逐人连接 + 计数，不是训练问题。 |
| MPC | 理论可、工程不可行 | 万级剂次 × 隐私集合求交 + 逐对日期差比较 + 分层计数，电路规模与轮次在试点资源下不可接受；且算子换一个就要重写电路。 |
| TEE（C2） | 是 | 两方只封最小投影（关联假名 + 日期差所需日期 + 分层键）进 TDX，节点内连接计数，只出过闸聚合（C3）。 |

### D4 最小投影 + 编码白名单（封装阶段）
- 疾控封 `scri-registry`：`{linkKey, ageBand, sex, immunizations[{code∈vaccineCodes, date}]}`；医院封 `scri-events`：`{linkKey, datedEvents[{code∈eventCodes, date}]}`。编码白名单来自阶段参数（CVX 207/208；ICD-10 I40.9/I30.9），不在白名单的接种与就诊不出院。
- 关联假名 `linkKey` 由各机构用同一把盐从身份标识派生（演示：`sha256(盐‖Synthea Id)` 前 20 位）；院内假名 `subjectKey` 彼此不同、不出院。

### D5 模块 ABI `scri@1`（四参 `run(inOff, n, k, outOff)`）
头部 20 字节 i32：`[riskStart, riskEnd, controlStart, controlEnd, doses]`；随后 `i32 dayDiff[n]`、`u8 pairStratum[n]`、`u8 doseStratum[doses]`；输出 `k × {riskEvents, controlEvents, doses}`（u32）。主体键、日期、编码文本、分层键文本**留在宿主**，模块只见数字列。宿主回填后校验不变量（窗口内事件 ≤ 配对数；剂次合计 = 输入剂次）。

### D6 发布审查口径
每层 `buckets[].count = min(非零的 riskEvents, controlEvents)`，按 minCell（演示 5）判；任一格偏小整层抑制，抑制层所有数值字段置零。**不出合计**（合计 − 未抑制层 = 被抑制层）。

### D7 解读：结论前置 + 结论一致性回查
实测（LLMA qwen3-1.7b，temperature 0）：只给逐层明细时，模型把唯一显著的「40 岁以下男性 RI 4.45（2.71–7.39）」说成「均未达到统计学显著性」；数字回查拦不住（数字都在清单里）。处理：
1. 事实清单第 3 行放**确定性归纳的结论**（「4 个分层中，『40 岁以下男性』风险期发生率高于对照期（…）；其余 3 个分层无统计学差异」），模型只转述；
2. `contradictedVerdicts()`：有分层「高于」而草稿无「高于」、有「低于」而无「低于」、方向不一时出现「均未/都无」等一概否定 → 422 拒收。
复测同一输入草稿正确，两道闸均通过。

### D8 合成数据：Synthea 接种史 + 注入信号
Synthea（6892 人）给出人群、性别、出生日期与接种史（CVX + 日期）；Synthea 不模拟不良反应，心肌炎/心包炎就诊按固定种子注入：医院覆盖 70%；基线日发生率 λ0 = 1e-3（为统计功效放大，远高于真实）；仅「<40 岁男性」mRNA 剂次在第 1–7 天按 (RI−1)·7·λ0 额外产生事件，真 RI = 4。答案键按与算子同一口径计算。

## Risks / Trade-offs

- [注入信号被误读为真实风险] → 物料每处标注「合成数据 + 注入信号，不代表任何疫苗真实风险」；对外红线以 `tdx-attestation-pilot/external-claims.md` 为准。
- [健康受种者效应使 RI 偏高] → 事实清单固定说明；生产需敏感性分析（接种后对照期、剔除接种前 14 天）。
- [结论回查是关键词规则，不是语义理解] → 只拦明确矛盾；草稿始终标注「待研究者确认」，事实清单与草稿并列展示。
- [TCB OutOfDate（阿里云 TDX 平台）] → 试点策略最低 TCB 5.1.3 按实测设置；如实记录，不称「最新 TCB」。
- [校验方密钥只在内存] → 重启即丢，在途作业需重提（DEPLOY §4.5 已登记）。
- [节点 OS 运营方] → TDX 保护的是对云宿主/虚拟化层隔离，TD 内 root 仍可见内存；对外不得称「节点运营方也看不到」，节点加固另立项。
- [查询预算] → 每次真跑扣疾控数据集预算 1/5；演示重跑次数受限。
