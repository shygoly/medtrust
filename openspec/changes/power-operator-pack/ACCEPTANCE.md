# 电力算子包验收标准

## 概述

本文档定义电力算子包（`@medtrust/domain-power`）的验收标准，确保包的功能完整性、性能指标、隐私保护和文档质量满足生产就绪要求。

## 1. 功能完整性

### 1.1 核心场景可运行

#### 负荷预测场景
- [ ] 端到端流程可运行：数据源 → 特征提取 → 脱密 → 聚合 → 预测
- [ ] 支持多方数据融合（电网 + 气象 + 工业用户）
- [ ] 预测输出格式正确（未来 24 小时逐小时负荷 + 置信区间）
- [ ] 预测精度可接受（MAPE < 5%，参考行业基准）

#### 需求响应场景
- [ ] 端到端流程可运行：数据源 → 潜力评估 → 优化
- [ ] 支持多用户可调节负荷聚合
- [ ] 优化输出格式正确（各时段调节目标 + 激励分配）
- [ ] 削峰填谷效果可量化（峰谷差降低 ≥ 10%）

#### 窃电检测场景
- [ ] 端到端流程可运行：数据源 → 异常检测 → 跨区域聚合
- [ ] 支持多供电局数据协同
- [ ] 检测输出格式正确（疑似窃电用户列表 + 风险评分）
- [ ] 检测召回率可接受（Recall ≥ 80%，参考行业基准）

### 1.2 算子单元测试

#### power.feature-extraction@1.0.0
- [ ] 正确提取统计特征（mean / std / max / min）
- [ ] 正确提取周期性特征（hourOfDay / dayOfWeek / isWeekend）
- [ ] 正确提取趋势特征（trend / seasonality，STL 分解）
- [ ] 边界情况：空数据、单点数据、缺失值处理
- [ ] 性能：1000 用户 × 30 天数据，提取时间 < 30 秒

#### power.load-forecast-merge@1.0.0
- [ ] 正确聚合多方特征（按样本量加权）
- [ ] 预测模型收敛（训练 loss 单调递减）
- [ ] 输出置信区间合理（覆盖率 ≈ 95%）
- [ ] 边界情况：单方数据、特征缺失、样本量不平衡
- [ ] 性能：100 方 × 1000 特征，合并时间 < 10 秒

#### power.dr-potential@1.0.0
- [ ] 正确评估可调节负荷潜力（峰时/谷时可削减/转移容量）
- [ ] 考虑用户舒适度约束（温度、照明等）
- [ ] 输出潜力曲线与历史负荷曲线一致
- [ ] 边界情况：零潜力、满负荷、负荷波动剧烈
- [ ] 性能：1000 用户，评估时间 < 5 秒

#### power.dr-optimize@1.0.0
- [ ] 正确求解优化问题（混合整数规划/启发式算法）
- [ ] 满足削峰填谷目标（峰谷差最小化）
- [ ] 满足激励预算约束（总激励 ≤ 预算上限）
- [ ] 输出方案可行（各用户调节量 ≤ 潜力上限）
- [ ] 边界情况：无可行解、预算不足、单用户主导
- [ ] 性能：100 用户 × 24 时段，优化时间 < 1 分钟

#### power.anomaly-detection@1.0.0
- [ ] 正确检测典型窃电模式（零功率、负功率、功率突变）
- [ ] 支持多种检测算法（孤立森林 / AutoEncoder / 统计检验）
- [ ] 输出异常评分合理（正常用户 < 0.3，异常用户 > 0.7）
- [ ] 边界情况：全正常、全异常、新用户冷启动
- [ ] 性能：10000 用户 × 90 天数据，检测时间 < 10 分钟

#### power.theft-merge@1.0.0
- [ ] 正确聚合跨区域异常评分（加权平均/最大值/投票）
- [ ] 输出疑似窃电用户列表（Top-K 排序）
- [ ] 估计区域窃电率（异常用户比例）
- [ ] 边界情况：无异常、单区域主导、评分冲突
- [ ] 性能：10 区域 × 1000 用户，合并时间 < 5 秒

## 3. 隐私保护

### 3.1 算子隐私审查

#### power.feature-extraction
- [ ] 不泄露个体用电曲线（只输出聚合统计特征）
- [ ] 支持 k-匿名脱敏（k ≥ 5）
- [ ] 支持差分隐私噪声注入（可选，ε < 1.0）
- [ ] 隐私预算可配置（按合约条款）

#### power.load-forecast-merge
- [ ] 不存储个体特征（只保留聚合权重）
- [ ] 预测输出不可逆推个体数据
- [ ] 模型参数不泄露训练数据分布

#### power.dr-potential
- [ ] 不泄露个体用电行为（只输出聚合潜力）
- [ ] 可调节负荷潜力脱敏（按用户组聚合）

#### power.dr-optimize
- [ ] 优化方案不包含个体标识（用户 ID 脱敏）
- [ ] 激励分配按聚合维度（不细化到个体）

#### power.anomaly-detection
- [ ] 异常评分脱敏（Top-K 输出，不包含正常用户）
- [ ] 不泄露正常用户用电模式
- [ ] 窃电模式描述泛化（不精确到时刻）

#### power.theft-merge
- [ ] 疑似窃电用户列表脱敏（风险评分分段，不精确排序）
- [ ] 区域窃电率模糊化（≥ 1% 的粒度）

### 3.2 差分隐私验证

- [ ] 负荷预测场景：ε < 1.0（针对个体用电曲线）
- [ ] 需求响应场景：ε < 0.5（针对可调节负荷）
- [ ] 窃电检测场景：ε < 2.0（针对异常评分）

### 3.3 k-匿名验证

- [ ] 所有输出满足 k ≥ 5（至少 5 个个体聚合后才输出）
- [ ] 边界情况：小队列自动拒绝（fail-closed）

## 7. 验收流程

### 7.1 自验收（开发团队）

1. 运行完整测试套件：`pnpm test`
2. 运行性能测试：`pnpm test:perf`
3. 运行隐私测试：`pnpm test:privacy`
4. 生成覆盖率报告：`pnpm test:coverage`
5. 填写本文档各检查项

### 7.2 交叉验收（质量团队）

1. 独立运行测试套件（全新环境）
2. 代码审查（随机抽查 30% 代码）
3. 文档审查（完整性、准确性、可读性）
4. 安全审查（依赖扫描、代码扫描）
5. 性能验证（压测、资源监控）

### 7.3 用户验收（业务团队）

1. 端到端场景验证（三个场景各运行 3 次）
2. 输出结果验证（与预期对比、可解释性）
3. 文档可用性验证（按文档操作是否成功）
4. 反馈收集（可用性问题、改进建议）
