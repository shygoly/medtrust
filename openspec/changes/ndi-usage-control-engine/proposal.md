# 使用控制策略引擎（解析 / 四态决策 / 义务执行 / 效果核验）

> 上游：NDI-TR-2025-05 §6.2.4（数据访问控制）、§6.3.5（数据使用控制）；TC609-6-2025-15《数据流通利用 使用控制》
> 现状：PEP 为二值判定（`apps/connector/src/domain/policy-enforcement.ts`）、MDOP 本地七项复核（`mdop-review.ts`）、出域闸门（`output-policy.ts`）

## Why

国标要的「使用控制」是一个**策略引擎**，我方现在是**一组布尔检查**：

| 国标要求（TC609-6-2025-15） | 现状 |
|---|---|
| 策略支持：数据交付策略 / 使用过程策略（查看、复制、存档、分发、算法模型应用）/ 通用约束 | `outputPolicy` 只覆盖产物白名单 + `minCell`；无「查看/复制/存档/分发」语义 |
| 策略解析：完整性校验、语法解析、语义解析、**冲突检测**、可执行格式、策略存储 | 无策略语言，`resolveOutputPolicy` 是代码常量与预设 |
| 行为校验输出四态：**允许 / 有条件允许 / 拒绝 / 默认拒绝** | 只有允许/拒绝（抛 `PolicyViolation`） |
| 操作执行：**义务事项**（二次认证、水印、用后删除、过程通知）、**效果核验**（到期删除核验）、异常中止、容错重试 | 无；阅后即焚是任务级销毁，不是策略义务 |
| 使用存证：操作记录（含策略协商修改过程）、过程记录、日志查询、**存证上报** | 审计有（`tc609-connector-audit`、`tc609-p1-audit-chain-hash`），缺策略协商记录与上报调度 |

**不做的代价**：送检 §6.2.4/§6.3.5 判部分或不符合；更实际的是——合约里写"仅可查看不可下载"时，系统无法证明自己执行了它。

## What Changes

1. **策略语言（最小集）**：JSON 结构，落 `packages/space-kernel-spi`（或 `packages/mdop` 旁挂领域包）：
   - `grant`（主体/客体/动作）、`constraints`（时间窗、地点、次数、环境等级）、`obligations`（水印、用后删除、通知）、`version`
   - 与既有 `outputPolicy` 的关系：`outputPolicy` 成为策略的一个 section，不另起一套
2. **解析器**：完整性（SM2 签名/哈希）、语法（结构校验）、语义（动作与约束可组合性）、**冲突检测**（同一主体/客体/动作的互斥授予）、规范化存储（canonical + SM3）。
3. **决策引擎四态**：`ALLOW` / `ALLOW_WITH_OBLIGATIONS` / `DENY` / `DEFAULT_DENY`；未匹配任何策略或解析失败一律 `DEFAULT_DENY`（与现有 fail-closed 一致）。
4. **义务执行器**：按声明顺序执行（先条件后主体动作），执行失败即降级为 `DENY`；至少实现「用后删除」与「过程通知」两项，水印留接口。
5. **效果核验**：关键操作后核验（删除后不可读、产物哈希与策略绑定）；核验失败记审计并中止。
6. **存证上报**：策略解析结果、每次决策、义务执行结果写入审计链，并按 `ndi-platform-state-report` 的通道上报摘要。
7. **PEP 改造**：调用引擎替代布尔判定；保留旧路径开关（`USAGE_CONTROL_ENGINE=legacy|v1`）用于灰度。

## 不做（范围外）

- 不实现「应用程序隔离部署」「模型哈希校验」这类更大的运行时能力（05 §6.1.2.1 的一部分）——单独立项。
- 不引入外部策略引擎（OPA/Cedar）；先自研最小集，避免多一个运行时依赖。

## 离线可用性（外部未对接时必须成立）

> 现网尚未对接丝路数港。本变更不得把基线抬高为「必须有外部才能跑」。总闸见 [`ndi-external-absent-e2e`](../ndi-external-absent-e2e/proposal.md)。

- **默认 legacy**：`USAGE_CONTROL_ENGINE=legacy` 为缺省，未启用前 PEP 行为与现状逐条一致。
- **旧合约默认翻译为 legacy 语义**：无策略的旧合约**不得**被判为 `DEFAULT_DENY`（那会让所有历史任务一夜被拒），必须按改造前语义放行。
- **先 shadow 后生效**：shadow 模式下引擎判定只记录、不下结论，用于对账分歧；分歧清零后再逐合约灰度。
- **回退路径**：任一合约可单独回 legacy，不需要重启。

## Impact

- 代码：`packages/space-kernel-spi`（策略类型）、`apps/connector/src/domain/policy-enforcement.ts`（改造）、`apps/api/src/runtime/digital-contract`（合约→策略编译）、`packages/database`（策略存储/版本）。
- 兼容：`outputPolicy` 与合约条款不变；引擎对旧合约以默认策略翻译。
- 风险：策略语言一旦对外发布就是接口，版本字段必须从第一天就有（`version`），否则后期无法演进。
- 工作量：本组四个变更里最大，建议单独立 design.md 后再拆 tasks。

## 验收

- [ ] 同一主体/客体的互斥授予被冲突检测拒绝（负向用例）
- [ ] 四态各有正反例；未匹配策略返回 `DEFAULT_DENY`
- [ ] 义务事项按声明顺序执行，失败即 `DENY` 并留审计
- [ ] 「用后删除」有可核验证据（删除前后各一次读断言）
- [ ] 决策与义务结果进入审计链并可按合约 id 查询
- [ ] `USAGE_CONTROL_ENGINE=legacy` 下行为与改造前一致（回归）
