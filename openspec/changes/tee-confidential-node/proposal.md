## Why

MDOP 把出域形态分成三类：**C3 聚合出域**（已上线，L1.5–L3 与平台合并走这条）、**参数出域**（L4 的逻辑回归系数与 LoRA 增量）、以及**C2 受控流动**（数据以加密封装进入通过硬件远程证明的可信空间节点）。C2 的协议语义在 v0.2 里已写完整，但**默认关闭**（§4.2 R4 / D-MDOP-6）：任何 C2 边在编译期即以 `E_CAPABILITY_MISMATCH` 拒绝，因为它缺少硬件证明这一前提；连接器能力通告的 `tee` 字段恒为 `null`（**2026-09-26 更新**：判定开关已按本变更 §1.1b 翻转——C2 边改判「目标节点证明登记有效且与合约证明策略相符才可放置」；翻转的是判定方式、不是能力，无硬件证明时 C2 仍为零，详见 DECISIONS D-MDOP-6 开关翻转补注）。

关闭 C2 的代价是明确的：**有一整类研究问题在现有通道上无解**。协议 §4.5 判定的判据是「要算的函数是否可分解」——

- **跨院同一主体配对（join）**：A 院只有暴露、B 院只有结局，C3 下两院只能各报一个总数，**数学上无法求交**；
- **亚组与切点的重新计算**：分层维度在提交时冻结，追加一个亚组必须重跑整个作业；
- **非线性模型与影像/病理/文本**：只能退化成「模型下到各院各训一份再合并」，在非独立同分布数据上明显退化——现在 L4 只能是逻辑回归与 LoRA 增量，正是该约束的结果；
- **受预算约束的交互式探索**：每次探索都是一次新作业。

同时，**该前提今天已经具备**：海光 CSV / Intel TDX / AMD SEV-SNP 均有可用的远程证明链（DCAP / CSV 证明服务），KMS 释放密钥的工程模式已经成熟；本仓也已把缺口如实登记在 TRUST P-CTL-8。继续把 C2 挂在「等硬件」上，会让医院与药企在最需要协作的几类研究上被永久卡住。

本变更的定位是**打开 C2 这条通道**：把可信空间节点做成 MDOP 里的一等节点（有自己的身份、密钥、能力通告、证明、回执），把「数据出域」换成「**密文出域 + 只在不被信任方持有密钥的、被证明过的代码里解密**」。

**必须同时写清的一句边界**（TRUST P-CTL-8、协议 §4.5）：C2 落地后 MUST NOT 表述为「数据没有出医院」。它换的是**信任锚**（CPU 厂商证明根 + 代码度量 + 可信空间运营方 + 密钥释放策略），合规定性变成**委托处理 / 数据出域**，且内存访问模式的侧信道不在 TDX/SEV-SNP 的防护范围内。

## What Changes

- **可信空间节点成为 MDOP 的一等节点**（新能力 `trusted-space-node`）：
  - 参与方身份自持（自生成密钥、注册只提交公钥），与医院连接器同构；
  - 上线时出**远程证明**（quote + 代码度量 + TCB 版本）；度量白名单来自注册中心，与算子清单**同一套签名与吊销机制**；
  - 证明有有效期，每次会话重新证明；证明摘要与度量进入**执行凭证的签署范围**——各院签的是「在哪个度量下执行」。
- **协议落地 C2 的数据面**（`mdop-protocol` 增量）：
  - 数据信封 `mdop.env/1.0`：**AEAD 密文**（本期实现为 AES-256-GCM，`cipher` 字段如实标注；**国密 SM4-GCM 未落地**，属对 D8 的临时偏离，见 D8 落地补注）+ 封装密钥引用 + 使用策略（合约、用途、允许算子、证明策略、`export: C3_only`、有效期）+ 水印 + 持有方签名；
  - `seal` 算子（类别 `local`，机制型）把本节点 C0 封装为 C2 信封；**只有 `seal` 能产生 C2**（R4）；
  - C2 边校验补齐：目标节点须通告 `tee` 能力且满足合约 `attestation_policy{tee, min_tcb, allowed_measurements}`；
  - 密钥释放协议：KMS 校验「证明有效 + 度量在允许清单 + 与凭证所指片段一致 + 凭证有效 + 合约未终止」才用**一次性公钥**加密数据密钥返回；密钥只存在于该 TEE 实例内存，实例退出即失效。
- **平台侧打开 C2 编译与登记**（`orchestration-kernel` 增量）：
  - 新增 `cp_mdop_attestation`：登记节点的 quote 摘要、度量、TCB、校验时间与有效期，并把证明摘要上链；
  - 编译器允许把 C2 边/阶段放到**通过证明且证明未过期**的可信空间节点；证明过期即拒；密钥不存在时 fail-closed；
  - 调度器把可信空间节点当普通节点下发阶段指令；销毁编排（`PurgeOrder`）**覆盖可信空间节点**，收齐全部回执才进 `PURGED`。
- **连接器侧出口守卫扩展**（`node-artifact-lifecycle` 增量）：出口从「只投 C3」扩展为「C3，或（C2 且目标为**证明有效的**可信空间节点且合约声明了该目标）」，并新增一条：**证明过期即拒投**。
- **本地复核同步收紧**（`local-plan-review` 增量）：七项复核的第 4 项要求 C2 目标不仅在合约声明内，而且其证明 MUST 由**本地独立校验**——MUST NOT 只凭平台侧的证明登记放行（复核只认本地可验证的输入，与其余六项同一原则）。
- **节点内的发布审查与查询预算**（本变更的硬约束）：发布审查（minCell + 二次抑制）与查询预算账本必须在可信空间节点**内部由被测代码强制**，而不是靠运营方自觉。缺少它们，C2 会退化成「把医院数据库的远程终端交给申请方」，其后果与直接出明细同级。**ε-差分隐私加噪不在本变更范围**（TRUST P-CTL-3 待接入）：节点只如实记录 `dp` 声明，`mode=epsilon` 不代表已加噪。
- **治理同步**：
  - 修订 **D-MDOP-6**（判定开关翻转为「目标节点证明有效才可放置」，附运营方与 KMS 归属前提；翻转的是判定方式，无硬件证明时 C2 仍为零）与 **D9**（`attestationLevel` 的如实标注口径：可信空间节点为硬件证明，院内连接器仍为 software）；
  - **TRUST P-CTL-8 → 正册 CTL-29**（远程证明与密钥释放：enforcement + 负例 + evidence）——**enforcement 符号与 spec 路径已齐（2026-09-26），但转正条件另含「真实证明代理与真实 KMS 落地并跑通 §9.2/§9.3 演练」**，未满足前继续留在待接入表；
  - **FLOWS.md 新增 FLOW-MDOP-02**（C2：seal → 证明 → 释放 → 节点内执行 → 只出 C3 → 销毁 → 锚定），并在跨域边说明里补 C2 的 crosses/payload 口径；
  - **DOMAIN.md** 新增实体（可信空间节点、证明记录、C2 信封、查询预算）与状态词汇；
  - **ARCHITECTURE.md** 的 C2 段落从「本期关闭」改为「**放置改判目标节点的证明登记；无硬件证明的部署里仍为零**」（附信任锚与运营方约束；不使用「默认关闭/已打开」这种会被误读为能力的二值措辞，两层状态分开写）；
  - `node scripts/check-meta-docs.mjs` 保持 0 error。

**本期不做**（后续变更）：
- **C1（MPC / 安全聚合 / PSI）**：C1 与本变更正交，SPU/MP-SPDZ 网关接入另立变更；
- **多可信空间节点互联**（节点间 C2 中转）与**跨空间**（`cross-space` 信任清单互通）；
- **GPU TEE 上的大模型训练**：本期只做统计与降密类算子，影像/文本多模态的工程化留到后续；
- **真实患者数据**：本期全部演练用合成数据；上线真实数据前须完成 REG 合规路径（委托处理/出域）与医院书面接受运营方。

## Capabilities

### New Capabilities
- `trusted-space-node`：可信空间节点的身份与证明、证明绑定的密钥释放、节点内执行与发布审查、只出 C3 的出口、销毁与回执、失败模式 fail-closed。

### Modified Capabilities
- `mdop-protocol`：C2 数据信封 `mdop.env/1.0`、`seal` 算子、`attestation_policy`、C2 边校验、密钥释放协议、查询预算与发布审查的协议要求。
- `orchestration-kernel`：C2 编译与放置、证明登记与生命周期、凭证纳入证明摘要、调度与销毁覆盖可信空间节点、平台不得接触数据密钥。
- `node-artifact-lifecycle`：**修改「C0 不出节点」**——出口从「只投 C3」放宽为「C3，或投给合约声明且证明可本地校验的可信空间节点的 C2」；C0/C1 仍然一律不出；新增 C2 制品入节点与句柄、节点内制品 TTL 与销毁回执。
- `local-plan-review`：**修改「七项本地复核」**——C2 目标须由本地合约声明且证明可被**本地独立校验**（不得只信平台登记）；DP 预算条款改为「医院连接器本地不申请预算，节点侧查询预算由节点自记账」。

## Impact

- **代码**：`packages/mdop`（信封/算子/凭证 schema）、`apps/api/src/mdop`（编译、证明登记、调度、销毁）、`apps/connector/src/mdop`（seal、出口守卫）、新组件 `apps/tee-node`、KMS 侧策略引擎；`apps/web` 的合约证明策略与作业详情。
- **部署**：新增可信空间节点与 KMS 两个组件；主机须具备可用的证明链（CSV/TDX/SEV-SNP）；节点网络只接受来自持有方连接器的出站投递。
- **合规**：数据出域性质变化 → REGULATORY 需新增委托处理路径；TRUST 威胁模型新增「可信空间运营方」这一敌手面。
- **既有链路**：不影响已上线的 C3 通道；同一条作业可混用（院内本地算 C3 + TEE 内算 C2→C3）。
