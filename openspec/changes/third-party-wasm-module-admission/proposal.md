## Why

`connector-wasm-sandbox-disproportionality` 建起了「平台签名 Wasm + 合约固定 SM3 + 能力受限沙箱」的执行机制，但只覆盖平台自研、单一 AssemblyScript 模块。D-CN-2 真正要防的「外来算法代码」还没有准入路径：第三方（药企 / 学术方）无法把自己的分析算法跑到院内数据上，只能提交参数、跑连接器自带代码。要让「算法可插拔、不逐院重部署」落地，缺的是一套准入机制——谁能提交、用什么语言、怎么审、怎么测、怎么发布、运行时怎么兜底、坏了怎么撤。

## What Changes

- **源码语言支持扩到两种**：Rust 与 AssemblyScript 的**源码**，均由**平台侧锁定工具链复现构建**出 `.wasm`。第三方提交的是源码，不是二进制。
- **准入只设两层，明确不设第三层**：
  - **Tier A**：平台自研模块（全源码 + 平台工具链）。
  - **Tier B**：第三方交源码，平台**复现构建 + 审查**，SM3 来自可读源码。
  - **（移除）Tier C 不透明第三方二进制**：SM3 必须由平台从源码复现产出——复现不出即无法入册，从**机制上**排除不透明二进制，而非靠政策拒绝。零能力沙箱里，黑盒二进制无法审「它到底干什么」，与「医院审过、同意跑这一份」的核心承诺相悖，且黑盒测试永远不完备（可测试数据上乖、真实数据上作恶）。
- **保密审查通道（IP）**：第三方可在 NDA 下把源码交平台审 + 构建，源码不公开，对医院只公开 `SM3 + 平台审查背书`。「要源码」不等于「要开源」。
- **准入五道闸（fail-closed，任一不过即拒，且不回退到内置实现）**：
  1. **静态白名单校验（不运行就挡）**：import 只允许宿主内存 + 窄数据 API（WASI / env / table / 共享内存一律拒）；export 签名固定、拒可疑 start 段；Wasm 特性白名单（禁 threads / 共享内存，按需禁 SIMD/GC/异常）；内存上限与模块字节大小上限。
  2. **复现构建 + 平台签名**：锁工具链、断网、hermetic 构建；两个独立构建器出**同一 SM3** 才算数；平台 SM2 CA 签这份 SM3。
  3. **沙箱内动态测试**：与独立参考实现**逐字段一致**；N 次 + 跨院运行时**确定性**；资源上限（超时 / 内存 / 指令预算 fuel）**确实触发**且只判任务失败、不波及连接器；**防外泄**（最小列投影 → 行序不变性差分 → 输出 schema 低熵约束 → canary 不可复原 → 过输出闸门）；malformed 输入模糊测试只能优雅失败。
  4. **影子发布**：先在一家医院真数据上「只算不发结果」，比对参考 + 看资源 / 输出形状，DPO 可查；干净后 canary → 全量。
  5. **运行时常态防护**：每次运行验 SM2 签名 + SM3 == 合约固定值 + 零导入实例化 + 过输出闸门 + 把模块 SM3 / `executionIsolation` 写进签名结果存证；**OS 层兜底**（seccomp 断 syscall、无网络命名空间、只读 FS、cgroup 限 CPU/内存）罩住沙箱 worker；引擎优先 **Wasmtime**（fuel + epoch 中断，比裸 V8 更适合跑不可信代码）；模块**可吊销**（撤签名 / 撤合约固定，凭 SM3 不符当场拒）。
- **治理登记**：新增 1 条 DECISIONS（`D-x`：只接受可复现构建的源码模块，不接受不透明第三方二进制，IP 走保密审查）；新增 1 个 TRUST 控制点（`CTL-x`：第三方算法准入闸）；DOMAIN 增补准入层级 / 审查背书词汇；D-CN-2 补注多语言与运行时兜底。

## Capabilities

### New Capabilities
- `third-party-module-admission`：第三方算法模块准入。覆盖两层准入（A / B，不设 C）、源码语言白名单（Rust / AssemblyScript）、平台复现构建、五道闸验收（静态白名单 / 复现构建+签名 / 沙箱动态测试 / 影子发布 / 运行时防护+OS 兜底+吊销）、保密审查通道。

### Modified Capabilities
- `digital-contract`：合约「固定算法模块」条款增加**准入层级**（A / B）与**平台审查背书**；这些字段计入合约哈希一起存证。
- `usage-control`：PEP 运行前增加**吊销检查**——模块被吊销（撤签名 / 撤固定）即拒执行。

> 前置依赖：`connector-wasm-sandbox-disproportionality` 提供的 `algorithm-sandbox` 执行机制。本变更在其之上扩展「多语言源码 + 运行时兜底 + 吊销」，故 `digital-contract` / `usage-control` 增量以该变更归档后的规格为基线，两变更有序落地。

## Impact

- **连接器**：`apps/connector/src/domain/sandbox/` 增加 Rust 模块加载 + 运行时兜底（OS 层 seccomp/cgroup、Wasmtime 适配、吊销检查）；执行前静态白名单校验（import / export / 特性 / 上限）。
- **控制面 API**：模块准入接口（源码提交、构建触发、审查状态、影子发布、吊销）；派发记录携带模块层级与审查背书；结果入库读执行标注。
- **平台侧构建**：`packages/wasm-algorithms` 增加 Rust 工具链（锁版本、hermetic、SM3 清单）；两独立构建器复现校验。仅开发依赖，不引入新运行时原生依赖。
- **数据库**（`packages/database` 控制面实体）：合约固定模块列增加层级 + 审查背书；新增模块吊销表。
- **前端**：任务详情显示模块层级（A / B）、审查背书、执行隔离与模块指纹。
- **部署**：连接器新增 OS 兜底配置（seccomp profile、cgroup 限额）与切 Wasmtime 的运行时依赖；平台侧构建器环境。
- **测试**：五道闸各自的验收用例（静态拒绝集、复现构建一致、动态一致性 / 确定性 / 资源 / 防外泄 / 模糊、影子比对、吊销生效）；「不接受不透明二进制」的负例（复现不出 SM3 即拒）。
- **治理文档**：DECISIONS `D-x`、TRUST `CTL-x`、DOMAIN 词汇、D-CN-2 补注。
