## Why

连接器目前**没有任何数据库接入能力**：`local-data-loader` 只会 `readdirSync` + `readFileSync` 读本地 JSON（`records.json` / FHIR bundle），`fhir-gateway` 是纯内存映射函数、自己不发起连接。真实医院的数据在 OMOP CDM 库里，不可能导成 JSON 交给连接器——**「接真实医院数据」这条路目前是断的**。

这一层必须落在连接器，不是别的地方：PEP、输出闸门、审计链都在连接器进程内，数据访问若在它之外（给 Wasm 开数据 API、或让 Python agent 另开一条连接），闸门就能被绕过，且会出现两个数据入口、两套守卫。

选 OMOP CDM 而非「通用数据库适配」，是因为 CDM 的表结构是**先验已知的规范**（v5.4 定死表名/字段/类型/主外键）。这让「不反射表结构就能生成 SQL」成立，也让同一份研究定义能跨院复用——这是联邦分析网络（DARWIN EU、EHDEN）能成立的技术前提。

## What Changes

- **连接器新增 OMOP CDM 数据源接入**，并明确为**唯一持有数据库连接的模块**。Wasm 模块 MUST NOT 获得任何数据访问能力（零导入不破）；Python agent MUST NOT 另开独立连接。
- **视图接入契约**：医院侧提供 schema 隔离的**视图层**（同名同结构模拟 CDM 表，去直接标识 + 行级过滤）+ 受限账号。经本地实测确认该契约可成立：底表不可达、视图不可写、行级过滤在研究方定义之前生效。
  - **纠正一个常见误解**：账号**不是纯只读**。队列定义 SQL 必须往 `results` schema 建表写 cohort，所以契约是「**CDM 视图只读 + results schema 可写**」两个权限域。按「只读」配置会导致首次上线即失败。
- **三参数配置替代元数据探测**：`cdmVersion` + `schema 名`（cdm / vocabulary / results）+ `dbms 方言`。不做表结构反射——CDM 结构由规范给定。
- **接入一致性校验（fail-closed）**：必需表存在、视图契约满足（不含直接标识列）、权限边界符合预期（底表不可达、视图不可写、results 可写）、`cdm_source` 与 `vocabulary_version` 可读。任一不过即拒绝接入，不降级为文件模式。
- **目录元数据自动产出**：数据产品目录的覆盖范围（表、年份跨度、记录数、CDM/词汇表版本）由连接器从库中统计产出，替代当前的人工登记。
- **SQL 执行通道 + 方言抽象接缝**：参数化 SQL 的执行入口，方言翻译留出接缝（第一版只实现 PostgreSQL）。实测确认方言翻译不可回避——SQL Server 方言的 `DATEDIFF` 在 PG 上需翻译，而国产库（达梦、人大金仓）连 SqlRender 都不支持。
- **`results` schema 留存治理**：中间结果会堆积在**医院自己的库**里，纳入既有 retention 约束。
- **连接器凭据管理**：数据库凭据只存在于连接器侧配置，MUST NOT 出现在控制面、任务载荷或派发记录中。

### 非目标（明确排除）

- **Circe 队列定义编译器**与 **FeatureExtraction 协变量提取**——另立变更。本变更只做「连上、验通、能执行参数化 SQL」。
- 不改变现有基于文件的数据路径（两者并存，按数据源类型分派）。
- 不实现 OHDSI SQL 全量方言翻译。

## Capabilities

### New Capabilities

- `omop-data-source`：连接器侧 OMOP CDM 数据源接入。覆盖视图接入契约（权限双域）、三参数配置、接入一致性校验（fail-closed）、SQL 执行通道与方言抽象、凭据边界、`results` schema 留存。

### Modified Capabilities

- `data-space-connector`：「本地数据网关与脱敏」当前只描述 FHIR 接入路径，需扩展到**数据库数据源**；并新增「连接器是唯一数据库句柄持有者」这一边界要求（Wasm / agent 均不得持有）。
- `data-product`：数据产品目录的覆盖元数据由**库内统计自动产出**（CDM/词汇表版本、表覆盖、时间跨度、记录数），而非人工登记。

## Impact

- **连接器**（`apps/connector`）：新增数据源模块（连接管理、一致性校验、SQL 执行、方言抽象）；`local-data-loader` 路径保留，按数据源类型分派；新增 PostgreSQL 驱动依赖。
- **控制面**（`apps/api`）：目录接口接收连接器上报的库内统计元数据；**不新增任何数据库凭据或连接**。
- **数据库**（`packages/database`）：连接器本地实体新增数据源配置与接入校验记录；控制面目录实体扩展覆盖元数据字段。
- **前端**：数据产品详情显示 CDM 版本、词汇表版本、表覆盖与时间跨度。
- **部署**：连接器新增数据源配置项与凭据注入；医院侧需按契约建视图层与受限账号（接入手册）。
- **治理**：DOMAIN 增数据源接入词汇与不变量；TRUST 需评估「视图 + 受限账号」作为**医院侧可自主掐断的第零道闸**（在所有软件闸门之外，由医院 DBA 掌控）；DECISIONS 需登记「连接器是唯一句柄持有者」与「只接 CDM 而非通用数据库」两条。
- **未决风险**：带行级过滤的视图在千万至亿行级 CDM 表上的性能影响**未经验证**（本地实测仅 4 行），需在真实数据量上评估后再定生产接入方式。
