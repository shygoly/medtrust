## 1. 数据源配置模型与连接管理

- [x] 1.1 连接器本地实体：数据源配置（label / type / 连接串 / `cdmVersion` / schema 三名 / `dbms` 方言 / 凭据引用）
      —— 实施调整：**配置**做成部署期 JSON（`CONNECTOR_CDM_SOURCES[_FILE]`，vantage6 同款），不进实体；**状态**（接入校验结果）才进实体（见 3.4）。
      理由：配置入库意味着连接器本地 SQLite 要存院内库的连接信息，且运行期可改——两者都不该发生。
      另：不接受任何连接串（`url`/`uri`/`connectionString`），拆成 host/port/database/user，避免口令随整串进日志
- [x] 1.2 凭据只从连接器侧环境或本地配置读取；新增单测断言凭据不出现在任何上报载荷与审计明文中（spec: 数据库凭据不出连接器）
      —— 测试抓到一个真 bug：执行器曾把 `env` 存成字段，生产里 `env` 即 `process.env`（含 SM2 私钥等**全部**秘密），
      序列化执行器会一次泄露所有秘密。已改为闭包取口令，回归用例覆盖 `JSON.stringify` 与 `util.inspect`
- [x] 1.3 连接池与超时管理；连接失败不拖垮长轮询循环
      —— 接住 pg Pool 空闲连接的 `'error'` 事件（无人监听会直接 crash 进程）；Node errno（ECONNREFUSED 等）归为 unavailable
- [x] 1.4 `@medtrust/connector` 新增 PostgreSQL 驱动依赖（版本锁定）—— `pg@8.23.0` / `@types/pg@8.23.1` 精确锁定

## 2b. 投影下推

- [x] 2b.1 CDM 取数接口：入参为分析所需的列/过滤条件，SQL 完成列裁剪与行过滤（spec: 投影在 SQL 里而非内存里）
      —— `cdm-projection.ts`：人员查询只回 `(person_id, exposed)`，药物过滤写成 `EXISTS … ANY($1)`；事件查询只回 `(person_id, term)`
- [x] 2b.2 取回结果转为既有投影载荷形态（最小整数列），汇入现有沙箱链路
      —— 抽出 `buildDisproportionalityProjection` 作为**唯一**构造点，文件路径与 CDM 路径共用，布局不可能漂移
      —— 药物按 `concept_id` 解析（design D8），不移植文件路径的模糊字符串匹配；解析不到即 fail-closed
- [x] 2b.3 回归测试：同一份数据分别走文件路径与 CDM 路径，沙箱输出 MUST 逐字段一致
      —— 真实 PG + 真实 Wasm 沙箱：投影载荷逐字节相同、沙箱输出逐字节相同、分桶逐字段相同（含并列稳定顺序）
- [x] 2b.4 负例：CDM 路径不得出现全表拉取（断言查询带列清单与过滤条件）

## 3. 接入一致性校验（fail-closed）

- [x] 3.1 必需 CDM 表（视图）存在性检查
- [x] 3.2 视图列不含直接标识列的检查（按 CDM 规范比对应有列集合）
      —— 除「规范外的列」外，还拦**规范内但承载直接标识**的列：`person_source_value` 按 ETL 惯例就是病案号
- [x] 3.3 权限边界探测：底表不可达 / 视图不可写 / `results` 可建表可清理
      —— 实施发现两处任务清单遗漏，已补：① **超级用户 / BYPASSRLS 账号**会绕过全部视图与权限，契约形同虚设；
      ② 「底表不可达」**无法按名字测**（医院可以任意命名底表 schema），正确判据是**最小权限**：
      允许集合外任何关系都**读不到**（schema USAGE 且表 SELECT；只看 USAGE 会把 PG≤14 默认的 public 误判为越权）
- [x] 3.4 `cdm_source` 与 `vocabulary.vocabulary_version` 可读性检查，并持久化留痕
      —— `local_data_source_status` 实体（只存状态，永不存凭据）；并校验库中声明的 CDM 版本与配置一致
- [x] 3.5 错误信息区分「权限不足（指明哪个权限域）」与「契约不成立」（spec: 权限不足与契约不成立需可区分）
      —— 六个权限域：账号属性 / 最小权限 / CDM 视图只读域 / 视图契约 / results 可写域 / 元数据；越权清单按 schema 分组不截断
- [x] 3.6 校验未过的数据源 MUST NOT 进入可用状态，且 **MUST NOT 降级回退到文件数据源**
      —— `CdmDataSourceRegistry.requireAvailable()` 是唯一取用入口；未校验 / 未通过一律抛
- [x] 3.7 负例总验收：缺表 / 视图含直接标识 / 纯只读账号 / 底表可达 / 元数据不可读，逐条 fail-closed
      —— 真实 PG 上 9 类：纯只读 / 底表可达 / 视图漏身份证号 / 病案号 / 缺表 / 元数据无权限 / 超级用户 / 不可达 / 错口令；每类归因到正确权限域且其它域不误报

## 4. 单一数据入口边界

- [x] 4.1 数据源类型显式声明与分派（CDM 库 / 文件），不可静默切换（spec 修订: 数据源类型不得静默切换）
      —— 本变更**不开放** CDM 上的生产分析（design D8）：CDM 类型产品派发一律 fail-closed 并说明原因
      —— 声明解析器放在 `@medtrust/database`（`parseDataSourceDeclaration`），控制面发布校验与连接器派发共用一份；
      CDM 声明带文件路径视为歧义直接拒（「库不可用改读文件」的退路从格式上就不存在）；本地已物化文件数据时派发 CDM 产品也不会误用它
- [x] 4.2 断言 Wasm 模块导入面不因本变更扩大——闸 1 零导入判据不变（回归测试）
      —— `import-surface.spec.ts`：env.cdm_query / sql_exec / db_connect … 与 WASI 读文件 / 收包一律实例化前拒；在用平台模块导入面恰为 env.memory
- [x] 4.3 联邦训练执行体改为从连接器取投影切片，不配置独立数据源凭据（spec: 其它执行体不得自建连接）
      —— 用户定夺（2026-09-21）：连接器算特征与标签，agent 只收切片（design D9）。
      连接器 `fl-round/training-slice.ts`（`esrd-proxy@1`：7 项数值观测 + 肾病代理标签）+ `DataProductLocalSource.withProductRecords`（按合约取数、不替换共享存储）；
      proto `RunLocalRoundRequest.training_slice_json`；agent 删除文件读取（`synthea_loader.py`、`AGENT_DATA_PATH`），切片校验拒收额外字段、无切片即失败；
      spec 带 `dataPath` 控制面与 agent 两处拒；agent 镜像不再内置患者文件。标签口径迁移在演示数据上逐人对拍一致。
      **后果**：演示训练合约指向的 `dp-insulin-panc-*` 无肾病阳性 → 演示标签全 0，须另调演示合约（见 design D9）
- [x] 4.4 负例：为算法模块或 agent 配置数据源凭据的尝试应被拒绝
      —— 四处落实：控制面发布拒收带连接信息的 CDM 声明；连接器数据源配置项白名单（无「开放给模块 / agent」开关）；
      agent 启动时发现数据源凭据变量（`AGENT_*DB*` / `CONNECTOR_CDM_SOURCES` / libpq `PG*`）即拒绝启动；
      agent 依赖里不得出现任何数据库驱动（结构性测试）

## 5. 目录覆盖元数据自动产出

- [x] 5.1 库内统计：CDM 版本、词汇表版本、含数据的表、时间跨度、记录数量级
      —— 只报**数量级**与**月粒度**；某表统计超时记 null（「统计失败」≠「没有数据」）；数据源整体不可达则整份作废只报版本
- [x] 5.2 上报内容只含统计量的断言测试（spec: 上报内容仍只是元数据）
      —— 共享白名单校验器 `validateCoverageReport`：连接器发前自检、控制面收后复检；多一个字段整份拒收
- [x] 5.3 控制面目录实体扩展覆盖元数据字段并入库
      —— `DataProduct.coverage`；`POST /connector/data-sources/:label/coverage` 只挂到**认证出来的**机构自己声明了该 label 的产品上；改声明即清旧覆盖
- [x] 5.4 版本变化时更新或标记待刷新，不以陈旧版本继续呈现（spec: 元数据陈旧需可识别）
      —— 连接器**周期复核**（`CONNECTOR_CDM_REVERIFY_MS`，缺省 6h）：版本变而统计未跟上 → 版本照实更新、覆盖标待刷新；校验不过 → 标待刷新。
      本地真机演练：DBA `REVOKE CREATE ON SCHEMA results` → 5 秒内目录变「待刷新」；`GRANT` 回来 → 恢复

## 6. results schema 留存治理

- [x] 6.1 中间结果表命名带任务标识，便于定位与清理
      —— `mt_<UTC 分钟>_<任务号 SM3 前 12 位>_<用途>`：不把任务号写进医院库
- [x] 6.2 任务结束按留存条款清理；异常终止的任务由周期性清理兜底
      —— **定夺未决 2**：任务结束**一律即删**——留存条款是上限不是下限，立即删除满足任何条款，且不与阅后即焚冲突。
      兜底清理随每次复核执行（孤儿表 > 24h 且不属于本进程在跑任务）。只碰本账号拥有且符合命名约定的表。
      `dropTask` 的调用方是 Circe 变更里的 CDM 任务执行体（本变更 D8 不派发 CDM 任务，故当前无业务调用方）
- [x] 6.3 接入校验确认 `results` 具备清理所需权限（与 3.3 合并验收）
      —— 接入校验的探针表走同一命名约定与 `dropTask` 路径：清不掉即契约不成立；崩溃遗留的探针也会被兜底认出
