## Why

现有规格 `data-space-connector` 已有两条要求：
- 连接器只能主动出站，不得要求参与方开放入站端口；
- 连接器身份必须由平台 CA 签发的 SM2 证书标识，没有有效证书就拒绝接入。

现在的实现违反了这两条：
- **平台主动连进医院。** 联邦训练的每一轮，控制面都通过 gRPC 直接调用各院 Python agent（`RunLocalRound`），训练日志也由控制面连进 agent 的 WS（5023）。这两条都是明文、无鉴权（agent 用 `add_insecure_port`，API 用 `createInsecure()`）。部署到真实医院，就意味着医院要为平台开一个谁都能调用的入站端口。
- **连接器信道只用静态令牌。** SM2 证书签名认证的代码已经存在（连接器签请求，API 用平台 CA 验证，另有强制开关 `CONNECTOR_CERT_AUTH_REQUIRED`），但 ali29 上两端都没有配置，实际跑的是静态令牌。代码里还写死了一个默认令牌 `dev-connector-token`。
- **任务下发靠每 5 秒一次的短轮询。** 空闲时也在不停请求，任务最多要等一个轮询间隔才被领走。

## What Changes

- **院内唯一出站组件是连接器**：
  - Python agent 退为院内计算后端，只接受本院连接器调用（院内网络 + 共享凭证），不再对平台开放任何端口。
  - 删除控制面主动调用 agent 的路径：`AgentDispatchClient` 的远程调用、`AgentLogBridge` 连入 agent 的 WS、`AGENT_GRPC_ROUTING`。
- **联邦训练轮次改由连接器中转**：
  - 编排器不再直接调用 agent，而是为每家医院生成这一轮的训练任务；
  - 连接器经长轮询领到任务，在院内调用本院 agent 的 `RunLocalRound`；
  - 训练结果连同本轮指标，经 SM3 摘要和 SM2 签名后回传；
  - 编排器等齐各院结果后做加权平均。超时的医院沿用现有的补偿机制，踢出本轮。
  - 本轮指标随结果一起回传，取代原来的日志 WS。
- **任务下发改为长轮询**：
  - 新增统一接口 `GET /api/v1/connector/tasks/pending?waitMs=`，一次返回该医院的 RWS 任务、FL 预测任务和联邦训练轮次任务。
  - 没有任务时，服务端挂起请求，直到出现任务或超时（上限 25 秒）；有新任务派给这家医院时立即返回。
  - 连接器收到响应后立刻发起下一次请求。每次长轮询都顺带刷新连接器的在线状态。
  - 旧的 `rws/pending`、`fl-prediction/pending` 在迁移期保留，标为废弃。
- **连接器信道强制证书认证**：
  - 缺省即为强制模式，每个请求都必须带平台 CA 签发证书的 SM2 签名；
  - 删除写死的默认令牌；令牌方式只在显式开启本地开发开关时才可用，而且必须显式配置令牌值。
- **下发的任务带平台签名**：
  - 平台对每个下发任务的规范化内容先算 SM3，再做 SM2 签名；
  - 连接器用部署配置里固定的平台 CA 公钥（`CONNECTOR_PLATFORM_CA_PUBKEY`，与 Wasm 变更共用）验签，验签失败就拒绝执行。
- **前置条件：控制面库持久化**。CA 根密钥存在控制面 SQLite 里，而这个库在 API 容器内且没有挂载卷，重建 API 就会重新生成根密钥，导致已签发证书、固定公钥、模块签名全部失效。必须先挂卷，这一步同时解决了「重建 API 会清空预跑任务」的老问题。
- **治理文档**：DECISIONS 新增 D-CN-4；TRUST 新增 CTL-21；FLOWS 更新联邦训练与任务下发的跨域边；ARCHITECTURE §6.4 更新；DEPLOY 更新环境变量和端口。

## Capabilities

### New Capabilities
（无）

### Modified Capabilities
- `data-space-connector`：
  - 修改「连接器可信通信」：强制证书认证；下发任务带平台 SM2 签名，连接器验签。
  - 修改「连接器主动外联部署模型」：任务下发改为长轮询；联邦训练轮次也经连接器下发；院内计算后端不对平台开放。
  - 新增「院内计算后端只受本院连接器调用」。

## Impact

- **控制面 API**：
  - 新增统一长轮询接口，并在 RWS、FL 预测、联邦训练轮次派发时唤醒等待中的请求。等待者登记在进程内存里，适用于当前的单实例部署；多实例需要改用发布订阅，登记为后续事项。
  - 联邦训练编排从「远程调用 agent」改为「入队并等待回传」。
  - 下发任务的签名。
  - 连接器鉴权守卫缺省改为强制模式。
  - 删除 agent 远程调用和日志桥。
- **连接器**：
  - 长轮询主循环取代 `setInterval`；
  - 联邦训练轮次中转，在院内调用 agent；
  - 任务验签；
  - SM2 证书与私钥配置（`CONNECTOR_CERT_FINGERPRINT`、`CONNECTOR_SM2_PRIVATE_KEY`，均已有读取点）。
- **Python agent**：gRPC 入口校验共享凭证，缺失或错误即拒绝；只监听院内网络；日志 WS 下线，或只在院内保留。
- **部署**：
  - 控制面数据目录挂载卷（必须最先做）；
  - 用平台 CA 为各院连接器签发证书，写入连接器配置；
  - API 删除 agent 路由相关配置；
  - 各院连接器配置本院 agent 地址，这会顺带接通 L3，但需先修复 Cox 小样本返回固定值的问题；
  - 登记新的环境变量。
- **测试**：
  - 长轮询：有任务立即返回、超时返回空、在途时新派发的任务能唤醒等待；
  - 不带证书签名的请求被拒；令牌降级被拒；
  - 任务验签失败被拒；
  - 联邦训练经连接器中转，多轮收敛，超时节点被补偿踢出；
  - agent 无凭证调用被拒。
