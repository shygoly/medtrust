## Context

以下为 2026-09-24 对照代码核查的现状，只列本设计要处理的部分。

- **三条互不相干的编排**：
  - RWS：`cp_rws_task` + `cp_rws_assignment`，持久化；
  - FL 预测：`cp_fl_prediction_*`，基本复制 RWS；
  - SecretFlow LoRA：状态只在内存里，API 重启即丢。
  - 三者只共享连接器传输层：长轮询 `GET /connector/tasks/pending`、平台签名的任务信封、内存去重。执行内容由连接器里按 `analysisType` 写死的 switch 决定（`connector-task-runner.ts`）。
- **信任根**：
  - `ca.service.ts` 的一把 CA 根钥（`cp_ca_keypair.privateKey`，明文 `text` 列）同时签证书、任务和算法模块。
  - `connector-admin.service.ts` 在注册方未提交公钥时代生成密钥对，并把私钥返回给调用方。
  - 所有 SM2 调用都用 sm-crypto 缺省参数：不做 Z_A 预处理，签名是原始 r‖s 十六进制。
- **合约**：
  - 医院的「批准」只是平台网页上的一次登录操作，合约没有任何一方的密码学签名。
  - 连接器不存合约，只按平台随任务下发的快照校验（`policy-enforcement.ts`）。快照在任务创建时冻结，之后撤销也看不到。
- **执行面**：
  - 能签名、能被合约固定的算子只有 L1.5 失衡检测一个 Wasm 模块（AssemblyScript 与 Rust 两份），跑在零导入沙箱里（`apps/connector/src/domain/sandbox/`）。
  - 输出闸门在连接器侧，缺二次抑制；修复另见独立任务卡片。
  - L1.5 的 PRR/ROR/IC 在平台上计算。
- **约束**：
  - 院方网络只出站（D-CN-4）；
  - 单实例 API + SQLite（D-DB-1）；
  - TEE 只有软件实现，须如实标注（D9 / CTL-09）；
  - 算法准入只收可复现的源码（D-CN-5）。
- **用户裁决（2026-09-24）**：全面替换现有编排；平台作为合约明示的 C3 接收方与合并方。

## Goals / Non-Goals

**Goals:**
- 医院的数据只在医院自己签过名的计划下被使用。平台改动计划、伪造本院的接受签名、替换算子，都会被连接器拒绝。
- 任一持有方拒绝或复核超时，作业就不能执行。
- 执行模型统一为「注册算子组成的作业/阶段」，作为后续迁移全部分析类型的内核。
- 流动标签在运行时强制：编译期校验，连接器复核时重算，出节点时再拦一次，C0 无法出节点。
- 签名合 GM/T 0003，密钥各归其主、按用途分离。
- L1.5 失衡检测端到端走通 MDOP，通过 MDOP §14 中适用于本期的一致性测试。

**Non-Goals:**
- 安全聚合、ε 预算账本、院方人工发布审批。本期只支持合约预授权的自动放行。
- C1 协议、C2 与可信空间节点、PSI 与 MPC、点对点中继。编译器对 C1 / C2 边一律报能力不符。
- 迁移 L0 / L1 / L2 / L3、FL 预测、LoRA；compose 页改为计划编辑器；下线旧管线。
- 身份锚脱离平台（did:web 或国家身份基础设施）、TLCP、API 多实例。

## Decisions

### D1 绞杀者模式：新内核与旧管线并行，新表不改旧表
MDOP 作业使用新表 `cp_mdop_*`：作业、阶段、片段、凭证、签名、句柄、投递、回执、算子、发件箱、nonce。旧的 `cp_rws_*` 与 `cp_fl_prediction_*` 不动。

理由：
- 旧管线在迁移期间仍在线上服务；旧记录被链上存证引用，应当只读保留。
- MDOP 的状态词汇与旧表不兼容，改旧表等于同时维护两套语义。

可复用的机制（出站领取、结果哈希校验、超时重派）按 MDOP 语义重写，不直接复用代码。

- **备选：在 `cp_rws_assignment` 上加 stageId / attempt / 依赖字段，演进成阶段表。** 迁移期新旧语义会混在同一张表里，旧管线的 `partial` 合并语义与否决直接冲突。不采用。

### D2 共用协议核心 `packages/mdop`，领域中立
包内容：
- schema：信封、算子清单、逻辑计划、物理计划与片段、凭证、句柄、审计回执、销毁回执；
- C0–C3 标签格与传播规则、能力匹配、错误码；
- 规范化哈希：RFC 8785 JCS，再做 SM3；
- 国标 SM2 签名与验签（D4）、凭证校验。

包内不出现患者、诊断、用药等概念，医疗 schema 放在调用方。

平台编译器和连接器复核调用同一份实现。连接器的独立性体现在输入上：它用自己的本地合约库、本地白名单和本地算子清单重算，不读平台的编译结果。这与 `@medtrust/wasm-algorithms` 闸 1 平台和连接器共用一份实现的做法一致。
- **备选：连接器另写一份独立实现。** 两份实现会漂移；「不信平台」要防的是平台的输入和输出被篡改，不是代码本身。不采用。

### D3 传输：沿用长轮询 + 出站 POST，控制面与数据面分开接口
- **平台 → 连接器**：长轮询响应增加 `mdop: Envelope[]`，取自 `cp_mdop_outbox`。消息投递至少一次；没有应答的要约或指令按原 `idempotency_key` 重发，连接器按 `msg_id` / `idempotency_key` 去重，并返回同一结果。
- **连接器 → 平台，控制面**：`POST /api/v1/mdop/messages`，承载接受/拒绝、合约签署、阶段状态、制品就绪、销毁回执、审计回执、能力通告。
- **连接器 → 平台，数据面**：`POST /api/v1/mdop/deliveries`，只承载 C3 结果投递。
- 控制面与数据面分开，是为了让「哪些接口携带数据」可以在代码和 FLOWS 里分别审计。
- MDOP 接口以信封签名作为唯一的应用层认证，旧的请求签名守卫只留给旧接口。
- **备选：连接器开入站端口，或另建中继。** 违反 D-CN-4。平台作为 C3 接收方之后（D8），本期没有点对点数据。不采用。

### D4 信封与 SM2 国标化（BREAKING）
- **信封**：字段按 MDOP §7.1：`mdop`、`msg_id`（ULID）、`msg_type`、`job_id`、`sender`、`receiver`、`timestamp`、`nonce`、`idempotency_key`、`body`、`sig{alg,kid,value}`。
  - 签名内容为「去掉 `sig` 后的信封」经 JCS 规范化，再做 SM3。
  - 身份标识用 `urn:tds:<space>:participant:<id>`，与 D11 的 URN 体系一致；`kid` 是公钥 SM3 的完整 64 位十六进制。现有 16 位十六进制（64 bit）的指纹不再用于 MDOP。
- **接收方校验**：签名有效、`receiver` 是自己、时间偏差在 ±5 分钟内、nonce 未见过。nonce 落盘保存 10 分钟，连接器重启后也不失效。
- **SM2 算法口径**：
  - GM/T 0003.2 签名，带 Z_A 预处理，缺省用户 ID `1234567812345678`；签名值按 GM/T 0009 用 DER 编码；算法标识 `SM2-SM3`。
  - 实现用 sm-crypto 的 `{ hash: true, der: true, publicKey }` 参数，库已支持，见 `sm2/index.js` 的 `getHash`。
- **切换范围**：证书、任务与信封、算子清单与模块、结果背书、连接器请求签名，同一版本一起切换。
  - 旧格式 `SM2-legacy-raw` 只用于核验切换前的历史对象，例如链上元数据；
  - 线上链路 MUST NOT 接受旧格式，否则可以被降级攻击。
- **互操作校验**：签名实现要和一个独立实现（gmssl 或 Tongsuo 命令行）交叉验证，双向签验一致才算通过。

### D5 密钥：参与方自生成，平台三钥分离，根钥加密落库（BREAKING）
- **参与方密钥**：连接器首次启动时（或运行 `connector keygen`）在本地生成 SM2 密钥对，私钥以 0600 权限保存在本地文件；注册时只提交公钥，平台 CA 为它签发证书。删除代生成密钥的路径。
- **平台三钥**：
  - CA 根钥：只签证书；
  - 平台节点密钥：签信封、凭证，并以合约一方的身份签署合约；
  - 注册中心密钥：签算子清单。它同时就是 P-CTL-6 所说的「专用算法签名密钥」。
  - 连接器在部署配置里固定三把公钥。
- **加密落库**：三把私钥用 SM4 加密后存库，密钥加密密钥来自 `PLATFORM_KEK`（配置了 Vault 就从 Vault 取）。生产环境缺少该密钥时拒绝启动。
- `@EncryptedColumn` 属于 api 包，控制面实体在 database 包，不能直接套用，所以在 `CaService` 内部做信封加密。
- **备选：继续一钥签一切，只把根钥加密。** 节点密钥因高频使用而泄露，会直接等同于 CA 泄露。不采用。

### D6 合约由持有方签署，连接器本地留存
- **规范化合约新增字段**：
  - 接收方列表 `[{party, role: merger|final, jurisdiction}]`，平台以 `merger` 身份列入；
  - 用途编码；
  - 允许的算子摘要（沿用现有模块固定条款）；
  - 复核方式 `review: auto | manual` 与复核时限；
  - `ethicsRequired`（及批件号、有效期）；
  - 提供方连接器公钥指纹、平台节点公钥指纹；
  - 预审快照哈希（D-CMP-2）。
- **签署流程**：
  1. 医院在网页上批准（维持现状）；
  2. 平台向该院连接器发 `ContractOffer`；
  3. 连接器本地确认：人工确认走仅限院内访问的端点或 CLI；自动确认需要本地策略文件显式允许；
  4. 连接器签名，发 `ContractAgree`；
  5. 平台验签后，用平台节点密钥副署并激活。
- 连接器本地库保存合约全文和双方签名。复核只认本地副本。
- **撤销**：
  - 医院可以在本地 CLI 撤销，立即生效（本地权威），随后通知平台；
  - 也可以在平台网页撤销，平台发 `ContractTerminate`，连接器标记本地副本。
  - 被撤销合约上的 MDOP 作业进入 ABORTED 并触发销毁。
  - 平台扣下撤销消息不发的风险，由「本地可撤」兜底。
- **旧合约**（没有持有方签名）继续服务旧管线，不能用于 MDOP 作业，报 `E_CONTRACT_UNSIGNED`，没有宽限期，与 D-CMP-2 同一原则。
- **药企的同意**：本期仍是平台记录的知悉哈希，不是密码学签名，如实标注（见 Open Questions）。

### D7 流动标签 C0–C3 与编译规则
- **标签格**：C0（本地明文）为最严，C3（可发布）为最宽；C1（密态）与 C2（受控流动）互不可比。
- **传播**：
  - 普通算子的输出取所有输入的最严上界；同时有 C1 和 C2 输入时，输出为 C0。
  - 只有 `declassify` 类算子能降级，输出等级由清单声明，参数不得弱于合约的发布条件。例如 `minCell` 参数必须不小于合约值。
  - 不可逆出规则按 MDOP R5。
- **跨节点的边**：
  - C0 一律违规（`E_LABEL_VIOLATION`）；
  - C3 的目标必须在合约接收方列表里，否则报 `E_CAPABILITY_MISMATCH`；
  - C1 / C2 本期没有节点通告对应能力，一律报 `E_CAPABILITY_MISMATCH`。
- **平台节点**：只接受 C3 输入。
- **放置**：
  - 输入为 `ds://<node>/…` 的阶段放在该节点；只依赖单个节点的阶段跟随该节点；
  - 依赖多个节点的阶段只能是平台合并阶段；
  - 显式 `at` 与数据所在节点冲突时，按 C0 跨节点报 `E_LABEL_VIOLATION`。
- **错误定位**：报错必须指明违规的边。
- 连接器复核时对本方子图（本方片段加上所有边界边）用本地清单重算一遍。

### D8 平台作为合约明示的 C3 接收方（P1 修订）
- **路径**：C3 结果经数据面接口从连接器投到平台，平台侧的 `system` 合并算子只接受 C3 输入，合并结果仍是 C3，经控制台交付给药企。
- **同意**：平台看得到 C3，这是合约写明、医院签过名的，不是默认能力。
- **P1 的边界**：P1 对 C0 / C2 仍然严格成立：平台上没有任何接口接收 C0 / C2。
- 各院模型增量属于 C0，本期不涉及；后续 LoRA 改造必须走安全聚合（C1），平台作为聚合服务端，只看到掩码后的和。
- **备选：药企部署连接器接收 C3。** 已由用户裁决不采用。

### D9 算子清单三类，连接器本地白名单
- **`kind` 三类**：
  - `wasm`：摘要为模块 SM3，沿用 D-CN-5 的源码复现与五道闸；
  - `oci`：摘要为镜像 digest，本期不启用；
  - `system`：连接器或平台自带的机制，包括数据源、降密、合并，以 `id@version` 加组件构建版本标识。
- **规则**：分析类算子只能是 `wasm` 或 `oci`；`system` 只承载机制，不承载受托分析逻辑。
- **清单签名**：清单由注册中心密钥签名；现有两份 L1.5 模块迁入清单，类别为 `local`。
- **白名单**：
  - 连接器白名单存本地表，缺省为空；由医院用 CLI 按摘要加入，演示环境由初始化脚本加入并标注。
  - 复核和执行都要求摘要在白名单里、没被吊销、清单签名有效。
- **吊销名单**：由平台节点密钥签名，随长轮询下发，连接器落盘，版本单调递增；启动后收到有效名单之前，拒绝执行任何 `wasm` 算子。
- **备选：继续以合约固定的 SM3 为准，不设白名单。** 那样平台能在同一份合约下换算子，与 P2 冲突。不采用。

### D10 本地复核：七项检查与拒绝粒度
按 MDOP §7.4 的七项，本期语义如下：

1. **白名单**：算子摘要在本地白名单中，未被吊销，清单签名有效。
2. **合约一致**：用途编码一致；数据集属于合约范围；当前时间和凭证有效期都在合约有效期之内。
3. **标签**：对本方子图重算标签（D7）。
4. **对端**：边界边的对端要么是本地固定公钥的平台节点，要么是证书有效且未吊销的参与方；C3 目标在合约接收方列表里。
5. **预算**：本期没有预算账本，凡是给本节点申请 ε > 0 的计划一律拒绝（`E_BUDGET_EXCEEDED`，说明为「本节点未启用预算账本」），fail-closed。
6. **伦理**：本地合约要求伦理批件时，作业的 `ethics_ref` 必须与合约一致且未过期，否则 `E_ETHICS_MISSING`。
7. **哈希**：用本方片段重算片段哈希；用作业头和片段哈希表重算 plan_hash；两者都要与要约一致（D11）。

- **复核方式**：合约为 `auto` 时，全部通过即签；合约为 `manual` 时进入本地待确认队列。复核时限缺省 72 小时，由合约配置，超时视同拒绝。
- **拒绝消息**：只含错误码和一句面向申请方的说明，不含本地策略原文、剩余预算或数据规模（MDOP §11）。
- **快照绑定**：复核时由连接器计算数据快照标识。文件数据源为文件字节的 SM3；CDM 本期不开放分析。标识写进接受签名；执行时重算，不一致报 `E_SNAPSHOT_CHANGED`。

### D11 plan_hash 与执行凭证
- **plan_hash**：`SM3(JCS({作业头, fragments: {节点: 片段哈希}}))`。作业头包括作业 ID、用途、申请方、合约、伦理批件、预算、有效期。
- **数据快照不进 plan_hash**：各节点复核时才算出快照标识，事先无法写入作业头。改由各持有方把本节点快照标识和凭证核心一起签名，凭证逐签署方记录。MDOP 所说的 `data_snapshots` 因此在接受时锁定，每个节点只为自己的快照签名。
- **要约内容**：每个节点只收到本方片段全文和片段哈希表，看不到其他节点的片段内容，也能独立重算 plan_hash。片段里包含它的边界边（对端、标签、通道）。
- **凭证核心**：`{ticket_id, job_id, plan_hash, fragments, not_before, not_after}`，在要约阶段就已确定。
  - 各持有方在 `PlanFragmentAccept` 中签的就是这份核心；
  - 平台收齐签名后加上自己的签名，组成凭证。
- **执行方校验**：
  - 本方签名在凭证里且有效（最关键：平台无法让本院执行一份本院没签过的计划）；
  - 平台签名有效；
  - 当前时间在有效期内；
  - 待执行片段的哈希与凭证一致。
- **如实边界**：其他持有方的签名用空间 CA 证书校验。平台运营 CA，因此「平台伪造他院的接受」只能事后审计发现（他院回执链里没有这条接受），而不是不可伪造。本院数据的使用只受本院签名约束，不受影响。做到不可伪造需要身份锚脱离平台，列入三期。

### D12 作业与阶段状态机、幂等、重试、销毁
- **状态机**：
  - 作业：`SUBMITTED → COMPILED → NEGOTIATING → TICKETED → RUNNING → RELEASING → SUCCEEDED | FAILED | ABORTED → PURGED`；编译失败、任一方拒绝或复核超时进入 `REJECTED`。
  - 阶段：`PENDING → READY → RUNNING → SUCCEEDED | RETRYING → RUNNING | FAILED`。本期没有控制类算子，不使用 `SKIPPED`。
- **合法迁移表**：以显式迁移表实现，参照 SecretFlow FSM 的写法。非法迁移抛错并记审计。
- **幂等**：`StageDispatch` 带 `idempotency_key = job:stage:attempt`，连接器落盘已处理的键，对重复键返回原结果，不重算。
- **重试**：
  - 本地算子最多重试 3 次，指数退避（30 秒、60 秒、120 秒），只对 `E_RUNTIME`、`E_TIMEOUT`、`E_PEER_UNREACHABLE` 重试；
  - 每次重试 attempt 加 1，不复用上次的中间产物。
- **否决**：收到任一 `PlanFragmentReject`，作业立即进入 `REJECTED`，并通知其他节点作废要约。
- **发布**：本期合约全部是预授权自动放行，`RELEASING` 在合并结果落库后自动完成；人工审批留待后续。
- **销毁**：作业一进入终态，平台就向所有持有本作业制品的节点发 `PurgeOrder`；收齐所有 `PurgeReceipt` 后进入 `PURGED`。平台上的 C3 结果（各院投递和合并结果）属于交付物，不在销毁范围内。

### D13 连接器制品库与 C0 出节点守卫
- **存储**：制品存在连接器本地表 `mdop_artifact`，字段为句柄、标签、schema、摘要、载荷、过期时间。
- **句柄**：只登记在平台，格式为 `art://<node>/<job>/<stage>/<output>`，不带行数等统计量，只有 C3 句柄可以带统计（MDOP §9.1）。
- **销毁**：
  - TTL 缺省 72 小时，可按阶段覆盖；
  - 清扫任务到期自主销毁，并发出签名的 `PurgeReceipt`（原因为 `ttl`）；
  - 收到 `PurgeOrder` 立即销毁，销毁后按句柄读取必须失败。
- **出节点守卫**：数据面客户端只允许投递 C3 制品，且目标必须在本地合约的接收方列表里；投递 C0 / C1 / C2 一律抛错并记审计。这是编译、复核之外的第三道拦截。
- **如实边界**：本期不做制品落盘加密，也不做介质级安全擦除；「不可再读取」指通过连接器接口不可读取。

### D14 审计回执链与锚定
- **回执内容**：每个阶段事件（接受、拒绝、开始、成功、失败、销毁）生成一条签名回执：`input_digests`、`op_digest`、`output_digest`、`label`、`prev_receipt_hash`。
- **链与校验**：每个节点单独成链，存连接器本地库，并以 `AuditReceipt` 消息上报；平台逐节点校验链的连续性。
- **锚定**：链头在作业进入终态时，以及每 30 分钟，经现有 `AttestationService` 锚定到长安链；链不可达时进入补偿队列（D-UC-2），不伪造交易号。
- **校验工具**：提供 `scripts/verify-receipt-chain.mjs`，任何一方都能脱离平台检测断链。
- 旧的连接器审计日志（`audit.ts`）继续保留；MDOP 回执是另一条独立的签名链。

### D15 第一条迁移链路：L1.5 失衡检测
- **算子**：
  - `source.dataset@1`（system，连接器）：绑定 `ds://<node>/<dataProductId>`，经现有加载与去标识化产出 C0。
  - `rws.disproportionality@1`（wasm，两份现有模块摘要）：输出四格表，C0。
  - `declassify.small_cell@1`（system，连接器）：修复后的输出闸门（含二次抑制），读合约 `minCell`，输出 C3。
  - `merge.disproportionality@1`（system，平台）：合并各院四格表，复用现有 PRR/ROR/IC 计算，输出 C3。
- **计划模板**：`rws.l15.disproportionality`，由网页向导填参数、选医院与合约，提交到 `POST /api/v1/mdop/jobs`。
- **Web**：RWS 向导只为失衡检测提供「经 MDOP 执行」开关；新增 `/space/mdop/jobs` 列表与详情页，展示阶段、各节点复核状态、凭证签署方、回执；结果复用现有 L1.5 结果组件。
- **开关**：平台与连接器用 `MDOP_ENABLED` 控制，缺省关闭，旧管线不受影响。

## Risks / Trade-offs

- **SM2 与密钥同日切换，失败会让线上连接器全断** → 先在本机三端（API + 两院连接器）完整演练，再上 ali29；保留旧镜像和旧密钥备份，直到新版本稳定；切换步骤写进 DEPLOY。
- **单个变更范围过大** → 任务按「核心包 → 密钥与签名 → 合约 → 注册与白名单 → 内核 → 运行时 → L1.5 → 一致性测试」分段，每段单独可合并、可测；以一致性测试作为本期验收。
- **演示的自动确认被误读为医院同意** → 自动确认只能由本地策略文件显式开启；回执和页面标注 `review=auto(policy)`；缺省为人工确认。
- **平台可伪造他院的接受** → 见 D11 的如实边界：写进 TRUST 与 v0.2，不对外宣称不可伪造。
- **与旧管线并行，两套语义让人困惑** → 只开放 L1.5，页面明确标注「MDOP 通道」；后续变更逐类迁移，迁完一类就下线对应的旧路径。
- **复核时限长导致作业挂起** → 演示合约为自动复核；人工时限可配置；超时即拒，fail-closed。
- **标签规则有缺陷，放 C0 出去** → 纵深防御：编译、连接器复核、数据面出节点守卫、输出闸门四道；一致性测试逐条覆盖。
- **SQLite 写入压力（发件箱、nonce、回执）** → 单实例 WAL，量小；nonce 与发件箱定期清理。

## Migration Plan

1. 治理与文档：DECISIONS 登记 D-MDOP 各条，TRUST 登记新控制点，出 MDOP v0.2 修订稿。
2. `packages/mdop` 及测试：JCS 与 SM3 金标向量、与 gmssl/Tongsuo 交叉验证 SM2、标签格穷举。
3. 签名国标化与密钥分离：本机演练 → ali29 切换，同时重新生成院方密钥、重新注册连接器。
4. 合约持有方签署：演示合约经连接器自动确认后重签。
5. 注册中心与白名单：L1.5 模块迁入清单，演示环境初始化白名单。
6. 平台内核与连接器运行时，缺省关闭。
7. L1.5 链路与 Web；打开 `MDOP_ENABLED`，跑一致性测试。
8. 更新 FLOWS / DOMAIN / ARCHITECTURE，`check-meta-docs` 为 0 error。

**回滚**：
- 关闭 `MDOP_ENABLED`，旧管线照常。
- 签名格式切换的回滚，要回退到旧镜像并恢复旧密钥备份，所以要到新版本稳定后才能删除旧密钥。

## Open Questions

- **生产环境医院在哪里确认合约和复核？** 本期是院内端点加 CLI。连接器本地管理页，或数据办公室人员自持密钥，留待有真实医院时确定。
- **药企同意的密码学签名**：药企没有节点，本期只有平台记录的知悉哈希。是否让药企用户在浏览器持钥签署，待定。
- **身份锚脱离平台**：did:web 或国家身份基础设施，列入三期。
- **CDM 数据源的快照标识**：CDM 分析本期不开放，快照标识的定义随 CDM 分析变更一起确定。
- **平台上各院 C3 投递的留存期限**：本期按交付物保留；是否要随合约留存约束一起销毁，待定。
