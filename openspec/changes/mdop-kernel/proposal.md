## Why

MDOP（`docs/医疗数据跨节点算子编排协议规范（MDOP）v0.1.md`）要求协议的安全性不依赖平台诚实，数据持有方对每一步有最终否决权，执行模型统一为「注册算子组成的 DAG」。2026-09-24 对照代码核查，现有内核在结构上与之相反：

- **信任根在平台。** 一把明文存库的 CA 根钥同时签证书、任务和算法模块；注册时未提交公钥的医院，私钥由平台生成后下发。合约没有医院签名，连接器不保存合约副本，只信平台随任务下发的快照。
- **没有否决。** 连接器拉取即认领，执行前不能接受或拒绝；单院失败时其余医院照常按 `partial` 合并。
- **编排按分析类型写死。** 线上 3 条管线（RWS / FL 预测 / SecretFlow）不共享任何领域模型，共 9 种任务实体、8 套状态词汇。能签名、能固定的算子只有 L1.5 失衡检测一个 Wasm 模块，其余是内置实现。
- **数据分级只在文档里。** FLOWS.md 的 payload 分级只被静态检查器读，运行时没有流动标签。
- **SM2 用法不合国标。** 签名未做 GM/T 0003 的 Z_A 预处理，也未用 DER 编码，与外部互通或送检都会卡住。

用户已裁决（2026-09-24）：**全面替换现有编排**，并以**平台作为合约明示的 C3 接收方（即 v0.1 所称 L3）**。本变更是第一期：倒置信任根、建立 MDOP 内核骨架，先迁 L1.5 一条链路；其余分析类型的迁移与旧管线下线由后续变更完成。

## What Changes

- **MDOP v0.2 修订稿**：在 v0.1 基础上修订。流动等级改名 C0–C3，避开与 RWS 阶梯 L0–L4、能力图谱 L1–L7、合规「L2」撞名。P1 放宽为「C0/C2 永不经平台，C3 与安全聚合后的总和可经平台，须合约明示」。算子增加 `kind: wasm | oci | system` 三类。C2（进入可信空间）在协议里保留，但硬件 TEE 到位前默认关闭。SM2 按 GM/T 0003 规定。协议定位为国标连接器接口之上的编排 profile。另如实写明跨院签名的信任边界。
- **共用协议核心 `packages/mdop`**（领域中立）：
  - 消息信封与消息类型、C0–C3 标签格与传播规则、逻辑计划与物理计划、执行凭证、制品句柄、审计与销毁回执的 schema；
  - 规范化哈希（RFC 8785 JCS + SM3）、标准 SM2 签名与验签、凭证校验、错误码。
  - 平台编译器和连接器复核调用同一套实现；连接器用自己的输入独立重算，不采信平台的编译结果。
- **BREAKING：SM2 国标化**。所有签名改为 GM/T 0003：Z_A 预处理，缺省用户 ID `1234567812345678`，DER 编码。覆盖证书、任务与信封、算法模块、结果背书和连接器请求签名。已上链的历史签名保留旧格式兼容验签。
- **BREAKING：密钥归属与分离**：
  - 参与方密钥一律由参与方自己生成，平台 MUST NOT 生成或接触参与方私钥；删除代生成路径。
  - 平台密钥三分：CA 根钥只签证书；平台节点密钥签信封与凭证；注册中心密钥签算子清单。
  - CA 根钥不再明文落库。
- **BREAKING（仅对 MDOP 作业）：合约由持有方签署并在连接器本地留存**：
  - 医院批准合约后，平台向该院连接器发出合约要约（ContractOffer）。连接器经本地确认后用本院私钥签署（ContractAgree），同时把合约存入本地库。只有带持有方签名的合约才能授权 MDOP 作业。
  - 合约新增字段：接收方列表（含平台作为 C3 接收与合并方）、用途编码、各方公钥指纹、复核方式（自动/人工）、是否要求伦理批件。
  - 旧合约继续服务旧管线，不能用于 MDOP 作业（fail-closed）。
- **算子注册与本地白名单**：
  - 算子清单进注册中心，由注册中心密钥签名。现有 L1.5 模块（AssemblyScript、Rust 两份）登记为 `wasm` 算子。
  - `system` 算子是连接器或平台自带的机制，包括：数据源、降密（输出闸门）、平台侧合并。
  - 每个连接器维护自己的白名单，由医院本地决定、缺省为空（fail-closed）。
  - 吊销名单由平台签名，连接器落盘并保持版本单调。
- **平台内核**：
  - 作业（Job）与阶段（Stage）的新表，与旧表并行、不改动 `cp_rws_*`。
  - 编译器：按数据就近放置、标签与能力校验、切分子计划片段、计算 plan_hash。
  - 凭证服务：下发片段要约 → 收集接受或拒绝 → 签发执行凭证；任一方拒绝或复核超时，作业即进入 REJECTED。
  - 调度器：MDOP §8 的作业与阶段状态机，幂等键为 `job:stage:attempt`，本地算子重试 3 次、指数退避；终态统一下发销毁指令，收齐销毁回执后进入 PURGED。
  - C3 结果由连接器投递给平台（平台是合约明示的接收方），平台侧合并阶段只接受 C3 输入。
- **连接器运行时**：
  - 本地合约库、本地白名单；
  - 七项本地复核，签名接受或只带错误码拒绝；
  - 每个阶段执行前校验凭证：本方签名、平台签名、有效期、片段哈希；
  - 片段执行器；
  - 制品库：句柄、TTL 缺省 72 小时到期自主销毁，收到销毁指令即销毁，并返回签名的销毁回执；
  - 每阶段签名的审计回执形成本地哈希链，链头定期经平台锚定到长安链。
- **第一条迁移链路：L1.5 失衡检测**。两院各自执行：数据源 → `wasm` 失衡检测 → 降密（输出闸门，含二次抑制）→ 投递平台；平台侧合并四格表，算 PRR/ROR/IC。控制台可按开关选择走 MDOP，并新增作业、阶段、签署方、回执的查看页。
- **治理**：新增 DECISIONS D-MDOP-1…、TRUST 控制点、DOMAIN 实体与状态词汇、FLOWS 的 FLOW-MDOP-01，更新 ARCHITECTURE；`check-meta-docs` 保持为 0 error。

**本期不做**（后续变更）：
- 安全聚合（LoRA / FL 预测改造）、ε 预算账本、院方人工发布审批（本期只支持合约预授权的自动放行）；
- C1 协议、C2 与可信空间节点、PSI 与 MPC、点对点中继；
- L0 / L1 / L2 / L3 与 FL 的迁移，compose 页改为计划编辑器，下线旧管线。

## Capabilities

### New Capabilities
- `mdop-protocol`：MDOP 协议核心——消息信封与防重放、C0–C3 标签格与传播规则、计划/凭证/句柄/回执 schema、规范化哈希与国标 SM2、错误码与拒绝粒度。
- `orchestration-kernel`：平台侧作业内核——逻辑计划、编译（放置/标签/能力/切片/哈希）、执行凭证签发与否决、作业与阶段状态机、幂等与重试、销毁编排、平台作为 C3 接收方的合并阶段。
- `operator-registry`：算子清单（wasm / oci / system）、注册中心签名、连接器本地白名单、签名吊销名单同步。
- `local-plan-review`：连接器侧本地复核——本地合约库、七项复核、签名接受或拒绝、复核超时即拒、执行前凭证校验。
- `node-artifact-lifecycle`：节点制品与留痕——制品句柄、本地制品库与 TTL、销毁指令与签名销毁回执、C0 不得出节点、审计回执哈希链与锚定。

### Modified Capabilities
以下都是新增要求，不改写现有要求原文。旧管线在本期内仍按现有要求运行，改写留到旧管线下线时进行，也避免与未归档的 `outbound-longpoll-agent-auth` 在同一要求上冲突。
- `participant-identity`：新增「参与方密钥自持」（平台不得生成或持有参与方私钥）、「平台密钥按用途分离」（CA 根钥 / 平台节点密钥 / 注册中心密钥，加密落库）。
- `digital-contract`：新增「持有方签署的数字合约」（接收方列表、用途编码、公钥指纹、复核方式；由持有方签署、平台副署）、「撤销终止 MDOP 作业」。
- `data-space-connector`：新增「MDOP 消息经出站通道传输」（控制面与数据面分开的出站接口，去重与幂等）。
- `rws-compute`：新增「L1.5 失衡检测经 MDOP 作业执行」。

信封格式与 SM2 签名口径（GM/T 0003：Z_A + DER）作为协议层要求，放在新能力 `mdop-protocol`。

## Impact

- **新包**：`packages/mdop`，平台与连接器共同依赖，不含医疗概念。
- **控制面 API**：
  - 新模块 `apps/api/src/mdop/`（注册中心、编译器、凭证、调度、消息与投递接口）。
  - 长轮询响应增加 `mdop` 消息列表；新增 `POST /api/v1/mdop/messages`（控制面消息）与 `POST /api/v1/mdop/deliveries`（C3 数据面投递）。
  - `ca.service.ts` 密钥三分、根钥加密落库；`connector-admin.service.ts` 删除代生成私钥；合约服务增加持有方签署流程。
- **连接器**：
  - 新目录 `apps/connector/src/mdop/`（本地合约库、白名单、复核、执行器、制品库、回执链）；
  - 连接器本地库新增若干表；
  - 本地确认入口（仅院内访问的 HTTP 端点 + CLI）；
  - 密钥本地生成与注册脚本。
- **签名格式切换**：平台、连接器、`scripts/verify-endorsement.mjs` 与链上元数据校验须同日切换；旧格式只保留验签。
- **数据库**：控制面新增 `cp_mdop_*` 表，连接器库新增本地表；旧表不动。
- **Web**：RWS 向导为 L1.5 增加 MDOP 开关；新增作业查看页。
- **部署（ali29）**：各院连接器重新生成密钥并重新注册；演示合约经连接器自动确认后重签，自动确认须如实标注为演示配置；新增环境变量。
- **不受影响**：旧 RWS / FL 预测 / SecretFlow 管线在本期照常运行。
