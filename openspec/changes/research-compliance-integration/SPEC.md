## 一、真实合作流程设计

### 1.1 五方主体角色定义

| 角色 | 实体 | 职责 | 法律依据 |
|------|------|------|----------|
| **数据提供方** | 示范甲医院、示范乙医院 | 数据脱敏上架、审批申请、收益结算 | 《数据安全法》第27条 |
| **数据消费方** | 医科大数据研究院 | 提交研究申请、使用数据、成果分享 | 《个人信息保护法》第13条 |
| **平台运营方** | MedTrust平台 | 技术支撑、流程编排、合规审查 | 《网络数据安全管理条例》 |
| **监管方** | 区域卫健委 | 敏感数据审批、合规审计、应急处置 | 《医疗数据安全管理办法》 |
| **技术审计方** | 区块链节点网络 | 全程存证、不可篡改、可追溯 | 《电子签名法》第8条 |

### 1.3 核心合规要点

#### 数据脱敏标准
- 患者姓名 → 脱敏为 "张*"
- 身份证号 → 脱敏为 "310101********0011"
- 手机号 → 脱敏为 "138****8001"
- 使用国密SM4加密敏感字段

#### 机构入驻审核清单
| 检查项 | 要求 | 权重 |
|--------|------|------|
| 资质完整度 | 100% | 30% |
| 等保等级 | ≥三级 | 25% |
| 数据管理制度 | 有 | 20% |
| 历史违规 | 0次 | 25% |

#### 数据分级审批
| 级别 | 类型 | 审批要求 |
|------|------|----------|
| L1 | 公开数据 | 平台自动审批 |
| L2 | 内部数据 | 医院审批 |
| L3 | 敏感数据 | 医院+监管审批 |
| L4 | 机密数据 | 专项审批 |

## 二、区块链存证管理

### 2.1 存证合约设计

#### InstitutionRegistry (机构注册)
```solidity
struct Institution {
    address did;              // 去中心化身份
    string name;              // 机构名称
    InstitutionType instType; // 机构类型
    string licenseHash;       // 资质证书IPFS哈希
    uint8 securityLevel;      // 等保等级
    bool isActive;            // 是否激活
    uint256 registeredAt;     // 注册时间
}
```

#### DataAssetMarket (数据资产市场)
```solidity
struct DataAsset {
    bytes32 assetId;          // 资产唯一ID
    address provider;         // 提供方
    string name;              // 资产名称
    DataType dataType;        // 数据类型
    uint256 price;            // 定价
    bytes32 termsHash;        // 使用条款哈希
    bool isAvailable;         // 是否可购买
}
```

#### AccessControl (访问控制)
```solidity
struct AccessRequest {
    bytes32 requestId;
    address requester;
    bytes32 assetId;
    string purpose;
    RequestStatus status;
    uint256 requestedAt;
    uint256 approvedAt;
}
```

### 2.2 存证场景

1. **机构入驻存证** - 资质证书哈希上链
2. **数据资产上架存证** - 数据schema、定价、条款上链
3. **申请审批存证** - 每级审批结果上链
4. **计算任务存证** - 任务参数、参与方、进度上链
5. **结果交付存证** - 结果哈希、确认签名上链
6. **资金结算存证** - 分账记录上链

## 三、Demo实现方案

### 3.1 真实但简化的设计

| 环节 | Demo实现 | 真实实现 | 差异 |
|------|----------|----------|------|
| 机构审核 | 表单提交+预设结果 | 人工审核+链上存证 | 时间缩短 |
| 数据脱敏 | 展示脱敏规则 | 真实脱敏处理 | 数据是模拟的 |
| 隐私计算 | 展示进度动画 | 真实FATE/MP-SPDZ | 结果是预设的 |
| 区块链 | 真实FISCO节点 | 多节点共识 | 单节点演示 |
| 存证查询 | 真实区块查询 | 相同 | 无差异 |

### 3.2 演示场景设计

#### 场景A：首次合作（完整流程，15分钟）
1. 医院入驻申请（2分钟）
2. 数据资产上架（2分钟）
3. 研究申请提交（2分钟）
4. 三级审批流程（3分钟）
5. 联邦学习执行（3分钟）
6. 结果交付与结算（3分钟）

#### 场景B：合规审计（3分钟）
1. 展示区块链浏览器
2. 查询某笔交易的完整链路
